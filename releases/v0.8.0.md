# rimsky v0.8.0

A **design-corpus and proof-hardening release**: the durable design catalogs
bootstrap with 62 user-outcome stories and 75 decisions, each story backed by
an executable proof that boots the real assembled product, plus four new
cascade + claim-handoff stories whose proofs exposed and closed real runtime
gaps. Two foundational sweeps land alongside: every control-API route moves
under a unified `/v1/` prefix, and event-log kinds become a typed
`OperationalKind` proto enum consumed as typed values end-to-end. The proofs
closed GitHub issues #15, #16, and #17 along the way.

## Breaking changes

- **All control-API routes now mount under `/v1/`.** The previous tree mixed
  bare paths (`/templates`, `/instances`, `/health`, …) with carve-outs at
  `/v1/observability/*`. Every route — including the unauthenticated health
  endpoints — now lives under a single `/v1/` prefix
  (`lib/control/controlapi/app.go`). A client pointing at the old bare paths
  gets a `404` with no other diagnostic; operators upgrading must repoint
  API consumers, probes, and load-balancer health checks at `/v1/...`. The
  supervisor's async-callback listener (`/v1/callback/{async_ack_id}`) is a
  separate `http.Server` and is unaffected.
- **Event-log kinds are validated at every boundary.** Event kinds become a
  typed `OperationalKind` enum in `lib/protocols/proto/v1/events.proto` plus
  an `events.Kind` value type in `lib/foundation/events/`, swept across every
  emit site. The persistence layer now rejects an unknown kind string at the
  unmarshal boundary as a defensive error, and the events read API rejects
  unknown kinds at the request boundary. Consumers that wrote or filtered on
  ad-hoc kind strings will now be refused. Signal-class kinds (the
  `terminal/...` / `transient/...` / `attribute/...` / `event/...` /
  `message/...` taxonomy) are unchanged and stay outside the enum.
- **`evaluateClaimScopeConflict` reclassifies committed-durable conflicts.**
  A claim-scope conflict against a committed durable hold now surfaces as
  acquisition-unavailable and routes through the operator's `error_types:`
  chain to `terminal/error`, instead of retrying forever against an asset
  surface that never releases. Graphs that (inadvertently) relied on the
  infinite-retry behavior will now reach a terminal error state.
- **Exported API additions in `lib/foundation/`.** Out-of-tree Go consumers
  see the new `events.Kind` value type with per-kind constructors
  (`KindStateTransition()`, `KindClaimAcquired()`, …), `ParseKindString`,
  `AllOperationalKinds`, and `OperationalKindFromProto`; persistence row
  types gain a `Payload` field on `ClaimHandleRow`, and the `ClaimHandles`
  persistence interface gains an `UpdatePayload` method — out-of-tree
  *implementers* of that interface must add it. The events surface now
  expects typed kinds rather than raw strings.

Pre-v1 — no production data, no locked-in consumers. Migration 008 is
additive (a nullable column), so no Postgres bounce is strictly required,
but the `/v1/` route move means every API consumer needs repointing.

## What's new

- **`rimsky run --terminate-after-run`** (and `--no-keep`, which now implies
  it) terminates the instance once the run reaches terminal, closing the
  durable-by-default × `rimsky watch` hang where a dev-loop invocation waited
  forever on an instance that would never terminate.
- **`rimsky agent` control-plane flags + fail-fast daemonize.** `agent start`
  gains `--proxy` (the host-agent-proxy endpoint, required unless `RIMSKY_URL`
  is set — v0.7.0 had no flag-based config here), `--api-key`, and
  `--state-dir`; `agent status` / `agent stop` gain `--state-dir`. Daemonize
  now poll-waits on a status file (`RIMSKY_AGENT_STATUS_FILE`, new on
  `hostagent.Config`) for `connected:true` and kills the child on failure, so
  a misconfigured proxy URL surfaces as a non-zero exit instead of a
  background daemon looping on dial failures.
- **Runnable example demos.** New `examples/onboarding-demo.sh` (with
  `examples/onboarding-template.yaml`), `examples/client-context-demo.sh`,
  and `examples/host-agent-control-plane-demo.sh` walk the onboarding,
  client-context, and host-agent control-plane flows against a live stack.
- **Claim payload survives to co-holders.** Migration 008 adds a nullable
  `payload` column to `rimsky_claim_handles`, so a downstream co-holder
  declaring `holds:` against an alias can substitute
  `{{claim.<alias>.payload.<f>}}` after the acquirer's dispatch transaction
  commits. Previously the payload bytes were lost at commit and the
  co-holder's dispatch landed in `terminal/error/template_resolution_failed`
  (GitHub issue #16). The payload stays inert inside rimsky per blessed
  invariant 20.
- **Typed event-kind surface.** The `OperationalKind` proto enum enumerates
  the canonical operational event kinds (auth audit, node-run lifecycle,
  locks, claims, attribute substitution, breakpoints, message bus, fan-out /
  sub-graph dispatch, parked-node lifecycle). Adding a kind is now a proto
  change + regeneration, with no schema migration.

## Fixes

- **Asset materialize trigger seeds a delivery frame.** An asset materialize
  against a quiescent instance previously stalled silently — the trigger now
  seeds the frame that delivers it.
- **Claim-producer `Capabilities` handshake re-runs at peer-dial time.** The
  handshake previously ran once at YAML-load time and could pass an empty
  `ValidationSupportedRoles` list to peers dialed later.
- **Per-sender terminal/error subscriptions fire across the cascade.** The
  cascade-signal-blind proof suite walks every cascade-firing signal type in
  the canonical taxonomy, closing the per-sender `terminal/error`
  subscription regression tracked as GitHub issue #15.

## Internal

- **Design corpus bootstrapped.** 62 user-outcome stories and 75 decisions
  land under `.ok-planner/design/`, each story carrying an executable proof
  that boots the real assembled product (rimsky-all-in-one via
  testcontainers, or in-tree binaries for unit-style proofs) — no proof
  asserts shape against an in-process construction. A compliance pass
  brings the corpus to the self-containment + current-state-only rules,
  and the frame concept's serial-queue boundary-crossing semantics are
  made explicit (GitHub issue #17).
- **New full-stack scenario coverage** for claim handoff (in-frame,
  across-frames, durable), cascade signal taxonomy, runtime diagnostics,
  tag management, template lifecycle / fan-out / error policy / sub-graph
  delegation / CEL subscriptions, and the HTTP verifier. The `examples/`
  module gains end-to-end tests (`main_e2e_test.go` per example), READMEs,
  and per-example Dockerfiles.
- **Test-gate hardening.** Root and `lib/services` `go test` invocations cap
  at `-parallel 4` to bound testcontainers contention; the demo subprocess
  runner sets `cmd.WaitDelay` so grandchild pipes can't block past the
  test's own timeout.
