# rimsky v0.6.0

A trust-and-correctness release for the bundled claude-agent executor. The
headline is a **host-defined Ed25519 sign-off gate**: a host can now require
that an agent's `report_complete` output carry valid cryptographic signatures
before a dispatch is allowed to resolve to terminal success — output that isn't
signed by the host's required validators can no longer reach success. Alongside
it: the executor's `cli.permission_mode` enum is corrected to the real Claude
CLI modes, control-API SSE streaming on `GET /mcp` is fixed, and the
contributor licensing model moves from the CLA + DCO two-step to a single
per-commit `Rimsky-Cert` sign-off.

## Breaking changes

- **`cli.permission_mode` accepted values changed.** The claude-agent
  executor's `cli.permission_mode` attribute enum was `["default", "ask",
  "deny"]` and is now `["default", "acceptEdits", "bypassPermissions",
  "plan"]` — the actual Claude CLI `--permission-mode` values. The old `"ask"`
  and `"deny"` were never valid CLI modes, and the old set rejected the
  executor's own default (`bypassPermissions`). A dispatch that explicitly set
  `cli.permission_mode` to a removed value now fails attribute-schema
  validation; dispatches that omit the field are unaffected.

## What's new

- **Host-defined Ed25519 sign-off gate on the claude-agent executor.** A host
  can require that an agent's `report_complete` output be cryptographically
  signed before the dispatch resolves to terminal success. Configured via new
  `cli.*` attributes:
  - `cli.required_signoffs` — an array of `{ public_key, path? }`. Each entry
    requires a valid Ed25519 signature over the canonical (RFC 8785) value at
    `path` (the whole attributes-delta when `path` is omitted), bound to the
    dispatch id under the domain `rimsky/claude-agent/signoff/v1`.
  - `cli.mcp_servers` — host-wired validator MCP servers
    (`{ name, url, headers?, allowed_tools? }`) the agent reaches to obtain
    sign-offs.
  - `cli.max_signoff_attempts` — corrective `report_complete` retries before
    the run terminal-errors (default `3`).

  The gate runs as a second layer after schema validation: get the shape right,
  then get it signed. It is tamper-proof — a gated agent cannot weaken its own
  gate by emitting `cli.required_signoffs` inside `attributes_delta`, because
  the gate binds to the spawn-time config. Unmet sign-offs after the retry
  budget commit a terminal `errored` outcome; a configured gate running against
  an empty `dispatch_id` fails loud rather than silently ungated. Adds a new
  runtime dependency, `canonicalize`, for RFC 8785 canonical JSON.
- **New terminal error class `agent/signoff_unobtained`.** Added to the
  claude-agent executor's declared error classes; surfaced when the sign-off
  gate cannot be satisfied within `cli.max_signoff_attempts`. A present-but-
  malformed `cli.required_signoffs` / `cli.mcp_servers` entry fails loud via the
  existing `agent/attribute_invalid` class rather than being silently dropped
  (which would disable part of the gate).

## Fixes

- **Control-API SSE streaming on `GET /mcp` no longer 500s.** The auth
  middleware's `capturingWriter` now proxies `Flush()` to the wrapped
  `ResponseWriter`. Without it, `capturingWriter` masked the underlying
  `http.Flusher`, the stream handler's `w.(http.Flusher)` assertion failed, and
  every `GET /mcp` returned "streaming unsupported".
- **Corrected `cli.permission_mode` enum** (see Breaking changes) — the prior
  set rejected the executor's own default and omitted every real CLI mode.

## Internal

- **Contributor licensing model: CLA + DCO → Rimsky Contributor Certificate.**
  The separate Contributor License Agreement signature and DCO sign-off are
  replaced by a single per-commit `Rimsky-Cert` trailer that folds the DCO
  provenance certification and the CLA rights grant into one sign-off. `CLA.md`
  is removed; `CONTRIBUTING.md`, `COPYING.md`, `COPYRIGHT`, and `licensing.yml`
  are updated; a required `Rimsky-Cert` sign-off CI check is added
  (`.github/workflows/contributor-cert.yml`).
- Hardened sign-off gate test coverage (envelope, park, gRPC) and added
  signoff, config-signoff, MCP-server-wiring, http-bridge, and server test
  suites plus an end-to-end sign-off-gate suite.
- Corrected stale executor/service/node/parked-state/transition-reason design
  concept docs to be path-free.
- The `/release` skill now fast-forwards `main` to the release commit when
  releasing from another branch; documented the gRPC test-client camelCase
  `Struct` encoding gotcha.
