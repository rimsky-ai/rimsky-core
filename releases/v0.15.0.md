# rimsky v0.15.0

A **structural release** built from one certified sprint that drained
the ruled issue intake. Three changes carry the weight. The `examples/`
Go module is gone, so the permissive-licensed surface is now the
protocols module alone. Every structured payload rimsky itself authors
is now declared in `events.proto` and built from the generated type,
which reconciles a dozen declared-versus-emitted mismatches and makes
both halves of that drift unrepresentable going forward. And the test
suites' verdict no longer depends on machine load: per-package time
ceilings are gone, replaced by a progress watchdog that reports a hung
run as inconclusive rather than as a failure. Alongside those, the
control API grows an explicit auth posture per mounted route and an
unauthenticated CA-root export, peer enrollment refuses to send an
api-key over plaintext unless told to, and template registration gets
stricter — publisher kinds and retry-backoff numerics are both checked
up front, and the error-policy `reason_template` key is renamed.

## Breaking changes

- **The `examples/` Go module is removed.**
  `github.com/rimsky-ai/rimsky-core/examples` no longer resolves, its
  workspace entry is gone, and `make test-examples` is removed — so
  `make test-all` no longer runs it. The module's manifest copies are
  dropped from fifteen Dockerfiles and its shard is removed from the CI
  matrix and the release-config tag filter. The dual-license carve-out
  that covered it is gone too: the Apache-licensed surface is now
  `lib/protocols` alone. Ten in-tree tests across three modules drove
  example artifacts as fixtures; those inputs moved to `test/fixtures/`
  rather than being deleted, so coverage is unchanged.

- **Event-log payload wire shapes changed.** `events.proto` gains ~30
  payload messages and reconciles the declared set against what is
  actually emitted, in both directions. Fields that were declared and
  never written are reserved out — `outcome`, `claimed_at`,
  `ownership_kind`, `current_claimed_by`, `winning_supervisor_id`,
  `node_id`, `claim_id`, `resumed`, `holder_id`,
  `prior_supervisor_id`, `omitted_fields` — and fields that were
  written and never declared are now declared: `dispatch_id`,
  `supervisor_id`, `terminal_kind`, `error_class`, `reason`,
  `callback_url`, `alias`, `intent`, `claim_handle_id`,
  `holder_node_id`. Consumers reading event payloads by key must
  update against the new declarations.

- **The `attributes_validation_failed` event kind is retired.** Enum
  value 42 and oneof field 45 are reserved. It had no emit site at any
  commit; its live sibling `attributes_schema_failed` covers the
  occurrence.

- **Payload-carrying Go fields change type.**
  `persistence.EventAppendInput.Payload`, `persistence.EventRow.Payload`,
  and `signal.Signal.Payload` are now `eventpayload.Payload` rather
  than `map[string]any`. That type's only constructor accepts a
  generated proto message, so a map literal no longer compiles into
  either field — which is the mechanism, not a convention. Read a
  payload back with `.Map()`; `eventpayload.Decoded` exists for the
  read path only.

- **`signal.PayloadSchemaForType` returns
  `protoreflect.MessageDescriptor`** instead of `reflect.Type`.
  `signal.PayloadMap` and the six hand-written payload structs
  (`TerminalErrorPayload`, `TerminalSuccessPayload`,
  `TransientRetryPayload`, `TransientParkPayload`,
  `TransientAwaitAsyncPayload`, `AttributeChangedPayload`) are
  removed, along with `events.KindAttributesValidationFailed`.

- **Peer enrollment over plaintext is refused by default.** Under
  `RIMSKY_PEER_AUTH=mtls`, a non-`https` `RIMSKY_CONTROL_API_URL` is
  now a startup error — the api-key crosses that hop in the clear
  against an unverified server. Use an `https` control-API URL with
  `RIMSKY_CONTROL_API_CA` naming the deployment CA root, or set
  `RIMSKY_ALLOW_PLAINTEXT_ENROLLMENT=1` to accept the exposure on a
  trusted local network.

- **The error-policy `reason_template` field is renamed to `reason`.**
  `spec.ErrorTypePolicy.ReasonTemplate` becomes `Reason`, and its YAML
  and JSON tags change with it. A template still written as
  `reason_template:` silently stops binding — the key is no longer
  recognized. Both an operator-facing template change and an exported
  Go API change in `lib/foundation`.

- **Templates naming an unsupported publisher kind are rejected at
  registration.** The declared-kinds capability is now consulted at
  registration time; previously an unsupported kind was accepted and
  failed later, at publish.

- **`retry_backoff` numerics are validated at registration.** A
  negative `base_delay_ms` or `max_delay_ms`, a zero `base_delay_ms`
  on a configured backoff (which makes every computed delay zero), or
  a `max_delay_ms` below `base_delay_ms` are all now rejected up
  front. This completes the `kind`/`jitter` enum checks shipped in
  v0.14.0; templates carrying these values were previously accepted.

- **`spec.AggregationPolicy.Validate()` and `spec.SelfTarget` are
  removed** from `lib/foundation/spec`. The method was unreachable —
  a duplicate of the fan-out validator that nothing called — so no
  registering template changes behavior, but external Go importers of
  either symbol must drop the reference.

- **`go test -timeout` is no longer the suites' hang backstop, and per-
  package ceilings are removed.** An aggregate per-package timeout is a
  budget shared across every test in the package, so machine load
  decides which arbitrary set gets killed — a load-dependent verdict.
  The sanctioned backstop is `tools/gotest-guard.sh`, which watches the
  runner's JSON event stream and kills only when nothing has started,
  completed, or emitted output for `RIMSKY_TEST_NO_PROGRESS_SECS`
  (default 20m), reporting that kill as an **inconclusive run** with
  its own exit code rather than as a test failure. A fitness test keeps
  the aggregate ceiling from returning.

## What's new

- **`GET /v1/ca-root` exports the deployment CA root, unauthenticated.**
  A new route, mounted outside the authenticated group by design: a
  service needs the root it will verify the control API against
  *before* it holds any credential. Previously the PEM was reachable
  only inside the authenticated enrollment response, which made it
  unavailable to exactly the callers that need it first.

- **Every mounted control-API route records an auth posture.** The
  action registry gains `AuthPosture` — `unauthenticated`,
  `identity-only`, or `permissioned` — as an entry property, and the
  registry is complete over mounted routes. A grant naming a
  non-permissioned action is now refused rather than silently
  scoping nothing.

- **The CLI resolves the api-key from the stored context.** `--key`
  and `RIMSKY_API_KEY` still win; absent both, commands fall back to
  the context written by `rimsky auth login`, and `RIMSKY_CONTEXT`
  selects which stored context that is.

- **A claim ref's declared `data:` blob reaches the producer's
  `Open`.** `OpenRequest` gains a `data` field carrying the blob the
  template author declared on the claim ref. The producer was already
  shown that blob to validate at registration; it now also receives it
  at acquisition, so it can act on what it approved.

- **The proxy serves its agent hop with the leaf it already enrolls.**
  Under `RIMSKY_PEER_AUTH=mtls` with no operator-mounted keypair,
  `rimsky-host-agent-proxy` serves the agent-facing listener with its
  enrolled deployment-CA leaf instead of falling back to plaintext.
  An explicitly mounted `RIMSKY_PROXY_TLS_CERT`/`_KEY` pair still wins.

- **Attribute substitution errors name the field.** `ErrMissingSource`
  carries the field it failed on, retrievable via
  `attribute.FieldOf`.

## Fixes

- **Scratch that cannot be read back now fails the dispatch.**
  Previously an unreadable scratch record was treated as absent, so
  the node ran as if it were its first attempt — silently discarding
  accumulated state instead of surfacing the fault.

- **A stray 4.2 MB Mach-O binary is removed from the module.**
  `tools/license-check/license-check` was committed by accident and
  shipped inside every `go get` of the root module since v0.14.0. It
  is untracked, and the `tools/` main packages are now anchored in
  `.gitignore` alongside the repo's other stray-binary guards.

- **Per-child candidate metadata survives the parent writeback.** The
  metadata a producer returns from `CommitCandidate` was discarded —
  only the version id was kept. It is now recorded per child under a
  `producer_metadata` key in the parent's writeback.

- **The in-tree stub executor echoes its declared tags**, so
  observability tests exercise the real reporting path.

- **A delegate-target validation check gains a test.** The behaviour
  was live but unproven; the corpus prose describing the older,
  dropped shape is corrected.

## Internal

- Twelve declared-versus-emitted payload mismatches reconciled; the
  retry cap and the previous attribute value are now written, and
  `discarded_claims` is retired.
- Auth event payloads (`AuthAccessAttempted`, `AuthAccessDenied`,
  `AuthKeyCreated`, `AuthKeyRevoked`, `AuthKeyRotated`) are declared
  and built from generated types.
- New out-of-tree test `test/permissivepeer/` proves the protocols
  module is buildable against on its own — a `go list -deps` closure
  check plus a peer that runs against a live rimsky stack — backing
  the dual-license split with an audited story rather than two
  decisions nothing tested.
- The sprint applied 18 section-scoped corpus deltas across 10 design
  artifacts — including one new story and two ratifications of
  out-of-band work — closed 24 promoted intake issues and retired 9,
  and certified clean: four producers, one fix cycle, re-review clean.
