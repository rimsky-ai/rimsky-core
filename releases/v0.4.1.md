# rimsky v0.4.1

A bug-fix release. Three real defects fixed — a supervisor callback row that
stored an undialable bind address, a template validator that rejected the
modern `holds:` co-holdership directive, and a late-bind store lookup that
panicked mid-dispatch on a nil transaction — plus an executor-stub fix and a
sweep of source/doc-comment drift. No wire-protocol, schema, config, or API
changes; upgrading from v0.4.0 is drop-in.

## Fixes

- **Supervisor persists a dialable callback address.** The supervisor wrote
  its listener bind host:port (e.g. `0.0.0.0`) into `rimsky_supervisors`
  instead of the advertised host:port peers use to reach it. The
  executor-facing `callback_url` already used the advertised value, so the
  bug was latent — but any failover or cross-supervisor callback recovery
  reading the row would have gotten an undialable address. The advertised
  host:port and the persisted row now derive from one helper and can't
  diverge. No schema change (the existing columns already meant "the
  reachable callback address").
- **Template validator accepts `{{claim.<alias>}}` reads from `holds:`
  co-held aliases.** A node co-holding a claim via the modern `holds:`
  directive and reading `{{claim.<alias>.address}}` was rejected at
  `template register`, while the legacy `inherits:` form validated — the
  documented-modern directive was the one that failed. The validator now
  recognizes held aliases the same way it recognizes acquired and inherited
  ones. Undeclared aliases are still rejected.
- **Late-bind store bindings lookup no longer panics on a nil transaction.**
  The dial-remote-stores bindings hook read `rimsky_instances` with a nil
  tx, which panics under both the SQLite and Postgres drivers (every table
  method requires an explicit tx). Any deployment using a late-bound service
  proxy hit this at dispatch — the underlying cause behind the reported
  all-in-one read-path wedge. The read is now wrapped in a short
  transaction.
- **Standalone stub executor advertises a permissive attribute schema.** The
  bundled test stub executor registered no observability RPC, so any node
  with an `attributes:` block dispatched against it failed the
  attribute-surface gate with `executor_schema_unavailable`. It now answers
  `Capabilities` with an open `{"type":"object"}` schema.

## Internal

- Doc- and comment-drift sweep: corrected the `ExecuteRequest.attributes`
  proto comment to the current `/v1/runs/{run_id}/attributes` writeback path;
  fixed a stub README reference to a nonexistent `ParkReason` value;
  repointed conformance-package godoc from the retired standalone
  `rimsky-*-conformance` binaries to the `rimsky conformance <protocol>`
  subcommand; and removed a dead `force-fire` route from the CLI test server.
- Concept-doc corrections: dropped the retired scheduled-node force-fire
  endpoint from the control-api concept surface, and fixed the named-lock
  concept to describe the real single-`limit:` config schema (not a
  nonexistent `mode:` field).
