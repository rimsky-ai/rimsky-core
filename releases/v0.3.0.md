# rimsky v0.3.0

A quality-of-life release for operators and workflow authors. It adds
read-only template linting, instance force-termination, an instance
status/watch view, a REST route for breakpoint hits, and named-event
emission from the bundled claude-agent executor — alongside fixes to the
claude-agent async-callback protocol, MCP tool dispatch, template
validation, CLI flag parsing, and supervisor diagnostics. This is also
the first release cut through the new release toolchain, so its images
ship with SBOM + provenance attestations and a critical/high CVE scan
gate.

## What's new

- **Template lint.** A read-shaped `POST /templates/validate` runs the
  full registration-validation pipeline without persisting, exposed on
  the CLI as `rimsky template lint <file>` (with `--warnings-as-errors`).
- **Instance force-terminate.** `POST /instances/{idOrKey}/terminate` and
  `rimsky instance kill` mark an instance terminal, force-fail
  resource-holding in-flight node-runs, abandon their uncommitted claims,
  and close the main run-scope. Introduces a new `instance_killed`
  cascade transition reason (`running`|`parked` → `failed`); the
  corresponding audit event-log row is keyed `instance_terminated`.
- **Instance status and watch.** `rimsky instance status` and
  `rimsky watch` — client-side aggregators built over existing reads plus
  the breakpoint-hits route — give a live, single-command view of an
  instance.
- **Breakpoint-hits REST route.** `GET /instances/{idOrKey}/breakpoint-hits`
  (under `breakpoint:read`) returns the breakpoint-hit list, byte-identical
  to the existing MCP resource, for consumers not on the MCP transport.
- **Named-event emission from claude-agent.** A new `emit_named_event`
  MCP tool lets an agent run emit named events that ride the
  async-callback `events[]` array, plus a `RIMSKY_EXECUTOR_DECLARED_EVENTS`
  env override that populates the executor's declared-events
  observability capability.

## Fixes

- **claude-agent async callback shape.** Both callback-body builders now
  emit the `success`|`error`|`park` oneof instead of the legacy
  `{type:...}` shape, which the supervisor rejected with `400` — this had
  hung every async-completing dispatch over the claude-agent HTTP-bridge
  transport.
- **Template validator.** Unenumerated properties are now admitted under
  `additionalProperties`-open executor schemas (per-property; enumerated
  properties are still validated).
- **MCP `tools/call`.** Fixes a nil-body panic, synthesizes the required
  `Idempotency-Key`, and selects routes tool-aware for `*_list` / `*_get`.
- **claude-agent ops.** Default ports moved to 9090/9190, the protocols
  symlink is dereferenced, and callback MCP tools are always allowlisted.
- **CLI flag parsing.** Flags interspersed with positional arguments are
  now parsed correctly.
- **Supervisor diagnostics.** The resolved callback advertise host is now
  logged, with a warning when it is loopback or unset (a common cause of
  executors being unable to dial back).

## Internal

- **Release toolchain.** Adds the `/release` skill and the `make
  dev-release` path (`tools/dev-release.sh`), and extends `make release`
  with host-side gates (`lint → license-lint → test-all`) ahead of the
  image build, scan, and push chain. A new top-level `releases/` holds
  per-tag notes.
- **Supply-chain signal.** `make scan` gates the chain on critical/high
  CVEs via Docker Scout, and image pushes now attach SBOM
  (`--sbom=true`) and provenance (`--provenance=mode=max`) attestations
  via a dedicated `rimsky-builder` buildx instance.
