# rimsky v0.7.0

A **comprehensive gap-closure release**: 43 user-outcome stories landed across
six clusters — CLI + control-API, auth + stores, template validation + cascade,
host-agent, executors, and sensors/lifecycle/observability — each proven by a
red→green test plus a full-stack acceptance gate. Headlines: the
`rimsky compose` engine is back as a first-class CLI verb, `rimsky watch`
reflows chronologically off a single events stream, identity-bound dry-run +
grant-scope enforcement land on the auth path, the host-agent-proxy gains
per-run-scope spawn isolation + per-binding exec() overrides + all-protocols
late-bind, a reference filesystem atomic-staging producer ships under
`examples/`, the postgres atomic-staging substrate goes in tree, and
`Idempotency-Key` becomes mandatory on every publisher emit.

## Breaking changes

- **`Idempotency-Key` is mandatory on `POST /instances/{id}/messages`.**
  Every publisher message-emit MUST carry the `Idempotency-Key` HTTP header;
  requests without it now return `400 Bad Request` with body
  `Idempotency-Key header is required`. The header was previously optional
  (dedup only ran when set). A publisher that omits the header today
  starts failing on upgrade.
- **Message-idempotency dedup tuple widened.** Migration 007 widens the
  PK on `table:rimsky_message_idempotencies` from `(instance_id, sender,
  idempotency_key)` to `(instance_id, sender_kind, sender, sender_subject,
  idempotency_key)`. Two distinct callers can no longer cross-collide on
  the same `Idempotency-Key` — the second caller now sees a `201 Created`
  against its own dedup row, not a `200 OK` replay of the first caller's
  message. On postgres, existing rows backfill to a stable
  `(operator, "")` tuple so an in-flight retry-with-same-key for the
  original sender continues to dedup. On sqlite (dev-only), the table is
  dropped and recreated — pre-v1, no data preservation.
- **`compose:` resource-name prefix is server-gated.** The reserved
  `compose:`-prefix on resource names is now enforced by both the
  `X-Rimsky-Compose-Origin: 1` request header AND a `compose:origin`
  capability action on the caller's grant. The header alone is no longer
  enough — a non-admin key without `compose:origin` that sets the header
  is rejected. (`*`-wildcard grants — i.e. admin — continue to hold
  `compose:origin` implicitly.) See `concept:permission`.
- **`auth.CheckGrant` signature changed.** Now takes a `target map[string]string`
  third argument and returns a `Mode` field on `CheckResult` (the matched
  entry's identity-bound write floor, defaulted to `ModeExecute`). Callers
  must thread the request resource target through; scope-mismatched grants
  no longer satisfy the check. `gateByAction` and the auth middleware are
  updated; out-of-tree consumers calling `auth.CheckGrant` directly need
  the new argument.
- **`grant.entry.scope` and `grant.entry.mode` are first-class.** Both
  fields move out of the prior `extras` bag onto the `Grant`/`GrantEntry`
  Go types (`code:lib/foundation/auth/grant.go`) and the JSON wire shape
  of the auth grant. Round-trip serialization is byte-stable;
  `ValidateGrantScope` now rejects unknown scope dimensions and any
  non-empty scope on actions that aren't scopeable.
- **Wait-set `topic_kind` taxonomy broadened.** Migration 006 expands the
  CHECK constraint on `col:rimsky_wait_set.topic_kind` from
  `('state','attribute','event')` to
  `('state','attribute','event','transient','message','terminal')`. The
  three legacy values stay admitted for back-compat; the three new
  values let the wait-set mapper carry each top-level signal class as
  its own value rather than folding everything past `event` onto
  `state`.
- **`rimsky-host-agent-proxy` no longer returns `Unimplemented` for the
  fronted protocols.** The previous `cmd/rimsky-host-agent-proxy/unimplemented_handlers.go`
  is deleted; the four fronted protocols (validation, publisher,
  data-processing, claim-producer) are now served end-to-end through
  the proxy by dispatching unary RPCs against the spawned late-bound
  child. (The gRPC `Unimplemented<X>Server` *embeds* remain — required
  by the gRPC service surface — but the handler methods implement the
  real RPC.) An out-of-tree caller that depended on the proxy returning
  `codes.Unimplemented` for those protocols will see real responses
  instead.
- **`sensor-cron` no longer carries the dead `MissedFires` field.** The
  field was persisted but never read; the package-level "no backfill"
  policy is the single source of truth. The columns are gone from the
  cron sensor's durable state.
- **`proto:claim_producer.proto::Unavailable` carries an optional
  `error_class`.** Producers MAY name the acquisition-failure class
  (a member of their declared error vocabulary, e.g. `pg/claim_unavailable`)
  rimsky's acquisition-failure routing keys the operator's `error_types:`
  chain on. Empty preserves the historical synthetic class
  `acquire/unavailable`. The `Available=false` wire shape is unchanged.
- **Wire-protocol field additions in `lib/protocols/proto/v1/`.** Out-of-tree
  consumers regenerating against the v0.7.0 protos pick up:
  `proto:claim_producer.proto::OpenRequest.run_scope_id` (field 8),
  `proto:executor.proto::ExecuteRequest.run_scope_id` (field 16),
  `proto:host_agent.proto::Binding.args` / `.env` / `.cwd` /
  `.ready_timeout_seconds` (fields 2–5), and
  `proto:host_agent.proto::DispatchFrame.rpc_method` (field 7). All are
  additive — clients on the old generated code keep working — but the
  generated message types change shape, which can shake out latent
  consumers that pattern-match on the old struct.

Pre-v1 — no production data, no locked-in consumers. Operators upgrading
should expect to bounce their dev Postgres after pulling the new
migrations.

## What's new

- **`rimsky compose` is back.** `cmd:rimsky compose up`,
  `cmd:rimsky compose down`, `cmd:rimsky compose plan`, and
  `cmd:rimsky compose status` ship as a first-class CLI verb. The
  compose engine resolves a manifest, plans the diff against current
  state, and applies it under the server-side `compose:` prefix guard
  described above. Example manifests under `examples/compose/`.
- **`rimsky watch` is chronological.** `cmd:rimsky watch` (driven by
  `code:cmd/rimsky/cli/watch.go::RunWatch`) now consumes a single
  `/events` stream and reflows events in chronological order across
  instances, replacing the prior per-instance polling that surfaced
  events out of order. End-to-end coverage under
  `file:test/scenarios/cli_watch_chronological_e2e_test.go`.
- **Identity-bound dry-run mode floor.** A grant entry can pin
  `mode: dry_run` and the effective dispatch mode is the stricter of the
  grant floor and the per-request flag — a `dry_run`-floored grant is
  never escalated to execute by an `execute=true` request. Cross-entry
  resolution is order-independent: when matching entries disagree on
  mode, `execute` beats `dry_run`. See
  `invariant:identity-bound-dry-run-mode-floor` and
  `concept:permission`.
- **Grant-scope enforcement across six actions.** `template_tag` scope
  now applies to the full lifecycle:
  `template:deploy`, `template:undeploy`, `template:deregister`,
  `tag:set`, `tag:delete`, and `instance:create`. Hash-form template
  ids resolve to candidate tags via `TemplateTags().ListByTemplate(...)`
  on the persistence handle (see
  `code:lib/control/controlapi/auth_request_target.go`), so a scoped
  key authoring against a tag-aliased template still passes scope.
  Set-membership semantics: multi-tag candidates need any one candidate
  tag to match.
- **Reference filesystem atomic-staging claim-producer.** New module under
  `examples/atomic-staging-fs-producer/` — a self-contained Go binary
  that implements `proto:claim_producer.proto::ClaimProducer` with
  filesystem-backed atomic staging (Linux rename + Darwin fallback), a
  janitor sweep, and a server harness. Used as a probe target for the
  9b serialization conformance probe described below.
- **Postgres atomic-staging substrate.** The bundled `rimsky-store-postgres`
  service gains an in-process atomic-staging store
  (`code:lib/services/stores/postgres/store/staging.go`), the
  `row_count_ratio` shape check, and explicit
  `pg/claim_unavailable` / `pg/swap_failed` emit classes. Conformance
  test suite under `lib/services/test/scenarios/atomic_staging/`.
- **Per-run-scope host-agent spawn isolation.** `rimsky-host-agent-proxy`
  keys spawned late-bound children on `(run_scope_id, binding)` instead
  of `binding` alone, so two run-scopes targeting the same binding spawn
  isolated children that are reaped together at scope termination. New
  `run_scope_id` fields on `proto:executor.proto::ExecuteRequest` and
  `proto:claim_producer.proto::OpenRequest` carry the scope across the
  wire.
- **Per-binding exec() overrides.** `proto:host_agent.proto::Binding`
  gains four additive override fields — `args`, `env`, `cwd`,
  `ready_timeout_seconds` — so a binding can layer extra argv, env, a
  cwd, and a readiness deadline on top of the global Spawn defaults
  without forking the binding declaration. Absent fields preserve
  today's behavior exactly.
- **Anonymous-mode late-bind.** Anonymous-mode dispatches can now reach
  late-bound children through the host-agent-proxy; the prior tension
  `tension:_resolved/anonymous-mode-locks-out-late-bind` is closed.
- **All-protocols late-bind.** The proxy serves validation, publisher,
  data-processing, and claim-producer end-to-end against the spawned
  child. `proto:host_agent.proto::DispatchFrame.rpc_method` is the new
  generic verb selector for protocols whose unary RPCs aren't
  byte-distinct in their requests (publisher's `Subscribe`, validation's
  `Validate`, data-processing's `BeginCandidate`); claim-producer
  continues to use `claim_producer_verb`.
- **MCP catalog on the claude-agent executor.** Inline MCP server
  declarations now resolve via a host-side catalog: `${ref:name}`
  references against `cfg:cli.mcp_servers` entries, four transports
  (stdio, sse, http, websocket), and `cli.allow_inline` to gate
  literal inline declarations. See
  `code:lib/services/executors/claude-agent/src/mcp-catalog.ts`.
- **`http-node` executor: 429 park-with-resume + configurable error class.**
  The bundled `http-node` executor parks the dispatch on HTTP 429 and
  resumes from the upstream response; the terminal error class is
  configurable via `env:RIMSKY_EXECUTOR_HTTP_NODE_ERROR_CLASS_FIELD`,
  the bridge URL via `env:RIMSKY_EXECUTOR_HTTP_NODE_HTTP_BRIDGE_URL`,
  and the body cap via `env:RIMSKY_EXECUTOR_HTTP_NODE_MAX_BODY_BYTES`.
- **Reference signoff validator.** A standalone reference validator ships
  under `code:lib/services/executors/claude-agent/src/examples/signoff-validator/reference-validator.ts`,
  with test fixtures, as a runnable example of a sign-off MCP server.
- **Verifier severity partition.** `verifier-shape-checks` now partitions
  results into `warning` vs `error` severity; warnings annotate the
  dispatch but don't fail it.
- **Template ref-validation mode.** A new `env:RIMSKY_REF_VALIDATION_MODE`
  selects between `all` (every ref must resolve), `available` (resolve
  what's resolvable, warn on the rest), and `none` (skip). Default `all`.
- **Mandatory instantiation static-config gate.** Instance creation now
  blocks on a static-config gate that proves the resolved template +
  attribute deltas satisfy declared shape checks before any side effect
  fires. See
  `code:lib/control/controlapi/instances_static_config_gate.go`.
- **Lenient `?` attribute-ref marker.** Substitution treats `${attr?}`
  as a soft reference: missing attributes resolve to empty rather than
  failing the dispatch, end-to-end.
- **Operator `frame:in` joins the running frame.** An operator emitting
  `frame:in` joins the live cascade frame the operator targets rather
  than starting a fresh one. New scenario:
  `test/scenarios/cascade/cascade_operator_frame_in_e2e_test.go`.
- **Breakpoint hits land co-transactionally on `/events`.** A breakpoint
  hit and its `/events` row commit together; the observability path no
  longer races against the breakpoint state transition.
- **Latest-attribute bag on the node read surfaces.** `GET /nodes` and
  the related read-side endpoints carry the node's latest committed
  attribute bag inline.
- **Sensor-cron durable state + replica-posture accuracy.** Cron sensors
  persist their durable state via the
  `env:RIMSKY_SENSOR_CRON_STATE_DSN` DSN; replica posture is computed
  honestly against that state, fixing prior cases where two replicas
  could both fire the same cron tick.
- **Backfill partition-selector override.** A partition selector
  override flows end-to-end through the backfill pipeline, with
  fullstack coverage under
  `test/scenarios/backfill/backfill_partition_override_fullstack_test.go`.
- **Settling `signal_type` on `GET /nodes`.** The settling signal type
  is now reported on the node read surface, so consumers don't have to
  cross-reference the cascade graph.
- **Out-of-tree protocol examples.** A new top-level `examples/` Go
  module (`pkg:github.com/rimsky-ai/rimsky-core/examples`) ships seven
  reference implementations — `examples/publisher`,
  `examples/executor`, `examples/validation`,
  `examples/data-processing`, `examples/lifecyclesubscriber`,
  `examples/claimproducer`, and the
  `examples/atomic-staging-fs-producer` above — each a runnable Go
  binary with a server harness and tests. Plus `examples/compose/`
  manifest fixtures for the `rimsky compose` engine. Added to
  `go.work`.
- **Claim-producer 9b conformance probe + ScopesConflict wiring.** The
  conformance runner under `lib/protocols/conformance/claimproducer/`
  gains a `serialization9b` probe and exercised terminals
  (`Commit`, `Abandon`, `Release`); the producer surface declares a
  `ScopesConflict` error class for operator routing.

## Fixes

- **Auth-middleware body capture no longer 403s on large scoped requests.**
  The audit-row body cap was applied to the gate-evaluation body as well,
  so a `>4 MB` scoped `POST /instances` request had its `template`
  field truncated out of the gate's view and was rejected as
  unauthorized. The capture path now splits: the gate sees the full
  body, only the audit row is bounded.
- **Cross-tenant `Idempotency-Key` collision.** Distinct API keys (and a
  publisher that names itself `operator`) can no longer replay each
  other's idempotency keys; the dedup tuple now includes
  `sender_kind` and `sender_subject` (see Breaking changes).
- **`CheckGrant` execute-vs-dry-run resolution.** The pre-fix path
  returned the first matching entry, so a key with one `execute` and
  one `dry_run` entry on the same action resolved deterministically
  on iteration order. The fix scans all matching entries and picks
  the most-permissive mode regardless of order.
- **`POST /instances/{id}/messages` with no-matching-node-type target.**
  A non-empty `target` that names no node type in the instance now
  returns `400` instead of silently broadcasting.
- **Host-agent Validation handshake probes the child.** The proxy issues
  a one-shot `Validate` RPC against the spawned child during readiness;
  a TCP-binding-but-no-Validation child now fails the spawn instead of
  hanging the first dispatch with `Unimplemented`.
- **`ValidateGrantScope` rejects malformed entries.** Unknown scope
  dimensions and any non-empty scope on an unscopeable action are now
  caught at validation time.
- **NULL message payload survives round-trip on both backends.** Sqlite
  + Postgres `messages` row scanning correctly handles `NULL` payloads;
  prior scan paths returned a non-nil empty payload that downstream
  consumers treated as a present-but-empty body.

## Internal

- **`tools/rulesdoc/`.** A new dev tool that generates derived
  rules-doc tables from the canonical source files; wired into the
  doc-lint flow via `make`.
- **Scenario test coverage substantially deepened.** New full-stack
  scenarios under `test/scenarios/` cover auth grants + dry-run
  identity binding, attribute lenient-marker recovery + ref-validation
  mode, breakpoint hits emitting events, cascade waitset-topic-kind
  taxonomy, cascade operator `frame:in`, compose-prefix guard,
  Idempotency-Key required, node signal-type readback, host-agent
  per-binding overrides, host-agent per-run-scope isolation,

  late-bind, host-agent reap, lifecycle force-terminate fullstack,
  node latest-attribute fullstack, backfill partition override
