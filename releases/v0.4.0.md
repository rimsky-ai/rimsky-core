# rimsky v0.4.0

A control-plane release centered on dry-run, audit, and fan-out delivery.
Permission grants become binary set-membership and dry-run moves to a
per-request flag; a durable auth audit log gains a filterable `GET /audit`
read surface; backfill partition overrides now bind to the fan-out node;
and frame delivery defaults to the serial queue. It also
ships the container-image CVE remediation — all 15 distributed images now
pass the strict critical/high Docker Scout gate at 0C/0H.

## Breaking changes

- **Permission grants are now set-membership, and the per-entry `mode`
  modifier is gone.** A grant is evaluated by set membership — a request
  is allowed iff any entry's action matches, and entry order is no longer
  significant (previously first-match-wins). The per-grant-entry `mode`
  write-modifier (`execute`/`dry_run`) is removed: a legacy `mode` key on
  a persisted grant is no longer a recognized field and falls into
  `Extras` like any other unknown key (pre-v1 — dropped from the matcher,
  no compat shim). `auth.GrantEntry.Mode` is removed from the Go API.
- **Dry-run is a per-request flag, not a grant property.** Write actions
  take dry-run from `?dry_run=true` on the request rather than a grant
  `mode: dry_run`; every write action has a dry-run branch with no auth
  carve-out. The CLI `--dry-run` flag is dropped.
- **Default frame-delivery mode is now `serial_queue` (previously
  `coalesce`).** Instances created without an explicit delivery mode now
  default to serial-queue delivery — enforced in the insert path in both
  drivers, with migration `004-frame-delivery-default` setting the Postgres
  column default to match.

## What's new

- **Per-request dry-run.** `?dry_run=true` previews a write's effect
  without persisting, across every write action.
- **Durable audit log + read surface.** Auth-audit writes are now
  synchronous and durable — the row lands before the gate returns
  (previously they were written off the hot path by a bounded worker pool
  that dropped rows under load). A new `audit:read` action exposes
  `GET /audit`, filterable by actor/action/target/key/status and time
  window with cursor pagination, backed by migration
  `003-audit-read-indexes` (expression indexes over the audit payload
  keys the reader filters on).

## Fixes

- **Backfill partition override now binds.** A backfill's
  `partition_request_override` now reaches the fan-out node; previously the
  literal template bytes flowed through and the override was silently
  dropped. Submit-time validation also rejects with `400` a
  `backfill:create` whose target is not a fan-out node wired for backfill.
- **Prune dry-run count.** A prune dry-run now returns a real
  would-prune count (`CountOlderThan`) rather than a placeholder.
- **Conflict-aware delivery coalesce.** Frame-delivery coalescing is now
  conflict-aware.
- **Container-image CVEs — all 15 images at 0C/0H.** `golang.org/x/net`
  is bumped to `v0.55.0` across the Go modules (clearing the shared
  critical/high set on the 13 Go images). The claude-agent executor image
  is re-based onto Chainguard/Wolfi with a production-only `node_modules`
  (no dev toolchain shipped), a digest-pinned base, pinned
  `@anthropic-ai/claude-code`, and runtime npm remediation (`fastify`
  4 → 5 plus `fast-uri` / `protobufjs` / `qs` overrides), clearing the
  Alpine OS and npm findings.

## Internal

- **Design + workflow docs.** Concept-catalog updates (dry-run,
  permission, event-log, backfill, fan-out, message) and a new tension on
  event-vocabulary-implied delivery, alongside design-doc
  self-containment cleanup.
