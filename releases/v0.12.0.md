# rimsky v0.12.0

A **routing and coherence release**: instance dispatch routing gets a
first-class identity — every instance now carries a
`target_routing_identity`, anonymous agents register under
collision-checked silly-name identities that persist across
reconnects, and the host-agent proxy routes uniformly by identity
instead of api-key special cases. Service discovery moves to a shared
address book published by the control API, replacing supervisor
accept-lists and claim-time name filtering. Config loading becomes
strict (unknown keys and unset `${VAR}` references fail at startup),
the operator env-var surface is renamed onto a uniform
`RIMSKY_`-prefixed registry with a generated catalog, and the CLI
ships as prebuilt binaries on GitHub Releases. Three drain sprints —
a GitHub-issue drain, a verified-bug drain, and an issue-queue
batch — land the rest: a bundled
park-then-resume recipe, the store→claim-producer vocabulary sweep's
user-facing tier, and twelve verified bug fixes — all under the
pre-v1 no-compat rule.

## Breaking changes

- **Config env vars renamed**: `STORE_FILESYSTEM_CONFIG` →
  `RIMSKY_CLAIM_PRODUCER_FILESYSTEM_CONFIG`, `STORE_POSTGRES_CONFIG`
  → `RIMSKY_CLAIM_PRODUCER_POSTGRES_CONFIG`, `RIMSKY_URL` →
  `RIMSKY_HOST_AGENT_PROXY_URL`, and the CLI's `RIMSKY_CONTROL_API`
  → `RIMSKY_CONTROL_API_URL` (`RIMSKY_ENDPOINT` swept everywhere).
  Removed knobs: `RIMSKY_EXECUTOR_CALLBACK_HOST` (claude-agent;
  loopback is the only behavior) and
  `RIMSKY_EXECUTOR_HTTP_NODE_TIMEOUT_MS` (http-node;
  `sync_rpc_deadline` is the sole request bound).
- **Strict config loading**: every YAML loader site routes through
  one shared strict loader (`lib/protocols/config`) — unknown keys
  are rejected (`KnownFields`), env expansion is `${VAR}`-only, and
  an unset `${VAR}` is a hard startup error. Stale `rimsky.yml` keys
  that previously loaded silently now fail loudly.
- **Anonymous instance creation requires a target agent**: every
  instance row carries a CHECK-enforced `target_routing_identity`
  (migration 038); `rimsky run` and instance creation against
  anonymous-mode deployments must name the target agent.
- **Wire protocol** (`lib/protocols/proto/v1/`): `host_agent.proto`
  adds `Register.routing_label` and `RegisterAck.routing_identity` —
  the proxy adopts and returns a routing identity (api-key id or
  assigned silly-name) that agents persist and re-present on
  reconnect; `lifecycle.proto` adds
  `OnInstanceCreatedRequest.target_routing_identity` and demotes
  `owner_api_key_id` to an audit signal — proxies route by
  `target_routing_identity` now. Fields are additive but the routing
  semantics changed; regenerate stubs and update proxy
  implementations.
- **Service address book replaces supervisor accept-lists**: the
  control API publishes the declared executors and claim producers
  on boot (migration 039); supervisors drop accept-list
  registration and all claim-time service-name filtering, resolving
  names read-through with a short TTL cache. Template registration
  validates service names against the same catalog; a dispatch
  naming an unresolvable service fails loudly instead of stalling.
- **Container binaries renamed**: `store-filesystem` →
  `claim-producer-filesystem`, `store-postgres` →
  `claim-producer-postgres` (image names were already
  `rimsky-claim-producer-*`). The claude-agent attribute
  `cwd_from_store` is now `cwd_from_claim_producer`.
- **Executor conformance is fail-closed**: `rimsky conformance
  executor` refuses to run against a live (non-stub) endpoint unless
  `--allow-live` is passed; the stub/probe signature is centralized
  in `lib/protocols/conformance/stubmode`.
- **Persistence schema**: migration slots 038–040 in both backends
  (instance target-routing identity, service address book,
  async-callback URL persistence). Pre-v1: migrations run forward
  automatically; no data-compat guarantees.
- **Go module surface**: the scheduler loop moved from the graph
  layer to `lib/runtime/scheduler` (old import path gone), and
  `lib/foundation` persistence/locks interfaces changed shape
  (supervisor registration lost its accept-list parameters; the
  address-book table and `RegisterAsyncAck` callback-URL parameter
  are new). Go-module consumers recompile against the new
  signatures.

## What's new

- **Prebuilt CLI binaries**: releases now ship
  `rimsky_X.Y.Z_{linux,darwin}_{amd64,arm64}.tar.gz` archives with
  checksums on the GitHub Release (goreleaser). Windows is
  intentionally absent (the CLI embeds Unix-only process control),
  and `go install .../cmd/rimsky@version` is documented as
  unsupported (workspace `replace` directives).
- **Anonymous-agent routing identities**: each anonymous agent gets
  a distinct generated silly-name (or requests one via
  `RIMSKY_AGENT_ROUTING_LABEL`), registration atomically rejects
  collisions, the adopted identity persists across reconnects
  (`RIMSKY_AGENT_IDENTITY_FILE`), and displacement notices are
  per-identity.
- **Bundled park-then-resume recipe**: `examples/park-resume/` — a
  rate-limit-once endpoint plus a copy-runnable
  `examples/park-resume-demo.sh` driving the bundled http-node
  through 429 → park → timed wake → success on the production
  parking path, with an e2e proof.
- **Env-var registry**: `tools/env-registry` generates a canonical
  catalog of every `RIMSKY_*` variable (`registry.md`) with a
  two-directional fitness test, so code and docs cannot drift.
- **Operator diagnostics**: orphan-reap diagnostics persist and name
  the uncalled callback URL; the control API's MCP endpoint gains
  `DELETE /mcp` (client-driven session close).

## Fixes

- `rimsky run` omitted the target agent and failed against
  anonymous-mode instance creation.
- Scheduler and control API now install their own outbound mTLS
  identity via a race-free once-per-process path (previously only
  the supervisor enrolled, breaking split-role peer auth).
- All lock-spec substitution failures route through the node's error
  policy, and `template_resolution_failed` emits the correct site
  (`attribute` | `lock_name` | `scope`).
- claude-agent `module` / `http-loopback` MCP specifiers must
  resolve at parse time; an unregistered specifier fails naming
  itself.
- Parked-lifecycle and eleven demo scripts gained the required
  target agent; a lifecycle test raced the async lineage write.
- Twelve-bug verified drain (sprint 2026-07-24) closed the remainder:
  wire-literal auth-const DRY sweep, deterministic-test sweep in
  `test/scenarios`, retired `frame_resolution_mode` purged from
  fixtures, content-addressed fake-claude-agent base image.

## Internal

- Scheduler tick loop and pure-cascade settlement relocated from the
  graph layer to `lib/runtime/scheduler`; graph purity is now
  unconditional in depguard.
- Wall-clock verdict lint (`tools/wallclock-lint`) with a per-file
  one-way ratchet; services-harness helpers swept to
  poll-until-success.
- JCS canonicalization pin frozen across all workspace manifests
  (replace directives rejected).
- Planning estate: file-per-issue intake under `.ok-planner/issues/`
  (52 verified narratives), three sprints executed and archived,
  ok-plugins suite trued up to v8.0.0.
- `COPYING.md` Apache-surface prose corrected to match
  `licensing.yml` (`lib/protocols/` + `examples/`).
