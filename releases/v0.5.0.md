# rimsky v0.5.0

A lifecycle-and-correctness release. The headline is **durable-by-default
instances**: an instance now lives until force-terminated, and self-termination
becomes an explicit per-instance opt-in (`terminate_after_run`) that fires at
most once more, after the next frame ends — replacing the old "auto-terminate
on drain" behavior. Alongside it: parked node-runs now correctly hold their
frame open, a real trace-retention sweep reaps terminal run trees on a
time-plus-count budget, the legacy `inherits:` co-holdership directive is
removed in favor of `holds:`, and a broad pass closes every filed issue and a
set of audit-surfaced runtime bugs. Schema migration `005` is additive
(default-off), but the lifecycle behavior change and the `inherits:` removal
are breaking — see below.

## Breaking changes

- **Instances are durable by default; auto-terminate-on-drain is gone.**
  Previously an instance self-terminated once its work drained. Now an instance
  persists until explicitly force-terminated. The only path to self-termination
  is the new opt-in `terminate_after_run` flag on the create request, and even
  then the instance terminates only after its *next* frame ends (strict "run at
  most once more" semantics) and never while a node-run is parked. The
  termination predicate (`MarkInstanceTerminatedIfDone`, both Postgres and
  SQLite drivers) was rewritten to these semantics: the old
  publisher-subscription and queued-frame self-termination clauses are dropped.
  Migration `005-instance-terminate-after-run` adds the `terminate_after_run`
  column (`NOT NULL DEFAULT false`), so every existing instance and every
  create request that omits the flag stays durable. Operators who relied on
  instances cleaning themselves up on drain must now either set
  `terminate_after_run` at create time or force-terminate explicitly.
- **The `inherits:` template directive is removed; use `holds:`.** Claim
  co-holdership is expressed entirely through `holds:` (wired through the
  held-subgraph layer). The legacy `inherits:` node key and its
  `spec.InheritEntry` Go type (aliased as `node.InheritEntry`) are deleted
  outright — pre-v1, no compat shim. A template still carrying an `inherits:`
  block no longer binds that field.
- **Go API: persistence interfaces renamed and extended.** In `lib/foundation`,
  `FrameTable.PruneOldRunsForRetention(ctx, recentFramesKept)` becomes
  `PruneTraceForRetention(ctx, recentFramesKept, cutoff)`; `EventTable` gains
  `DeleteOlderThan(ctx, cutoff) (int, error)` and `NodeEventTable` gains
  `DeleteOlderThan(ctx, cutoff) (int, []NodeEventOrphan, error)` (the
  node-event variant also returns the spilled-blob orphans to reap); and
  `ClaimHandleTable` gains `ListByNodeRun` and `UpdateNodeRunID`. Consumers
  importing these interfaces — or implementing them — must update call sites
  and implementations.
- **`rimsky-entrypoint` now validates its role argument.** The entrypoint
  honors its single command argument: no command spawns all three roles; a
  recognized role (`rimsky-scheduler` / `rimsky-supervisor` /
  `rimsky-control-api`) spawns only that role; an unknown argument now exits
  non-zero with a clear error instead of being ignored. Migrate runs exactly
  once across a split deployment (the no-arg all-in-one path, or the
  `rimsky-control-api` role in a three-container split), overridable via
  `RIMSKY_ENTRYPOINT_MIGRATE` (`=1` forces, `=0` skips).

## What's new

- **Opt-in `terminate_after_run` on instance create.** The flag threads from
  the create request through migration `005`, persistence, and the control-api
  instance projection (mirroring how `paused` is surfaced), giving a
  run-at-most-once-more instance for callers that want the old ephemeral shape.
- **Trace retention sweep.** `PruneTraceForRetention` reaps terminal frame rows
  (node-runs cascade) by the lesser of a trailing time window and a
  recent-frames count cap; `EventTable` and `NodeEventTable` gain
  `DeleteOlderThan`. `SweepRunTreeRetention` drives all three under a new
  `trace_trailing` retention knob, and the sweep is wired into the scheduler
  tick with the `retention:` config plumbed through. Spilled named-event blob
  handles are queued for cleanup atomically with the row delete.
- **Parked node-runs hold their frame open.** `ListRunningFramesNoPendingNodes`
  counts parked node-runs as unresolved work in both drivers, so a frame with a
  parked run is no longer treated as drained.
- **MCP connect-and-control transport.** `GET /mcp` now opens an SSE stream
  instead of returning `405`, `notifications/initialized` is consumed, and a
  session id is issued (live push remains protocol V2). Internal-MCP connection
  stability is hardened across long SSE streams and CLI resume in the
  claude-agent executor.
- **`AggregationPolicy` YAML keys bind.** The aggregation-policy struct gained
  `snake_case` YAML tags, so its keys now bind from config as documented.
- **Object-store sensor validates backends.** The sensor rejects unserviceable
  object-store backends at startup and advertises only the backends it actually
  has registered.

## Fixes

- **Messages to a quiescent instance are delivered.** `POST
  /instances/{id}/messages` now seeds a delivery frame inside the
  message-insert transaction, so a message to an instance with no running frame
  is actually delivered instead of sitting pending indefinitely.
- **Standalone `rimsky-control-api` wires configured publishers.** The
  standalone control-api binary now loads the configured publishers into its
  app dependencies; previously they were empty, so a multi-process deployment
  returned `unknown_publisher`.
- **CLI event-cursor encoding.** The `rimsky watch` and `rimsky instances
  events` follow loops now pass the opaque server `next_cursor` token through
  instead of fabricating a numeric cursor, fixing the `500` on page advance
  (filed issue #1).
- **Durable claim lifetime through the real acquire path.** A durable claim's
  lifetime is now threaded through the actual acquire path rather than only the
  test seam (audit item D5).
- **`candidate_handle` reaches the fan-out leaf.** The candidate claim handle
  now lands in the fan-out leaf's `ExecuteRequest` (audit item E4).
- **`{{child.partition_key}}` binds at fan-out dispatch.** The child
  partition-key template reference is now resolved at fan-out dispatch (audit
  item E14).
- **Publisher resync at control-api startup** (audit item F8), and **per-reason
  park-cap vocabulary aligned to the stored `ParkReason` values** (audit item
  E11).
- **Config-example fix.** The Postgres store `config-example.yml` shipped
  `write_semantics: direct`, which the parser rejects; it now reads `sync`.

## Internal

- **Verification + coverage pass.** A whole-project verification traced every
  documented concept to a behavioral test, closed ten acceptance gaps where a
  claim was "proven" only by a stubbed component or a shape assertion, and added
  real end-to-end gates (named-lock capacity contention, write-semantics
  coexistence, observability schema enforcement, sub-graph delegate-cycle
  rejection, post-commit verify-before-run race under `-race`, filesystem
  stage-then-swap, a real `rimsky-sensor-http` image firing a downstream node).
  The all-in-one image's SQLite stack is now driven end to end
  (`harness.WithSQLite()` → drive a node to terminal).
- **CI workflow.** Added a multi-module build/test/lint workflow; removed the
  broken docs-lint workflow that referenced a nonexistent make target.
- **Concept docs** (instance, frame, event-log) updated to match the new
  lifecycle, frame-end, and retention behavior; assorted source/comment drift
  corrected (the `claims:`→`stores:` doc-comment drift, the auto-terminal
  promote-not-delete comments, the nonexistent `viewer` role reference).
