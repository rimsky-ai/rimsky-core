# rimsky v0.10.0

A **wire-protocol-coherence and template-DSL release**: the executor
protocol collapses streaming Execute + heartbeats + ResumeContext +
NamedEvent into a unary Execute with uniform Success/Error/Park
terminals (each carrying `attributes_delta` + `scratch` + `tags`);
the operator-facing template DSL gains a typed-message registry with
cascade-send, a gated debug-override channel, and an explicit two-flag
cascade-shape on every `subscribes:` entry; bundled filesystem and
postgres claim-producers light up end-to-end fan-out via SplitScope
with sub-claim wire parity; attribute carry-forward, opaque executor
scratch, and an in-process executor transport ship as a coordinated
set, with `loop_counter` as the first bundled in-process builtin and
`claude-agent` session-resume rebuilt onto the same mechanism; and a
new `rimsky compose run` verb drives a compose manifest to terminal
in one OS process without external infrastructure, leaving a forensic
artifact under `.rimsky/runs/`. Pre-existing bugs surfaced through
the rebase chain — a cascade direct-invalidate race, an
ErrorTypePolicy retry loop that silently bailed on its own re-claim,
a `SelectCandidates` filter that excluded pure-cascade rows, a gate
substitution path that missed delivered messages — landed structural
fixes alongside the planned work. Per the pre-v1 break-freely rule
the persistence migration tree was reset.

## Breaking changes

- **Executor Execute RPC is now unary, not streaming.** `Execute` is
  declared `rpc Execute(ExecuteRequest) returns (Outcome)`; the
  request returns exactly one `Outcome` populated with one of
  `Success` / `Error` / `Park` / `AwaitAsyncCallback`. The streaming
  `ExecuteEvent` wrapper and the `Heartbeat`, `NamedEvent`, and
  `StreamClose` messages are removed from the wire. Per-dispatch
  liveness for async dispatches travels over HTTP keepalive +
  attribute-writeback callbacks against the supervisor's callback URL.
  Executor authors must rebuild against `lib/protocols/proto/v1/executor.proto`
  v0.10.0 and switch their server handler signature; emitting events
  mid-execution moves onto `Success.tags` + `Success.attributes_delta`
  (or the Error/Park equivalents). The four-variant Outcome oneof
  field tags (`success=1, error=2, park=3, await_async=4`) match the
  prior `StreamClose.outcome` tags, so a pre-generated client that
  still parses the old enclosing-message wire shape will not silently
  cross-decode.
- **`Success` / `Error` / `Park` carry uniform `attributes_delta` +
  `scratch` + `tags`.** All three settling terminals gained the same
  three optional fields. `attributes_delta` (`google.protobuf.Struct`)
  is the terminal-final attribute writeback channel and is now
  available on `Error` and `Park` as well as `Success`; the supervisor
  commits it atomically with the verdict via the caller-provided tx.
  `scratch` (`bytes`) is the executor-attached opaque blob persisted on
  the dispatch row (`col:rimsky_node_runs.scratch_inline` /
  `scratch_handle` / `scratch_handle_backend`); on a superseding
  dispatch (stale-recovery / retry-after-error / recalculate) the
  enqueue path copies it from the prior row onto the new row and
  passes it back in `ExecuteRequest.scratch`. `tags`
  (`repeated string`, set semantics — duplicates collapsed at decode,
  first-appearance order preserved) replaces the prior `NamedEvent.name`
  emission path; each tag MUST appear in the emitting executor's
  observability-declared tag set, and the supervisor's terminal handler
  rejects undeclared names. Downstream subscriptions match on tags via
  CEL `when:` filters over `payload.tags`.
- **`ResumeContext` and Park's `payload` / `session_token` removed —
  resume state rides attribute carry-forward.** `ExecuteRequest.resume_context`
  (field 13) and `Park.payload` (field 2), `Park.session_token`
  (field 4), and the entire `ResumeContext` message are removed (field
  numbers reserved). Executors that need state across a park-and-resume
  cycle write it to `attributes_delta` on `Park` and read it from
  `ExecuteRequest.attributes` on the resume dispatch. The `claude-agent`
  reference executor's session-token resolver collapses to the
  single attribute path (the TS dual-path resolver is gone).
- **`AsyncCallbackBody.events` removed.** Field 1 is reserved.
  Per-emission data folds into the chosen settling outcome's `tags`
  set + `attributes_delta`.
- **`ErrorPayload.action_index` removed.** `events.proto`'s
  `ErrorPayload` drops field 4; the prose enum of allowed
  `action_taken` values narrows to drop `"invalidate"` (the
  operator-invalidate audit-action terminology that retired
  alongside the operator-invalidate route).
- **`PRIOR_HEARTBEAT_STALE` renamed `PRIOR_STALE_RECOVERY`.** The
  enum value at tag 1 of `PriorDispatchDisposition` keeps its wire
  tag; only the symbol name changes. Generated clients re-import
  cleanly; hand-rolled wire parsers reading the symbol name need an
  update. The semantic widens accordingly: the disposition covers
  both the sync RPC connection-broken-in-band case and the async
  `max_quiet_period` exceeded case.
- **`StoreHandle` → `ClaimProducerHandle`; `ExecuteRequest.stores` →
  `ExecuteRequest.claim_producers`.** The dispatch-time handle map and
  its element type both rename. Existing field tags are preserved
  (`ExecuteRequest.claim_producers = 7`); the `kind`, `handle`, and
  `candidate_handle` fields keep their numbers and meaning. Executor
  authors update their generated-stub references; producers continue
  to emit `Acquired.address` bytes as before.
- **`SubScopeDescriptor` gains `address` + `payload` (fan-out wire
  parity).** `claim_producer.proto`'s `SubScopeDescriptor` adds two
  bytes fields — `address = 4` (the per-sub-claim address an executor
  uses to access the underlying data) and `payload = 5` (per-sub-claim
  payload surfaced to the child's substitution via
  `{{claim.<alias>.payload[.<field>]}}`). Both are opaque on the wire
  but the runtime requires JSON-valid bytes when non-empty — producers
  emitting non-JSON address bytes must wrap them in a JSON envelope
  (e.g. a base64-tagged object); non-JSON bytes are rejected with a
  clear error. The change brings sub-claims to wire parity with
  regular claims.
- **Publisher subscription envelopes: `target_node` removed,
  `message_kind` → `message_type`.** `SubscribeRequest` drops
  `target_node` (field 5) entirely — receiver routing now happens at
  rimsky's message-delivery layer against node-subscription edges,
  not at the publisher. `message_kind` becomes `message_type`
  (`SubscribeRequest.message_type = 6`,
  `PublisherSubscriptionDescriptor.message_type = 6`); the publisher
  copies it onto each envelope as `type`. There is no longer a
  default — an empty `message_type` is rejected at the
  receipt-time registry gate. Publishers update their generated stubs
  and stop populating `target_node`.
- **`SensorContext` → `PublisherContext` (validation protocol).**
  `validation.proto`'s `ValidateRequest.context` arm at tag 5 renames
  from `SensorContext` to `PublisherContext` (`sensor_name` →
  `publisher_name`). `validation_supported_roles` accepts `"publisher"`
  in place of `"sensor"`. The bundled sensors (cron, http,
  object-store, webhook) still ship under
  `lib/services/sensors/sensor-*` and keep their service kind names;
  the change is at the validation-protocol surface only.
- **`declared_events` → `declared_tags` on executor observability.**
  `ObservabilityCapabilities.declared_events` (field 7) becomes
  `declared_tags`. Rimsky validates at template registration that
  every subscription's CEL `when:` filter over `payload.tags`
  references a declared tag, and rejects emissions of undeclared
  names at the supervisor's terminal handler. The
  `subscribes: [{..., type: event/<name>}]` grammar is gone — the
  canonical replacement is `type: terminal/*` paired with a CEL
  `when:` predicate matching the tag in `payload.tags`. The
  substitution arm `nodes.<X>.event.<name>.<json_path>` is removed;
  per-emission data rides `nodes.<X>.attribute.<key>` instead.
- **Persistence migration tree reset.** Under the pre-v1 break-freely
  rule, the Postgres and SQLite migration trees consolidate to two
  files each: `001-initial.sql` (a full current-state schema, formerly
  `001-schema.sql`) and `014-drop-supervisor-active-node-count.sql`.
  Migrations `002` through `009` are removed, alongside the
  consolidated intra-development migrations `010`–`013` that landed
  during stories such as utility-nodes, typed-message, and executor
  protocol coherence. Operators on a dev Postgres or SQLite database
  predating v0.10.0 must drop the database and let the migrator
  rebuild from scratch; no compatibility shim is provided. The schema
  itself carries the cumulative shape of every retired migration —
  typed-message tables (`triggering_message_id NOT NULL` on
  `rimsky_frames`, typed-message vocabulary), in-place retry columns,
  the async-callback registry (`async_ack_id`,
  `async_ack_registered_at` with its unique partial index;
  `effective_max_quiet_period_seconds`, `effective_max_runtime_seconds`),
  the per-dispatch scratch columns (`scratch_inline`, `scratch_handle`,
  `scratch_handle_backend`), the message-receiver-node creation
  reason, the `prior_dispatch_disposition` CHECK widened to admit
  `stale_recovery` / `retry_after_error` / `recalculate`, and the
  wait-set CHECK with no `event` row kind.
- **Heartbeat liveness retired across the runtime.** The
  `last_heartbeat_at` columns on `rimsky_node_runs`,
  `rimsky_supervisors`, and `rimsky_claim_handles` are gone. So is
  the supervisor's `livenessTick` cadence — `rimsky_supervisors.active_node_count`
  is no longer cached on the row; `GET /v1/health` computes it
  on-demand via `ListRunning` + a per-supervisor in-memory count.
  `Config.HeartbeatTimeout` is removed; the operator surface narrows
  to three observable deadlines on the async path —
  `sync_rpc_deadline` (default 30s, applied via `context.WithTimeout`
  on the supervisor's unary call), `max_quiet_period`, and
  `max_runtime` (both default `0=disabled`). The async-callback
  registry persists across supervisor restart;
  `SweepExecutorDeadlines` reads the per-row effective deadlines and
  routes `max_runtime` over `max_quiet_period` when both fire. The
  `event/<name>` subscription grammar's heartbeat-derived
  `KindHeartbeatLost` event kind is also retired; the audit-channel
  equivalent for operator-applied debug overrides is the new
  `OPERATIONAL_KIND_DEBUG_OVERRIDE_APPLIED` (tag 82).
- **Error-policy model collapses per-class chains to a single
  node-level `MaxRetries` + per-class `action`.** `TemplateNodeDef`
  gains `MaxRetries` (per-dispatch budget across all error classes)
  and a single `RetryBackoff`. `ErrorTypePolicy` collapses to one
  action per class — `retry` | `pass` | `give_up` |
  `release_and_requeue`. The retired `discard_claims_then_retry`
  action and the per-class `Count` / `Backoff` / `MaxDelayMs`
  chains are gone, as is the supervisor-side default cap that
  silently overrode operator-declared retry counts. `EvaluatorState`
  shrinks to `RetryCounter` (no `ActionIndex`, no per-class cursor).
  Operators with policies declaring per-class retry counts must move
  the budget to the new node-level `MaxRetries`. The new
  `release_and_requeue` action releases acquired locks and the
  dispatch row, exits without state transition; the scheduler
  re-picks the row on its next tick. `handleAcquireUnavailable`
  defaults to releasing the row when no operator policy is declared
  for `acquire/unavailable`. `MaxRetriesWithoutProgressDefault` is
  removed from the Config struct. The supervisor-side
  `defaultInfraRetryCap = 10` is retained for infra-class errors
  operators don't typically declare policies for.
- **Subscription entries require two cascade-shape flags.** Every
  `subscribes:` entry now carries `wake_on_change` (pointer-bool,
  governs whether the receiver fires when the sender's value matches)
  and `force_upstream_refresh` (pointer-bool, governs whether the
  receiver's invalidation drags the named upstream into the same
  frame). Both are required at template registration. The legacy
  `hard_dep:` attribute-field flag is removed — `force_upstream_refresh`
  is its replacement. Implicit edge generation from
  `{{nodes.<X>.attribute.<Y>}}` substitution references is retired;
  every read needs an explicit `subscribes:` entry. Registration
  rejects templates with uncovered substitution refs and emits a
  structured `substitution_ref_uncovered` error carrying a flat
  copy-pasteable suggested entry.
- **Operator-invalidate route retired; `node:reset` becomes a pure
  retry-budget clear.** `POST /v1/admin/instances/{id}/nodes/{id}/invalidate`,
  the `node:invalidate` permission, the
  `rimsky admin invalidate` CLI subcommand, the
  `InvalidateAdapter` / `UnifiedInvalidate` / `InvalidateNode`
  runtime chain, and the corresponding MCP descriptor are removed.
  Re-running a node is expressed by sending a typed message into the
  template's `messages:` registry, or by the gated debug-override
  channel below. `POST /v1/nodes/{id}/reset` survives but is now a
  pure retry-budget clear — no envelope synthesis, no frame opens.
  `Harness.InvalidateNode` is retired from the test scaffolding.
- **Backfill subsystem deleted.** The `concept:backfill` design
  artifact, the `POST /v1/instances/{id}/backfill/*` control-API
  endpoints, the `rimsky backfill create|list|show|cancel` CLI
  subcommands, and the related scenario tests are removed.
- **`rimsky asset materialize` retired.** The `POST /v1/assets/{id}/materialize`
  HTTP handler, the `rimsky asset materialize` CLI subcommand, the
  corresponding MCP tool, and the audit action row are removed.
  Materializing a value happens by running the producing node — via
  a typed message or the debug-override channel.
- **`{{trigger.message.payload}}` substitution retired.** The
  legacy directive collapses into `{{messages.<type>}}` as sugar for
  `{{nodes.<type>}}`. Template authors update their substitution
  expressions.
- **Per-subscription `frame:` modifier retired; one frame per
  message.** The cascade walker carries no frame-shape state on
  individual subscription entries; frames are message-driven and
  one-per-frame. The walker's `Frame` field on `SubscriptionEntry`
  and its `FrameIn` / `FrameNext` / `FrameResolutionCoalesce` /
  `FrameResolutionSerialQueue` constants are gone. The collapse
  eliminated `AppendSourceToQueuedFrame` /
  `ListRunningFramesWithSources` (their backing `source_node_ids`
  column is gone) and the `SweepUpstreamRefreshForRunningFrames`
  scheduler call site. The `frame_resolution_mode` column on
  `rimsky_frames` is dropped.
- **Exported Go API moves.** Public-API consumers see correlated
  renames and signature changes:
  - `lib/foundation/locks`: `ModeCoexists` signature collapses from
    four args to three (`intentA, intentB, sem`) since the original
    quadrant required uniform `WriteSemantics` across the comparison.
  - `lib/foundation/spec`: `NodeStoreRef` → `NodeClaimProducerRef`
    (`lib/graph/node` re-exports the alias). `AggregationPolicy`
    struct is removed entirely; the four `AggregationKind*` constants
    retype from untyped strings to a new `AggregationKind string`
    enum; `AggregationKindCarryVerbatim` is retired. New
    `MessageSchema` struct backs the typed-message registry block.
  - `lib/foundation/persistence`: `NodeEvent`, `NodeEventTable`,
    `NodeEventOrphan`, `ResumeMetadataRow`, and `FrameResolutionMode`
    are removed. New row types appear: `FrameRowWithMessage`,
    `PureCascadeReadyRow`, `NodeRunSummary`, `NodeRunLatest`,
    `NodeRunForGate`, `NonCascadeStaleInput`. New typed-string types
    `CreationReason` and `CascadeMode` replace the previous untyped
    string usages.
  - `lib/foundation/persistence/blob`: new exported `Config`, `Pool`,
    and `New(cfg Config) *Pool` covering the spilled-bytes pool
    that backs scratch + payload + address persistence.
  - `lib/foundation/cascade`: `NodeState` gains `IsInFlight`,
    `IsTerminal`, and `IsSerializationGated` predicate functions
    and an exported `InFlightStates` slice.
  - `lib/foundation/events`: `KindHeartbeatLost()` constructor is
    removed and `KindDebugOverrideApplied()` is added.
  - `lib/graph/node`: `PolicyAction` is now an alias for
    `ErrorTypePolicy`; `BoolPtr` and `IntPtr` helpers are exported.
  - `lib/control/launch`: new exported `StartUnifiedStack`,
    `UnifiedStack`, `OpenDriverFromEnv`, `RunScheduler`,
    `RunSupervisor`, `RunControlAPI`, `RoleFailure`, and `StopFunc`
    cover the single-process unified all-in-one runners.
    `RIMSKY_PROCESS_ROLE=unified` gates the memory blob backend on
    this path.
  - `cmd/rimsky/cli/compose`: new exported `MigratePersistence`,
    `StartRoleStack`, `RoleStack`, `WaitForControlAPIReady`, and
    `RunComposeRun` cover the compose-driver layer that wraps the
    `lib/control/launch` runners for `rimsky compose run`.
    `compose.ApplyPlan` signature changes from
    `(ctx, c, plan, opts) error` to
    `(ctx, c, plan, opts) ([]CreatedInstance, error)` so callers
    receive the created-instance descriptors back inline.
  - `cmd/rimsky/cli`: the exported entry points `RunAdminInvalidate`,
    `RunAssetMaterialize`, `RunBackfillCreate`, `RunBackfillList`,
    `RunBackfillShow`, and `RunBackfillCancel` are removed alongside
    the corresponding subcommands.

## What's new

- **`rimsky compose run <manifest>`.** A self-hosted verb that drives
  a compose manifest to terminal without external infrastructure and
  leaves a forensic artifact under `.rimsky/runs/`. Includes flag
  parsing, an artifact-root walk-up + run-dir layout, synthetic
  `rimsky.yml` / `supervisor.yml` emission, in-process role-runner
  orchestration via `lib/control/launch`, terminal-wait loop, four
  progress-printer modes (default / quiet / verbose / json), and
  graceful drain with bounded SIGTERM-then-SIGKILL escalation plus a
  second-SIGINT escape. Unified mode genuinely shares one
  persistence layer — `RunScheduler` / `RunSupervisor` /
  `RunControlAPI` now take an injected `persistence.Database` from a
  single `launch.OpenDriverFromEnv` site. SQLite `MaxOpenConns`
  default bumped 1 → 8.
- **Typed-message schema layer.** Templates declare a `messages:`
  block; the `emits_message:` node-kind keyword publishes a typed
  message; receipt-time registry rejection guards against
  undeclared types. The substitution path
  `{{messages.<type>.<field>}}` reads from the typed-message vocabulary
  via the same resolver as `{{nodes.X.attribute.Y}}`. Frame creation
  routes through a single `EnqueueFrame` chokepoint; the cascade
  walker has zero frame-creation calls.
- **Cascade-emit.** A node may emit a typed message that opens a
  fresh frame on every subscribing receiver; coalesce semantics are
  expressed by template author choice at the `messages:` and
  `subscribes:` registries rather than per-subscription `frame:`
  modifiers. The walker's stale-mark is gated on `wake_on_change`
  at three sites — terminal-driven, message-driven, and
  pure-cascade — while the wait-set insert remains unconditional
  to preserve the receiver's substitution context.
- **Debug-override channel.** `POST /v1/instances/{id}/debug/override`
  is a new gated route, available only when the instance is paused
  or the breakpoint is in pause-mode-hit state. A new
  `instance:debug-override` permission guards it. The audit ledger
  records each successful override via
  `OPERATIONAL_KIND_DEBUG_OVERRIDE_APPLIED = 82`. This replaces the
  ad-hoc operator-invalidate path for "force the runtime past a
  stuck state."
- **Empty-message wake trigger.** Empty type `""` is seeded as an
  implicit declared-message-type at template registration;
  author-declared `""` entries are reserved-for-runtime errors.
  `BuildSubscriptionEdges` injects structural-root edges keyed by
  `sender=""`; a new `SenderBoundToEmpty` flag disambiguates from
  cross-cutting empty-sender edges. The compose driver and
  `Harness.CreateInstance` emit one empty message per instance
  after create; instance create itself is idle until that
  message lands.
- **Attribute carry-forward as a load-bearing primitive.**
  `resolveAttributes` carries the receiver's own prior-run
  attribute values forward into its next-frame substitution
  context, scope-bounded so sub-graphs seal. This is the channel
  on which `loop_counter` accumulates, on which the `claude-agent`
  reference executor's `session_token` rides, and on which
  parked-and-resumed executor state survives the park boundary
  (replacing `ResumeContext`).
- **Per-dispatch executor scratch protocol.** `ExecuteRequest.scratch`,
  `Success.scratch` / `Error.scratch` / `Park.scratch`, and a
  mid-dispatch `POST {callback_url}/v1/runs/{run_id}/scratch`
  callback give executors a durable opaque blob keyed to the
  dispatch row. The bytes are inert in rimsky. On a superseding
  dispatch (`PRIOR_STALE_RECOVERY` / `PRIOR_RETRY_AFTER_ERROR` /
  `PRIOR_RECALCULATE`) the enqueue path copies scratch from the
  prior row onto the new row and materializes spilled scratch via
  the configured `BlobBackend` before populating
  `ExecuteRequest.scratch`.
- **In-process executor transport.** The supervisor's `ClientPool`
  grows an in-process arm with a channel-backed `EventStream`,
  letting bundled builtins run without a network hop or a
  protobuf wire round-trip. `kind:` becomes template-DSL sugar
  resolved at validation + canonicalize: a `kind:` reference
  expands to the corresponding bundled or operator-registered
  executor. `loop_counter` ships as the first bundled in-process
  builtin; an `attribute_passthrough` builtin is paired with the
  fan-out demo proofs. `IsBuiltinAlias` / `SchemaFor` /
  `DeclaredTagsFor` helpers under the control-API template hooks +
  supervisor schema shim let future builtins light up everywhere
  automatically.
- **Bundled-store fan-out end-to-end.** The filesystem and postgres
  claim-producers advertise `supports_split_scope = true` and
  implement `SplitScope` with substrate-specific
  `partition_request` shapes (list / `batch_pick` / `expand_folder`
  for filesystem; list / `partition_policy` for postgres).
  Sub-claims land at wire parity with regular claims via
  `SubScopeDescriptor.address` + `payload`; sub-claim intent is
  inherited from the parent at the runtime layer. The conformance
  suite extends to cover the SplitScope round-trip. Seven runnable
  example proofs under `examples/` drive the assembled rimsky
  stack over HTTP.
- **`claude-agent` `dispatch_context_read` MCP tool.** Exposes the
  four `ExecuteRequest` dispatch-context fields (`dispatch_id`,
  `run_scope_id`, `prior_dispatch_id`,
  `prior_dispatch_disposition`) as a read-only spawn-time snapshot,
  so the agent can adapt to retry-after-error / stale-recovery /
  recalculate dispatch paths without inferring from indirect
  signals.
- **`claude-agent` session resume rebuilt on attribute carry-forward.**
  The executor's `session_token` rides
  `attributes_delta.session_token` on Park and reads from
  `ExecuteRequest.attributes` on the resume dispatch — the same
  mechanism every other parked-resume executor uses. The TS
  dual-path resolver is gone.
- **Substitution-ref coverage check at registration.** The validator
  rejects templates with uncovered `{{...}}` references and emits a
  structured `substitution_ref_uncovered` error carrying a flat
  copy-pasteable suggested `subscribes:` entry, so template authors
  see the missing edge inline rather than chasing a runtime
  resolution failure.
- **`KindDebugOverrideApplied` audit event.** The
  `OPERATIONAL_KIND_DEBUG_OVERRIDE_APPLIED = 82` operational-kind
  records each successful operator override applied through the
  gated debug channel, distinct from the legacy
  `OPERATIONAL_KIND_OPERATOR_OVERRIDE` which records the surviving
  `node:reset` operator action.
- **Diff-based attribute cascade.** On every settle the runtime
  diffs the run's persisted attribute data against the prior run's
  data and emits `attribute/<key>/changed` only for keys that
  actually changed (`lib/runtime/attribute_cascade.go`,
  `NodeAttributeTable.GetPriorRunData`). Wired uniformly into every
  settle path — terminal complete (held + fresh + poisoned),
  terminal park, `applyErrorPolicy` pass / give-up,
  subgraph-caller settlement, fan-out parent settlement,
  `SettleFromDelegate`, and pure-cascade scheduler.
- **`BuildAttributeDeps` as the single substitution-deps source.**
  The deps map for substituting `{{nodes.X.attribute.Y}}` reads
  each subscribed sender's most-recent fresh-settled attributes
  directly from the attribute store; the wait-set keeps its real
  job (which receiver to evaluate next). Substitution availability
  no longer hangs off cascade emission, so narrowed diff-cascade
  emits don't strand receivers reading unchanged-but-needed
  upstream values. `buildPendingInputBagSplit` and
  `senderKeyedBagToDeps` are removed.
- **Scheduler and claim-poll defaults lowered.** The scheduler tick
  default goes 1500ms → 250ms; the supervisor claim-poll default
  goes 1000ms → 200ms, applied across the Go `Config` defaults,
  the `RIMSKY_SCHEDULER_TICK_MS` env default, and the baked
  `all-in-one supervisor-config.yml`. Recovers ~2.5s of pure
  waiting per dispatch round in services scenarios with no
  measurable DB-load impact.
- **Postgres testcontainer pooling for `make test-all`.**
  A new `lib/foundation/pgpool` ships a per-test-binary postgres
  container with a migrated template DB and per-test
  `CREATE DATABASE TEMPLATE` clones, dropped in `t.Cleanup`. The
  three factories (`test/support/testpg`,
  `lib/foundation/internal/pgtest`, `lib/services/test/harness`)
  delegate to it. Migration-specific tests use a new
  `StartUnmigratedPostgresDSN` that clones the empty template.
  Persistence test packages adopt `t.Parallel()` (safe now that
  each test has its own cloned DB).
- **Per-module `make` targets + CI matrix shard + gotestsum
  report.** The build surface gains per-module targets and a CI
  matrix shard; test runs emit a `gotestsum` report; postgres
  testcontainer flags are tuned. The Makefile's examples
  test-report shard's `jsonfile` path is corrected.

## Fixes

- **Cascade direct-invalidate race.** The cascade-tip's
  upstream-refresh sweep could leave a window between a receiver's
  stale-mark and its wait-set row install during which the
  supervisor dispatched the receiver against a stale upstream
  value. Replaced with a structural fix that routes every
  direct-invalidate path through the same `frame.EnqueueFrame`
  chokepoint that backs typed-message wakes: receivers are stale-
  marked and the wait-set rows mapping each receiver's run to its
  `force_upstream_refresh` upstreams are inserted in the same
  promotion tx. The supervisor's existing eligibility predicate
  then gates the receiver until the upstream settles. No new
  state; no race window. The retired `pullHardDepUpstreams` helper
  is renamed `pullForceRefreshUpstreams` to drop the
  retired-concept name (paired with
  `pullForceRefreshUpstreamsForMessageReceiver` on the
  message-driven path).
  `TestPerRunAttributes_HardDepPullsUpstream_DirectInvalidateOfReceiver`
  now passes.
- **`ClaimDispatchRow` self-idempotency.** The in-place retry loop
  (`acquireOneCandidateWithRetry` →
  `handleAcquireUnavailable`) reclaims the dispatch row in a short
  tx to persist policy state; on the next iteration the
  `WHERE claimed_by IS NULL` predicate rejected the same
  supervisor's re-claim and the loop bailed silently — leaving the
  row stale-and-claimed until the liveness sweep. Predicate
  relaxed to `(claimed_by IS NULL OR claimed_by = $supervisor)`
  in both Postgres and SQLite; pinned by a new conformance case
  `ClaimantGuard/RunClaimSelfIdempotent`.
- **`SelectCandidates` filter excluded pure-cascade rows.** The
  message-receiver-node injected by `createInstance` for each
  declared message type has `executor_name IS NULL` AND no
  `required_stores`; the filter required NULL executor to coexist
  with non-empty `required_stores`, so message-receiver-nodes were
  never selected, named messages never settled their virtual
  node, and subscribers never woke. Filter relaxed to
  `executor_name = ANY(...) OR executor_name IS NULL`.
- **Gate-eval substitution missed delivered messages.**
  `buildResolvedBagAtGateEvalCarry` built `Deps` only from drained
  attribute-kind wait-set rows; messages cascade via terminal-kind
  rows, so `{{messages.<type>.<field>}}` failed with
  `template_resolution_failed` even though the message body sat in
  `rimsky_messages` for the same frame. Mirrored what
  `BuildAttributeDeps` already does at dispatch time:
  `ListDeliveredForFrame` and seed deps keyed by message type.
- **`applyErrorPolicy` audit class vs. policy lookup class.** The
  producer-classified retry path now emits its audit signal keyed
  by the original producer-reported class
  (e.g. `pg/claim_unavailable`) while looking up the policy via
  the synthetic fallback (`acquire/unavailable`).
  `TestProducerClassRouting_PrefixFallback` passes.
- **`handleAcquireUnavailable` no-policy fall-through.** Stopped
  pre-checking `ErrorTypes` and silently releasing the row when no
  policy is declared; nil-policy now falls through to
  `applyErrorPolicy` which `Evaluate(nil)` returns `give_up`.
  Matches `TestAcquireUnavailable_NoPolicyFailsFast`.
- **Idempotent-mode queue dedup shape mismatch.** `bagsEqual` was
  comparing the new pending run's un-resolved sender-keyed bag
  against the prior stale-not-claimed run's post-substitution
  `dispatch_input_bag`; the dedup never fired. The gate-evaluator
  now resolves first, then applies the cascade-mode rule against
  the resolved bag, so both sides have the same shape.
- **Infra-retry counter persisted on the in-flight row.** The
  supervisor-side `defaultInfraRetryCap` retry counter is now
  persisted onto the in-flight run row instead of staying in
  memory, so a supervisor restart doesn't reset it.
- **Settling-signal type surfaced via control + CLI.** The
  control-API and CLI now expose `settling_signal_type` and the
  test fixtures are aligned with the seven-state run schema.
- **Wire-format alignment in service test fixtures + demo
  templates.** A class of fixture-side wire-format drift caught
  during the services scenario sweep is corrected.
- **`HeartbeatTimeout` option retired alongside the protocol
  collapse.** The Go `Config` field is gone; the dead
  `heartbeat_interval_ms` YAML key (which the parser never read —
  it expects `liveness_interval_ms`) is removed from the
  all-in-one, the compose-synthetic, and the services-harness
  baked configs.
- **Subscription-deps unification picked up several latent gaps.**
  `walkCascadeForInvalidatedNode` lacked an own-upstream pull on
  direct invalidation; `pullHardDepUpstreams` was renamed
  `pullForceRefreshUpstreams` to drop the retired-concept name;
  `message_delivery` and `pure_cascade` cascade walkers were
  silently ignoring `wake_on_change`; eight services scenario
  tests + one publisher example + one README built templates as
  JSON map literals that the struct-literal sweep missed and
  needed the new cascade flags added explicitly.
- **Examples test-report shard `jsonfile` path corrected.** The
  Makefile bug that placed `examples.json` outside the repo and
  broke the final `cat` is fixed.
