# rimsky v0.9.0

A **stability-and-correctness release**: thirteen user-outcome stories
land with executable proofs, a race-honest test harness lands ahead of
every consolidation, and the runtime gains four load-bearing
guarantees the spec named — instance-create that never blocks on
publisher reachability, single-process all-in-one mode, upstream
gating at dispatch eligibility, and SQLite multi-process safety. The
child-execution paths unify behind a single dispatch + settlement
primitive, the claim spine collapses fifteen hand-written ownership
guards per driver to one written site, and peer TLS is enforced at
every dial including the HTTP-bridge executor. Several pre-existing
bugs the review cycles surfaced — an SQLite text-timestamp ordering
defect, a broken breakpoint TTL comparison, a cross-supervisor
sub-claim settlement stall — landed fixes alongside the planned work.

## Breaking changes

- **Instance create no longer blocks on publisher reachability.**
  `POST /v1/instances` previously called the publisher's `Subscribe`
  RPC inline with a bounded retry budget; a slow or unreachable
  publisher could hang the request or fail it. The endpoint now
  commits the subscription rows in `mounting` state inside the
  create transaction and returns immediately; a retry-forever
  reconciler drives them to `active` out of band. Clients that
  needed `active` before proceeding must poll `GET /v1/instances/{id}`
  for `subscriptions[*].state == "active"`. Operators see per-
  subscription state on the instance surface (`subscriptions:` array
  on the instance-detail response).
- **All-in-one image runs all three roles in one OS process.** The
  no-command `rimsky-all-in-one:latest` path previously spawned three
  child processes (`rimsky-scheduler`, `rimsky-supervisor`,
  `rimsky-control-api`). It now runs all three roles in-process via
  the new `lib/control/launch` package, gating the memory blob
  backend's now-true single-process premise. Operators reading
  `ps -ef` inside the container will see one process, not four;
  metrics endpoints get per-role port assignments (or
  `RIMSKY_METRICS_PORT_<ROLE>` overrides). Single-role containers
  (`command: [rimsky-scheduler]` etc.) keep their per-process
  behavior, but the strict env-var validation introduced below
  (`RIMSKY_CONTROL_API_PORT`, `RIMSKY_ENTRYPOINT_MIGRATE`) applies
  to them too, since the role binaries route through the same
  `lib/control/launch` runners as the unified path.
- **Upstream gating tightens dispatch eligibility.** A stale run is
  no longer dispatch-eligible while any subscribed upstream has an
  in-flight run in the same frame, regardless of how its staleness
  was propagated (`lib/runtime/runner_acquire_upstream_gate.go`).
  Frames that previously progressed by racing an upstream's settlement
  now wait for it. Pending-only cycles use a deterministic byte-wise-
  lowest tie-breaker so legal cycles stay live. Self-edges are
  excluded (the drain-my-own-queue idiom is preserved).
- **Producer errors cross the HTTP boundary typed.** A producer
  failure that previously surfaced as a bare `500 Internal Server
  Error` now returns `502 Bad Gateway` (producer failed) or `422
  Unprocessable Entity` (producer rejected operator input), with the
  body carrying `producer_name`, `error_class`, and `message`. Clients
  matching on `500` for any producer-related failure need to update.
- **Peer TLS enforced on every dial site.** The `tls` key now parses
  on store and publisher config entries (previously executor-only),
  accepts exactly `off | required`, and every enumerated dial — store,
  publisher, data-processing, validation, executor (gRPC and HTTP
  bridge), observability handshake — honors the mode. `tls: optional`
  is rejected with a clear error naming the entry. `tls: required`
  against a plaintext peer fails loud with the peer name and mode.
- **Static-validator warnings reach `validation_warnings` and trip
  `warnings_as_errors`.** Static warnings (e.g. the acquisition-policy
  advisory) that previously stayed internal now appear in both the
  register and validate response paths and, with
  `?warnings_as_errors=true`, block registration. Templates that
  registered cleanly while quietly tripping advisories will now either
  surface them or be rejected, depending on the flag.
- **`error_types` validation accepts producer-declared classes.**
  `validateErrorTypes` now range-checks against the executor ∪
  producer ∪ `acquire/*` union (`lib/graph/node/template_validator.go`),
  and the `acquire/*` family acts as a prefix fallback when an exact
  producer-class entry is missing. Unattributable keys become
  advisory warnings instead of hard rejections. Templates that
  declared producer-classified `error_types` keys and were previously
  rejected at registration now succeed and route as declared.
- **Migration 009 — subscription-mounting state.** The
  `rimsky_publisher_subscriptions.state` CHECK constraint expands
  to `('mounting','active','failed','stopped')`; a `failure_reason
  TEXT` column is added (nullable, written on the row when a
  non-retryable error stamps the row `failed`); the column default
  flips from `active` to `mounting`; and the partial state index
  rebuilds to cover both `mounting` and `active`. Postgres
  `ALTER TABLE ... DROP CONSTRAINT ... ADD CONSTRAINT`; SQLite
  table-rebuild idiom (no compat shim per the pre-v1 rule).
  Existing dev SQLite database files predating the fixed-width
  timestamp format (see Fixes) should be deleted before upgrade —
  mixed-format timestamp rows mis-order within one second.
- **Exported persistence API: publisher-subscription surface
  reshaped.** Out-of-tree Go consumers of
  `lib/foundation/persistence` see four related changes: the blind
  `PublisherSubscriptions.Update` method is removed and its payload
  struct `PublisherSubscriptionUpdate` is gone; callers migrate to
  the per-state guarded `CompareAndSetState` (or the helpers in
  `lib/runtime/publishers.go::markSubscription{Active,Failed,Stopped}`).
  `PublisherSubscriptions.Get` now requires a non-nil `tx` (the
  caller's tx is no longer optional). `PublisherSubscriptionRow`
  gains a `FailureReason` field (matching migration 009). A new
  state constant `PublisherSubscriptionStateMounting = "mounting"`
  joins the existing set.
- **`RIMSKY_CONTROL_API_PORT` and `RIMSKY_ENTRYPOINT_MIGRATE` are
  strictly validated at startup.** Both env-vars previously fell
  through silently on bad input (`RIMSKY_CONTROL_API_PORT="80a0"` →
  port 0 → default 8080 with no diagnostic;
  `RIMSKY_ENTRYPOINT_MIGRATE="true"` → silent ignore). Both now exit
  non-zero at startup naming the offending value.

Pre-v1 — no production data, no locked-in consumers. Migration 009 is
additive; `make migrate` (or the entrypoint's own migrate step) handles
it.

## What's new

- **Subscription mounting.** Operators see publisher subscriptions
  progress `mounting → active` on the instance surface; the silent-
  mount-failure class is closed. Demo: `examples/subscription-mounting-demo.sh`.
- **Single-process all-in-one mode.** All three roles in one OS
  process under the no-command path; the memory blob backend is now
  safely usable in this mode. Proof:
  `lib/services/test/scenarios/single_process_allinone_test.go::TestSingleProcessAllInOne_MemoryBlobAcrossRoles`.
- **Upstream gating at dispatch eligibility.** Fan-in receivers
  dispatch only after all in-flight upstreams in the frame resolve,
  regardless of propagation path. Proof:
  `test/scenarios/all_upstream_gating_test.go`.
- **Multi-hard-dep rendezvous guard.** Two-hard-dep shapes rendezvous
  in one frame (the livelock was reproduced as a test, then guarded).
  Proof: `test/scenarios/multi_hard_dep_test.go`.
- **Typed producer errors over HTTP.** `producer_name`, `error_class`,
  and `message` carried under 422/502/500 distinction. Demo:
  `examples/producer-error-demo.sh`.
- **Validation rejections name the mode and the config key.**
  Reference-validation failures now read like
  "`example` failed; ref-validation mode `all` made it fatal; relax
  with `templates.ref_validation_mode: available` or `none`".
- **Producer-declared error classes.** New
  `CapabilitiesResponse.declared_error_classes` field
  (`lib/protocols/proto/v1/claim_producer.proto`); producer-classified
  acquisition failures route through `error_types:` with `acquire/*`
  as the prefix fallback.
- **Peer TLS enforcement.** `tls: required` honored at every dial
  site including the HTTP-bridge executor; failures name the peer
  and mode. Proof: `test/scenarios/peer_tls_test.go`.
- **Base-Commit response fields wired.** Producer Commit response
  `version_id` persists on the claim-handle row;
  `producer_metadata` surfaces in fan-out parent writebacks.
- **`work_completed` event emitted at terminal application.** Pairs
  with the existing `work_started`; also emitted for the
  heartbeat-loss-abandoned dispatch in a tx-atomic variant.
- **Named-lock acquisition counter.** Labeled distinct from
  producer-claim acquisitions, bounded cardinality.
- **`ObservabilityCapabilities.validation_supported_roles` on the
  executor observability mix-in.** Validation roles now plumb
  uniformly across all three peer kinds (claim-producer, executor,
  publisher); the executor advertises its supported roles on the
  observability capability surface (mirroring the publisher's own
  `PublisherCapabilities.validation_supported_roles`).
- **Split three-container topology test.** A canonical
  non-all-in-one deployment is now pinned end-to-end.
- **Race-detection gates in the build.** `make test-all` runs a
  thin `-race -count=1` slice over the race-sensitive packages;
  `make test-race` runs the full `-race -count=3` treatment and is
  required by the release chain.

## Fixes

- **SQLite text-timestamp lexicographic ordering.** Timestamp
  columns formatted with `time.RFC3339Nano` had trailing zeros
  trimmed, so within one second `…00.5Z` sorted after `…00.999Z`.
  All SQLite timestamp writes now use a fixed-width nine-digit
  fractional layout; `parseTime` reads both shapes.
- **Breakpoint `AutoResumeStale` TTL comparison.** A space-vs-`T`
  lexicographic compare made any same-day TTL effectively zero;
  every hit under an auto-resume-after-TTL breakpoint resumed
  immediately. Both sides now `datetime()`-normalized.
- **Cross-supervisor sub-claim settlement stall.** A leaf-run
  claimed by a different supervisor than the parent acquirer would
  silently fail to settle the parent — the producer Commit fired
  but `Promote` no-opped on the wrong-claimant guard. The leaf
  acquirer now re-stamps the sub-claim holder; the parent
  settlement takes over the parent handle CAS-guarded before
  resolution.
- **SCC pending-cycle tie-break dual-pass.** A mixed-phase cycle
  member evaluated from two contenders could compute different
  SCCs and both dispatch. The membership predicate is now uniform.
- **Fan-out failure + retried instance-create losing subscription
  rows.** A fan-out failure between the instance commit and the
  publisher inserts left the instance live with zero subscription
  rows. Subscription rows are now inserted inside the instance-
  create transaction, atomic with the instance row.
- **`markSubscriptionStopped` blind update.** A late stop could
  clobber a row's `failed` state and reason; the call now uses
  guarded CAS from the caller-observed prior state.
- **`tryAcquireBatch` aborted on benign selection races.** A run
  row legitimately retired between selection and `tryAcquire` made
  `RunTree().GetByID` return nil → fail-closed → entire acquire
  tick aborted. The lookup-nil branch now skips just that candidate;
  the lookup-error branch keeps the fail-closed abort.
- **Restamp CAS contention aborted whole acquisition batches.** A
  concurrent-supervisor restamp race aborted every remaining
  candidate in the batch. The CAS-mismatch class now skips just
  the contended candidate.
- **Test flakes.** `claim_scope_conflict_race_test.go` counted
  committed (durable) remnants against the simultaneous-active
  invariant; `audit_read_test.go` compared RFC3339Nano timestamp
  strings lexicographically. Both fixed.

## Internal

- **Race-injection hooks at four contended seams.** The
  `PostCommitHook` pattern extended to `PreAcquireUnavailableHook`,
  `CheckAndFireHook`, `PreReapHook`, and the post-fold bail-engine
  route pin — every defended seam has a deterministic injection
  test.
- **Polling audit.** `test/support/eventwait/eventwait.go` —
  event-log-tail helper replacing sleep-poll waits where ordering
  was masked.
- **Claimant-guard helper.** One written `holder_supervisor_id`
  predicate per driver instead of fifteen hand-written copies;
  conformance suite proves wrong-claimant is a no-op on both
  drivers.
- **`DispatchChildren` / `SettleChildren` unification.** Replaces
  the parallel delegation + fan-out paths in `lib/runtime/`;
  carry-verbatim N=1 enforced at template validation; cascade
  bridge fires inside settlement.
- **SQLite multi-process safety.** Bare read-then-write sites are
  transactional via `BEGIN IMMEDIATE`; tick + migration locks are
  `flock(2)`-based file locks (cross-process). The pre-v1 dev-only
  framing is retired.
- **Driver-parity suite expanded.** Eight new conformance areas
  (`frame_lifecycle`, `frame_settlement`, `park_resume`,
  `retention_sweep`, `message_idempotency`,
  `claim_handle_queries`, `publisher_subscriptions`,
  `select_candidates_cursor`, plus the new
  `list_in_flight_run_phases`), all registered in `Suite` and run
  against both drivers.
- **`lib/control/launch` package.** Importable role runners
  (`RunScheduler`, `RunSupervisor`, `RunControlAPI`) that the
  no-command entrypoint and the role-binary mains both use. Role
  binaries shrink to thin shells.
- **Comment-drift sweep.** Ten enumerated comments corrected; the
  archived author guide deleted.
- **Design corpus.** `concept:child-execution` created, 26
  concepts mutated (the plan's 13 spec-directed mutations plus a
  corpus-wide compliance sweep across the three review cycles),
  3 tensions resolved (delegation+fan-out shared primitive,
  reaper-vs-bail abandon asymmetry, sqlite-vs-memory reject
  asymmetry) and one new open tension filed (graph→runtime
  scheduler-import exception), 13 story files + 39 decision files
  created, three TOCs refreshed.
