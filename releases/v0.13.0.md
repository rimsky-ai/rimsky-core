# rimsky v0.13.0

A **governance and hardening release**. Four sprints land here: a
corpus realignment drain that brought the design catalog back into
agreement with deployed reality, an intent-ledger ingestion that
discharged 3,095 accumulated claims, a ruled-intake drain, and an
audit-gap drain that closed thirteen promoted issues. The
user-facing weight is in operator surfaces — `peer_auth: mtls`
becomes a single flip that covers the control API's own port, a
per-run lifecycle endpoint lands on both HTTP and MCP, the bundled
executors converge on one listen-address env-var pair, and the
license check learns to classify third-party dependencies. The
release also removes the race detector from every build gate: the
suite's verdict is now a function of the code alone.

## Breaking changes

- **Bundled executor listen addresses unified.** All four bundled
  executors now read `RIMSKY_EXECUTOR_HOST`,
  `RIMSKY_EXECUTOR_PORT_GRPC`, and `RIMSKY_EXECUTOR_PORT_HTTP`. The
  per-executor forms are gone: `RIMSKY_EXECUTOR_HTTP_NODE_HOST`,
  `RIMSKY_EXECUTOR_HTTP_NODE_PORT`,
  `RIMSKY_EXECUTOR_VERIFIER_HTTP_HOST`,
  `RIMSKY_EXECUTOR_VERIFIER_HTTP_PORT`,
  `RIMSKY_EXECUTOR_VERIFIER_SHAPE_CHECKS_HOST`, and
  `RIMSKY_EXECUTOR_VERIFIER_SHAPE_CHECKS_PORT`.
- **The object-store sensor no longer advertises its in-memory
  backend.** A stock sensor offers only the filesystem backend and
  refuses a subscription naming the in-memory one. Set
  `RIMSKY_SENSOR_OBJECT_STORE_ENABLE_MEMORY_BACKEND` to opt back in.
- **The conformance CLI's lifecycle-check alias flag is removed.**
  Each protocol's suite is reachable only through its own
  `rimsky conformance <protocol>` subcommand; a test now forbids any
  flag naming another protocol.
- **`persistence.Queue` gains `GetAnyByID`.** External implementers
  of the interface must add the method. It returns a dispatch row in
  any state, where `GetByID` filters to in-flight states.
- **`peer_auth: mtls` now covers the control API's own port.**
  Setting it plus the CA key makes every internal peer entry default
  to required TLS and serves the control API over TLS from the
  deployment CA. Services enrolling against a TLS control API need
  `RIMSKY_CONTROL_API_CA`.
- **Carry-verbatim is removed.** The validator's named case is folded
  into the generic unknown-value rejection.
- **License headers moved to SPDX expression form** across the tree
  (`AGPL-3.0-or-later OR LicenseRef-FallGuy-Commercial` /
  `Apache-2.0`). Licensing semantics are unchanged; the root LICENSE
  files still govern.

## What's new

- **Per-run lifecycle state over HTTP and MCP.** An operator holding a
  run id can read that run's state — in flight or terminal — via
  `GET /v1/runs/{run_id}` behind the `run:read` action, and through
  the equivalent MCP tool.
- **Second-signal hard exit on every deployed shutdown path.** A
  second interrupt during graceful shutdown forces immediate exit
  rather than waiting out the grace period.
- **Named-lock acquisitions are graphable alongside producer claims**
  in a single metric family, discriminated by label.
- **The license check classifies third-party dependencies.** An
  Apache-surface package importing an unclassified or
  copyleft-incompatible module now fails the build, against a
  curated permitted-license set.
- **CI runs the plumbline lint.** A comment-hygiene or
  citation-resolution violation fails the build.
- **List fan-out is one store-agnostic capability**, proven
  end-to-end against the bundled filesystem producer as well as
  Postgres.
- **CLI archives ship with published SBOMs**, one per platform
  archive on the GitHub release.
- **Sub-claims inherit their parent's realized write semantics** from
  insert, so a later acquisition overlapping an active fan-out
  sub-claim gets a normal coexistence evaluation instead of a
  misleading in-flight error.
- **The remaining HTTP bridges use protojson** in both directions.

## Fixes

- **A swept-and-re-acquired dispatch emits exactly one
  `work-started` event** across the episode, matching its single
  `work-completed`. The liveness-recovery sweep previously
  double-emitted.
- **Anonymous mode's boundary is exact**: on a fresh deployment every
  operator control-plane action succeeds unauthenticated, and machine
  service enrollment — the one deliberate exception — is refused.

## Internal

- **The race detector is removed from every build gate.** The suite's
  job is catching regressions in business logic, and its verdict must
  be a function of the code alone; a green race-detector run proves
  nothing, so gating on one makes the gate's verdict probabilistic.
  `test-race` is deleted, the `release` chain no longer calls it, and
  a build-chain test fails if `-race` reappears in the Makefile or
  the CI workflow. Deterministic race-injection tests at the four
  defended concurrency seams remain the project's race-defense proof.
- The SQLite retention-contention test's verdict rested on three
  wall-clock constants; it now blocks on signals and passes iff both
  its goroutines complete. The package's runtime dropped from 405s to
  5.9s.
- 233 live decisions brought to choice altitude with genuine
  alternatives; the intent-dossier debt discharged across 76
  dossiers; 111 decisions annotated at their code enforcement sites.
