# rimsky v0.14.0

A **hardening and hygiene release** built from one certified sprint
that drained the ruled issue intake, plus a sweep of the GitHub issue
tracker. The user-facing weight is in the host-agent proxy — under
`peer_auth: mtls` it now enrolls with the deployment CA like every
bundled service and serves its peer-facing protocols on a dedicated
mTLS listener — and in the enrollment machinery itself becoming a
public package (`lib/protocols/peerauth`) that external service
authors can use directly. Template registration gets stricter (unknown
`retry_backoff` values are now rejected up front), a write-only
dispatch-tuning column is dropped from the schema, and the wire
`.proto` files are swept to comment-hygiene zero with no wire change.

## Breaking changes

- **The proxy's peer-facing protocols move to a dedicated mTLS
  listener under mTLS peer auth** (`RIMSKY_PEER_AUTH=mtls` on the
  proxy container). `rimsky-host-agent-proxy` now
  enrolls against the control API (fail-closed: enrollment failure is
  a startup error) and serves the executor / claim-producer /
  lifecycle / observability protocols on a new listener at
  `RIMSKY_PROXY_PEER_GRPC_PORT` (default 9091) that requires client
  certificates from the deployment CA. The agent-facing listener
  (`RIMSKY_PROXY_GRPC_PORT`, default 9090) then carries **only** the
  host-agent protocol and keeps its existing
  `RIMSKY_PROXY_TLS_CERT`/`RIMSKY_PROXY_TLS_KEY` posture. mTLS
  deployments must repoint peer dialers at the new port. Without
  mTLS peer auth the single-listener shape is unchanged.
- **Templates with unknown `retry_backoff` values are now rejected at
  registration.** `retry_backoff.kind` must be `linear` or
  `exponential`; `retry_backoff.jitter` must be `none` or
  `plus_minus` (empty stays legal, meaning defaults). Previously a
  typo was accepted and silently fell through to default behavior.
- **`max_retries_without_progress` is dropped from
  `rimsky_node_runs`** (migration 041, both backends). The column was
  write-only — the park path stamped it and nothing ever read it
  back; the enforcement half of the mechanism was never built. The
  read-side counter `consecutive_retries_no_progress` stays.
  `UpdateDispatchTuning` is removed from the persistence queue
  interface; external implementers must drop the method.
- **`CascadeMode` moves to `lib/foundation/spec`.** The type and its
  four constants relocate from `lib/foundation/cascade`; the spec's
  `NodeClaimProducerRef.Intent` is now the typed
  `claimproducer.Intent` rather than a bare string. External Go
  importers must update references; wire and YAML shapes are
  unchanged.
- **The claude-agent executor's declared-tags surface is removed.**
  `RIMSKY_EXECUTOR_DECLARED_TAGS` is no longer read and the bundled
  registration no longer advertises tags; the capability had no
  consumer.

## What's new

- **Peer-auth enrollment is a public package.**
  `lib/protocols/peerauth` — enrollment against the control API,
  automatic leaf renewal, ready-made gRPC server/client credentials —
  moves out of the bundled services' internal tree, so an external
  service author gets the same fail-closed mTLS machinery the bundled
  services use. The mTLS test kit ships alongside it as
  `lib/protocols/mtlstest`.
- **The proxy can verify an HTTPS control API.**
  `RIMSKY_CONTROL_API_CA` points at a CA-bundle PEM used for the
  proxy's control-API calls (registration `whoami`, instance-cache
  fallback); setting the CA against a non-HTTPS URL is a startup
  error.
- **The host agent's path allowlist is configurable from the
  environment.** `RIMSKY_AGENT_ALLOW_PATHS` (comma-separated) seeds
  the agent's allow-paths without flags.

## Fixes

- **`rimsky help` lists all eight conformance suites.** The root
  usage block was missing `lifecycle-subscriber`; a test now asserts
  set equality between the usage text and the dispatched subcommands
  in both directions. The same sweep adds `auth login` to the root
  usage, corrects the `watch` description to mention `--until`, and
  fixes the `held_frames_list` action description. (gh#41)
- **The CLI's target-agent resolution honors the identity-file
  override.** `RIMSKY_AGENT_IDENTITY_FILE` was already read by the
  agent daemon, but the CLI's target-agent guess bypassed it and went
  straight to the default path; both now resolve through the same
  lookup.
- **The compose audit-artifact demo works again.** Its verification
  query named a column (`phase`) that does not exist and a state
  value that was never written; it now queries `state = 'fresh'`.
- **The all-in-one memory-blob scenario no longer fails on container
  boot retries.** Config files were staged into containers from
  one-shot readers, so a retried boot mounted empty files; staging is
  now temp-file-backed and re-readable.

## Internal

- **The `.proto` files are swept to comment-hygiene zero.** Prose
  comments move out of the wire definitions (and their generated Go);
  no message, field, or RPC changed — the wire is byte-identical.
- **The vendored examples are self-contained.** The compose demos'
  stub executor and sample manifest move from CLI testdata into
  `examples/compose/`, and the one-shot demo was verified to run
  from a vendored copy containing only `examples/` and
  `lib/protocols/`.
- `COPYRIGHT` and `COPYING.md` now name the two SPDX marker strings
  verbatim, matching the license check's constants. (gh#40)
- Corpus upkeep from the sprint: the race-gate-split decision is
  retired, a host-agent-proxy-enrollment decision lands, and five
  concept deltas (plus smaller certification-loop repairs across
  nine more concept docs) bring the catalog to deployed reality.
