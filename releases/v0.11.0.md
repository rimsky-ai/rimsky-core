# rimsky v0.11.0

A **hardening and coherence release**: the deployment grows a real
security perimeter — a deployment CA with service enrollment, mutual
TLS on the core peer and callback hops, TLS on the host-agent proxy,
webhook ingress auth, and a default-closed SSRF egress guard on the
outbound-HTTP services — while a full-repo drift-remediation program
(2,585 adjudicated findings driven to zero open) trues the codebase
up against its design corpus. Frame isolation is restored as a
structural invariant with per-instance message-queue coalescing; the
claude-agent executor is ported to Go with per-node MCP and
expose-env under operator allowlists; the all-in-one path runs
bundled services in-process so `rimsky run` self-hosts templates with
no external infrastructure; and sensors gain a ratified
fault-handling policy (drop on permanent control-API rejection) plus
a settle window for mid-write object-store deposits. Twenty-three new
migration slots (22 postgres/sqlite pairs plus one sqlite-only) and a
wide vocabulary unification (messages are SENT, signals EMITTED;
`NodeRunID` everywhere; claim-producer over "store") land under the
pre-v1 no-compat rule.

## Breaking changes

- **Wire protocol** (`lib/protocols/proto/v1/`): `executor.proto`
  retires terminal/park fields — `reason`, `reason_note`,
  `reason_label`, and the park-time `attributes_delta` are now
  `reserved`; terminal-signal construction collapses onto shared
  builders and the last heartbeat-mechanism remnants are gone.
  Executors built against v0.10.0 stubs must regenerate.
- **Persistence schema**: migration slots 015–037 in both backends
  (036 is sqlite-only — timestamp-dialect normalization; postgres
  skips it). Highlights: the frame owns its root run-scope
  (015, 029), per-instance message-queue coalesce (017),
  frame-isolation restoration (018), deployment CA storage (022),
  claim lease tokens (031), and the claim-producer vocabulary
  renames (033, 037 — e.g. `required_stores` →
  `required_claim_producers`). Pre-v1: migrations run forward
  automatically; no data-compat guarantees.
- **Retired mechanisms**: `terminate_after_run` +
  auto-instance-termination (019), the parked-state watchdog +
  `park_reason` (025), `frame_timeout` (024), the
  `rimsky_frames.state` column (021, lifecycle state now derives
  from node-runs), attribute-override match counters (020, now
  event-derived), and the cross-cutting `(instance: true)`
  subscription form.
- **Template DSL**: `emits_message` is renamed `sends_message`
  (send-vs-emit vocabulary sweep: messages are sent, signals
  emitted). Executor-side `${env:VAR}` substitution is retired in
  favor of the `{{env.VAR}}` substitution source, resolved by the
  platform.
- **Outbound HTTP is now default-closed (SSRF guard)**: the
  `http-node` executor and `sensor-http` sensor block
  loopback/private/link-local/metadata destinations unless the
  deployment opts CIDRs back in via
  `RIMSKY_EXECUTOR_HTTP_NODE_EGRESS_ALLOWLIST` /
  `RIMSKY_SENSOR_HTTP_EGRESS_ALLOWLIST`. Deployments that reach
  internal endpoints must set the allowlists.
- **Sensor rejection policy**: on a permanent control-API rejection
  (4xx except 408/429), every bundled sensor now logs loudly, drops
  the observation, and advances its consumed-state — transient
  failures keep the retry behavior. Previously a rejected
  observation could be retried forever.
- **claude-agent executor**: the TypeScript implementation is
  retired; the executor is now Go. Per-node MCP servers and
  expose-env are gated by operator allowlists
  (`RIMSKY_CLAUDE_AGENT_MCP_ALLOWLIST`,
  `RIMSKY_CLAUDE_AGENT_EXPOSE_ENV_ALLOWLIST`; unset = open for
  local dev, set = exact boundary).
- **Peer auth**: core peer and supervisor-callback hops speak mutual
  TLS under the new deployment CA; services enroll via the
  `service:enroll` permission; the run-token mechanism is swept.
  Zero-config local dev keeps working via daemon-administered
  loopback mTLS.
- **Supervisor callback advertise is fail-fast**: an empty
  `callback.advertise_host` (or
  `RIMSKY_SUPERVISOR_CALLBACK_ADVERTISE_HOST`) combined with a
  wildcard bind is now a startup error — the supervisor refuses to
  stamp `http://0.0.0.0` into callback URLs. Deployments that bound
  `0.0.0.0` without an advertise host must set one before
  upgrading.
- **Entrypoint migrate ownership**: in a split-role stack only the
  `rimsky-control-api` container runs migrations (the no-command
  all-in-one path still always migrates), so a three-container
  deployment migrates exactly once. `RIMSKY_ENTRYPOINT_MIGRATE=1|0`
  overrides per container; any other non-empty value is a startup
  error naming the value.

## What's new

- **Deployment CA + enrollment**: a per-deployment certificate
  authority with service enrollment, agent-proxy TLS, webhook
  ingress auth, and outbound bearer auth on the openlineage
  subscriber.
- **Frame isolation as a structural invariant**: each frame owns its
  root run-scope; cross-frame state leaks are closed; per-instance
  message-queue coalescing replaces the queued-frame state.
- **All-in-one, no infrastructure**: bundled services register
  in-process in the unified stack; `rimsky run` self-hosts templates
  when no endpoint is configured; `rimsky compose run` and the
  all-in-one image share the single-process path.
- **claude-agent (Go)**: per-node MCP server declarations
  (`transport: http | stdio | module`), expose-env pass-through that
  keeps rimsky out of the credential loop, per-node silence and
  tool-in-flight deadlines (default-disabled).
- **`{{env.VAR}}` substitution source** for attribute templates.
- **`rimsky watch`** settles on idle and supports a pending-message
  filter end to end.
- **Sensors**: `sensor-object-store` holds mid-write deposits until
  a settle window elapses; all sensors implement the ratified
  drop-on-permanent-rejection policy.
- **Operator diagnostics**: `GET
  /v1/admin/diagnostics/producer-outbox` surfaces the producer verb
  outbox; error dispositions gain a retry-after channel.
- **Executor callback routes**: external executors can now `POST
  ${callback_url}/v1/runs/{run_id}/keepalive` and `/attributes`
  during a run, authorized by the dispatch's `cancel_token` as a
  bearer.
- **Multi-replica correctness**: lifecycle scope transitions
  serialize across replicas via a postgres advisory lock (sqlite's
  single-writer mode subsumes it).

## Fixes

- The drift-remediation program closed 2,434 adjudicated findings
  across the ledger, including a 249-defect confirmed-bug wave.
  Highlights: filesystem claim-producer recycle-ring ordering broke
  under Docker VirtioFS mtime flooring (now an explicit ring
  position), sequenced-cascade per-round upstream pinning restored,
  graph names carried across the async boundary so graph-scoped
  `after_terminal` breakpoints match, MCP session lifecycle races,
  concurrent-reap ack correlation in the host-agent proxy, and a
  `staged_async` swap that cascade-destroyed external schema
  objects.
- Security closures beyond the perimeter work: a core
  validation-bypass trio, frame-end and queue-cap TOCTOU races,
  atomic last-active-key revocation, webhook body-size caps,
  host-agent allow-path canonicalization, and stolen-spawn-port
  retry.

## Internal

- Full-repo drift-remediation program: three phases, worktree-wave
  orchestration, ledger archived under `.ok-planner/history/`.
- Vocabulary unification: send/emit, `NodeRunID`, claim-producer;
  tx-last parameter idiom across ~1,900 call sites.
- Content-addressed image tags (`:src-<tree-hash>`) with harness
  self-resolution — test paths no longer consume `:latest`; an
  in-stack test-runner image executes suites inside the stack
  network (`make test-in-stack`); `make reap-images` prunes stale
  tags.
- Planning estate migrated to the ok-planner 4.x layout (issue
  queue, sketches, same-named history archives).
