# Intent Dossier: signal

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner

## Net position

- Every node-run transition is described by one unified vocabulary: a Signal {type, payload} with a hierarchical slash-separated type-path, driving cascade-fire, audit, and subscription (2026-05-23, signal-taxonomy-and-policy-decoupling, artifact; never retracted).
- The current taxonomy families are: `terminal/success`, `terminal/error/<class>` (the only two run-terminating verdicts); `transient/*` (retry/<attempt>/<class>, park/snooze, park/await_callback, await_async, infra/<class>, release_and_requeue/<class>); and `attribute/<key>/changed`. The `event/<name>` and `message/*` families are retired (see Intentional absences).
- "Terminal" means run-terminal only: a signal that can be followed by another dispatch in the same run is not a terminal. Park and infra are not terminals (2026-06-24, 8a8539a4, transcript).
- Type-paths are canonical and validator-enforced; ValidateTypePath is wired into the emit helper so an undeclared type-path fails mechanically at emit time (2026-06-23, 10cf843b, transcript).
- The cascade engine is signal-blind: firing is gated purely on (edge type-path match) AND (CEL when: predicate); the engine never branches on the signal type. Every terminal outcome continues the cascade — terminal/error cascades exactly like terminal/success (2026-06-10 artifact; reaffirmed forcefully 2026-06-18, 8a3b8c19, transcript).
- Cascade-fire IS subscriber match. There is no sender-side cascade-fire gate; senders emit signals, receivers decide (2026-05-23, artifact).
- Non-cascading signals (transient/park/*, transient/await_async, formerly terminal/infra) emit a bare audit row and no cascade, because the node resumes rather than settling (2026-06-10 artifact; park reclassification 2026-06-24 transcript).
- Signal payloads never propagate down the cascade. A payload has exactly two consumers: the CEL when-predicate evaluated at walk-time to gate wait-set insertion, and the audit-log row. Wait-set rows carry no payload; subscribers receive the wake, not the payload (2026-06-23, 10cf843b, transcript; stated durably at the primitives when tension event-vocabulary-implies-delivery was resolved 2026-07-07, 3f71f90a).
- Every signal emit, cascading or not, writes one audit row to rimsky_events with kind = the type-path, unconditionally and independent of subscribers (2026-05-23, artifact; reaffirmed 2026-06-10).
- attributes_delta exists only on terminal/success and terminal/error/<class>, and means what this dispatch's verdict contributed — never the node's full persisted bag. A parking executor writes no node attributes; aggregate/holder settlements carry an empty delta (2026-06-24, 8a8539a4, transcript).
- attribute/<key>/changed is diff-based and uniform: every node, on every settle path, regardless of node type or executor presence, diffs final settled values against the prior run's persisted values (same-RunScope only; empty bag if no prior run, so first runs emit for every key) and emits only for keys that actually changed (2026-06-22..23, 10cf843b, transcript).
- The diff-gate baseline is same-RunScope only — no cross-frame or cross-scope fallback. Frame isolation is the north star; a node re-running in a fresh frame has no prior, so the signal fires (2026-07-05..06, 3f71f90a, transcript).
- Vocabulary: signals are EMITTED (broadcast into the subscription fabric, receivers opt in); messages are SENT (directed push). Swept repo-wide (2026-07-03..06, 3f71f90a, transcript).
- Tags on terminals (terminal-tag) replace named events: every settling terminal carries type + attributes_delta + a set of tags; tag-conditional subscription is CEL `"<tag>" in payload.tags` (2026-06-16..17, 055468fc / b31002b8, transcript).
- Every signal type-path binds exactly one canonical payload schema; all terminal-signal payload construction flows through single typed builders (BuildTerminalErrorSignal / BuildTerminalSuccessSignal) with positional signatures requiring every schema field (2026-06-24, 8a8539a4, transcript).
- Color (fresh | failed | parked) is informational only; cascade never gates on color (2026-05-23, artifact).
- Node execution is orderly and stepwise: a node fully settles at its terminal before any downstream subscriber sees its signals; each terminal walks exactly one level of receivers — no multi-level BFS (2026-06-16 transcript; one-level walk 2026-05-23 divergence, artifact).
- Signals at a terminal are deliberately emitted through two paths per key: inline in-transaction into the cascade walker (so when: predicates see real payload values) and post-commit as the canonical audit row. Judged deliberate, not a bug (2026-05-23 divergences, artifact) `(artifact-only)`.
- Known deliberately-open item: non-signal audit kinds (state_transition, lock_acquired, auth.*, etc.) remain free-form TEXT; the events-kind-no-enum tension was left open by choice (2026-05-23, artifact) `(artifact-only)`.

## Required behaviors (open promises)

- Unconditional audit emission: every signal writes one rimsky_events row with kind = type-path and payload as JSONB, independent of subscriber match (2026-05-23, signal-taxonomy-and-policy-decoupling, artifact): "Independent of subscribers; audit always emits."
- Emit-time type-path validation: ValidateTypePath enforced in the emit helper, with test coverage for the guard and for the declared transient/infra/<class> and transient/release_and_requeue/<class> patterns (2026-06-23, 10cf843b, transcript): "fix it (and make sure we have test coverage for it)".
- Every terminal outcome continues the cascade; terminal/error cascades like terminal/success, including when the sender settles via error_types: pass (fresh color) or give_up (failed color) — the issue #15 behavior is pinned (2026-06-10 artifact; 2026-06-18, 8a3b8c19, transcript): "*every* terminal outcome will continue the cascade."
- terminal/error/abandoned is a cascade-firable, subscribable signal emitted when held work is abandoned (2026-06-20, 8a3b8c19, transcript): "it means the node's work was lost, so the graph should be able to detect and react to that." Uses the terminal/error/<class> subclass shape, not a new signal root.
- Held-cascade broadcast rule: every node that executed during a claim hold broadcasts the commit/abandon outcome to its subscribers at claim resolution — terminal/success at commit, terminal/error/abandoned at abandon; during the hold, cascade flows only among held-subgraph members (2026-06-20, 8a3b8c19, transcript).
- Diff-based attribute/<key>/changed emission, uniform across every settle path, driven solely by the persisted attribute delta, with audit emission driven by the same diff (2026-06-22..23, 10cf843b, transcript): "emit signals only for the attributes that actually did change during the run."
- Single typed terminal-payload builders with positional all-fields signatures; no divergent inline payload construction (2026-06-24, 8a8539a4, transcript): "why isn't there a single method that emits terminals and requires all fields?"
- attributes_delta = verdict contribution only; holder/aggregate settlements carry an empty delta (2026-06-24, 8a8539a4, transcript).
- Template registration rejects subscriptions to park signal types; users can only subscribe to success and error settling signals (2026-06-24, 8a8539a4, transcript): "report an error if templates subscribe nodes to park."
- Tag mechanics: TerminalSuccessPayload and TerminalErrorPayload carry Tags []string; two-gate tag validation (registration warning against declared_tags; runtime rejection of undeclared tags as executor_protocol_violation) (2026-06-17, b31002b8, transcript).
- loop_counter declares exactly two tags (loop, done); Success carries loop below max, done at max; with max=3, three dispatches total (2026-06-17, b31002b8, transcript).
- The five foundation cascade scenario proofs (attribute-changed diff-gate, sequenced-preserves-cascade-rounds, idempotent-mode-dedupes, cascade-defers-during-flight, most-recent-coalesces-cascades) must exist and be green — retiring them was rejected (2026-07-05, 3f71f90a, transcript): "no deferrals, no follow-ups... this is foundation, so we won't accept any unknowns."
- Async handoff emits transient/await_async atomically in the same transaction as persistent ack registration, so async work survives supervisor restart (2026-06-17, b31002b8, transcript).
- Empty-string sentinels stay swept: SettlingSignalType is a nullable *TypePath with honest nil-checks; no "empty string means success" first-class value (2026-06-19, 08d65bfe / 8a3b8c19, transcript).
- GET /nodes/{id} carries settling_signal_type (canonical type-path, absent when not settled), matching the run-tree/lineage value (2026-06-06, comprehensive-gap-closure, artifact) `(artifact-only)`.
- Hierarchical bundled-executor error classes: pg/verifier_check_failed/<check_kind>, http/server_error/<status>, agent/tool_use_failed/<tool> etc., so subscribers can prefix-match a failure family or pin a leaf (2026-05-23 artifact; reaffirmed for restoration 2026-06-15, 8c66c02c, transcript).
- Declared error classes must have real emit sites: pg/claim_unavailable and pg/swap_failed must actually fire and reach subscribers, not merely validate (2026-06-06, comprehensive-gap-closure, artifact) `(artifact-only)`.
- Fan-out child aggregation emits terminal/error/aggregate/{strict_failed,threshold_failed,first_failed}, passing through the generic terminal/error/* prefix by design (2026-05-23 divergences, artifact) `(artifact-only)`.
- Breakpoint signal_type filter: valid only on after_terminal checkpoints (400 on before_dispatch), validated against the taxonomy, trailing-* only, prefix-matched against the terminal signal's type-path; pre-dispatch failures (OnError path) are not caught by after_terminal (2026-05-24, instance-debugger, artifact) `(artifact-only)`.
- OnError emits the canonical terminal/error/acquire/unavailable (or transient/retry/<n>/acquire/unavailable) from each branch's state-transition transaction; OnError and applyErrorPolicy deliberately remain two functions (2026-05-24 review-cleanup, signal-taxonomy divergences, artifact) `(artifact-only)`.
- instance_killed is a state-machine-validation-only transition reason, never an audit-event kind; the teardown's auditable cause is one administrative instance_terminated event row (underscore form, not the slash taxonomy) (2026-05-28, quality-of-life-features, artifact) `(artifact-only)`.
- Event-log payload split: typed oneof payloads for signal-class events; free-form JSON for operational events (2026-06-08, corpus-bootstrap, artifact) `(artifact-only)`.

## Intentional absences

- `event/<name>` signal family, the rimsky_node_events ledger table (dropped, migration 013), and the {{nodes.X.event.Y}} substitution arm — retired outright in favor of tags on terminals (2026-06-16 decision, 055468fc; executed 2026-06-17, b31002b8, transcript). Restorers must not resurrect named events in any form.
- `message/*` signal-taxonomy family — on the excise list of retired mechanisms that must not appear as current (2026-07-07, 3f71f90a, transcript). Messages are nodes/virtual-nodes, not a signal kind.
- `terminal/park/*` and `terminal/infra/*` — park moved to transient/park/{snooze,await_callback} (audit-only, never cascade-fires, subscriptions rejected); terminal/infra/* deleted entirely (never emitted; infra failures retry via transient/infra and settle as terminal/error/<infra-class>) (2026-06-24, 8a8539a4, transcript).
- attributes_delta on Park — fully backed out (proto wire field, persistence merge, payload exposure) after park's reclassification as a non-terminal (2026-06-24, 8a8539a4, transcript).
- The last-outcome concept and last_outcome column (schema-dropped), and the fresh_changed cascade-fire gate — replaced by subscriber match plus payload fields (changed on terminal/success, discarded_claims on transient/retry) and lineage's settling_signal_type (2026-05-23, artifact; fresh_changed also on the 2026-07-11 excise list).
- `recalculate` as a second graph-level message — invalidate is the only graph-level cascade message; recalculate is a verb, not a message; the concept file was retired (2026-05-04, public-docs-architecture, artifact).
- A `lifecycle/*` top-level signal kind — declined; lifecycle-subscriber protocol covers those cases; a node-subscription path would be parallel with ambiguous semantics (2026-05-23, artifact).
- transient/on_error_resolved and transient/policy_resolved — declined; subscribers subscribe to the resulting terminal directly (2026-05-23, artifact).
- The synthetic terminal/success "invalidationCascadeSignal" walk after parked-resume and upstream-refresh propagation — residue of the retired invalidate concept; removed after causing a confirmed spurious-dispatch bug (2026-06-18, 8a3b8c19, transcript).
- Multi-level BFS cascade walk over downstream receivers — each terminal walks exactly one level; deliberate spec-intent override (2026-05-23 divergences, artifact).
- Fan-in attribute merging (mergeChildAttributesIntoHolder and its per-key attribute-changed emit at holder settle) — removed entirely; fan-out nodes discard per-partition output attributes (2026-06-22, 10cf843b, transcript).
- Cross-frame diff-gate baseline (the GetPriorRunData widening, commit 20724e96) — ruled a frame-isolation violation and fully reverted, including the concept:signal clause that documented it (2026-07-05..06, 3f71f90a, transcript).
- Pull-vocabulary rename of subscribe/payload (watch, body, event→response) — considered and declined; tension resolved by keeping the names and stating the walk-time-only payload semantics at the primitives (2026-07-07, 3f71f90a, transcript).
- The loop node's "loop"/"done" as named events (2026-06-14 position) — superseded by loop/done tags on Success under the terminal-tag model (2026-06-17, b31002b8, transcript).
- The `frame: in|next` subscription modifier — frames are opened only by message arrival; frame: next is not restored; multi-frame behavior is explicit messaging (2026-06-15, 4c42fe5b, transcript).
- AsyncCallbackBody.events array and NamedEvent stream events — removed with the executor-protocol-coherence refactor (2026-06-16, 055468fc, transcript).

## Conflicts needing human ruling

- **RESOLVED 2026-07-14 (user ruling, transcript tier): only settling events are subscribable — retry is out.** The subscribable set is exactly {terminal/success, terminal/error/*, attribute/*/changed}. User: "it is fine to say that only settling events are subscribeable, which rules out both park and retry... consistent and fine to remove retry. we can't think of any good reason to subscribe to it." The 2026-06-24 walk-back's recovered rationale (the settle boundary: audit-only signals mark a run that resumes rather than settles — no outcome for downstream to consume) is ratified as the principle; the user notes the 06-24 ruling read as a compromise over the attributes_delta issue at the time, but the settle-boundary line is endorsed on its own merits. Consequences: (a) subscriptions to every transient/* type (retry, infra, release_and_requeue, await_async) are rejected at template registration with the same audit-only style error park gets; (b) transient/retry and transient/release_and_requeue emission becomes audit-only — no cascade-fire (today they ride the cascade+audit bundle in the error-policy path; that is now a defect); (c) the cascade-firing set narrows to {terminal/success, terminal/error/<class>, attribute/<key>/changed}, superseding the 2026-06-17 enumeration that included transient/retry; (d) retry/park visibility is the event log's job, not the graph's.
- **RESOLVED 2026-07-14 (user ruling, transcript tier): signal emission is one bundled in-transaction path.** Cascade-fire (wait-set staging) and the audit event-log row happen atomically in the same transaction as the settlement (today's emitSignalInTx shape); either both land or neither. The May dual-path (walker inline + post-commit audit write, 2026-05-23 artifact "deliberate") is superseded historical — its crash window let the event log lie about what the cascade saw. Audit-only signals invoke the audit half alone (park today; transient/retry and release_and_requeue join per the 2026-07-14 subscribability ruling). Findings asserting post-commit audit emission are refuted.
