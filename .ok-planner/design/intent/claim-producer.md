# Intent Dossier: claim-producer

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner

## Net position

- The protocol is canonically **4 verbs (Open / Commit / Abandon / Release) plus the Capabilities() startup handshake**, with optional SplitScope and ScopesConflict mix-ins advertised in capabilities. The Go interface additionally carries Name(), which is not on the wire (2026-05-11, log-convergence; 2026-05-19, crimefinder).
- The noun "store" is fully retired from core: protocol, Go types, YAML keys, proto fields, routes, scheduler predicates, image names all say claim-producer / claim_producers. "Store" survives only as bundled-services-layer colloquialism for data-backed producers (2026-05-12, nomenclature-resolution; ratified and completed per user order "rename them all", 2026-06-19, a02fe167, transcript). The legacy top-level `stores:` YAML key stays hard-rejected with an error directing rename to `claim_producers` (2026-06-19, a02fe167, transcript).
- OpenResponse is a oneof of Acquired (address, payload, canonicalized scope bytes, realized_write_semantics) or Unavailable; Unavailable carries an `error_class` field routable through error_types. claim_id is rimsky-generated (2026-05-04, service-protocol-contract; 2026-06-06, comprehensive-gap-closure).
- Open fires inside the foundation-side acquisition transaction between the claim-handle INSERT and COMMIT; address, payload, and realized_write_semantics can never be back-filled, mutated, or refreshed afterward (foundation invariant 15) (2026-05-04, foundation-contract, artifact-only).
- Scope and address bytes are opaque end to end (invariant 20): never logged, %v-formatted, validated, transformed, or put in error messages by rimsky (2026-05-11, log-convergence).
- Single-writer-per-scope (invariant 4b): overlap is producer-defined via ScopesConflict when advertised, byte-equal comparison as the trivial default; rimsky must actually consult ScopesConflict during acquisition and the fan-out sub-claim path (2026-05-15, data-platform-extensions; 2026-06-06, comprehensive-gap-closure; reaffirmed 2026-07-13, 3f71f90a, transcript).
- staged_async producers must not internally serialize writers on lock-shaped predicates (invariant 9b); the conformance suite actively probes this (2026-05-04, service-protocol-contract; 2026-06-06, comprehensive-gap-closure).
- Claim intent ('r'/'rw') is a cascade-layer contract: producers validate its shape at Open, capture it, and correctly ignore it afterward; the coexistence predicate (ModeCoexists) is the load-bearing consumer (2026-06-18, 8e7e4c10, transcript, user).
- Fan-out is completely orthogonal to messages: a fan-out is just a claim request to a producer triggered by a partition; the producer decides the partition (producer-specific partition_request schema in, standardized list of SubScopeDescriptors out); the fan-out node only iterates the returned list (2026-06-18, 9fb55f08, transcript, user).
- Both bundled stores (filesystem and postgres) implement SplitScope and advertise supports_split_scope: true — this is inside the v1-code-complete line (2026-06-18..19, 9fb55f08 / 8e7e4c10, transcript).
- Per-partition executor attribute writebacks do NOT aggregate onto the fan-out parent; rimsky invents no aggregator vocabulary. Sanctioned output channels: producer_metadata on Commit, the data-processing mix-in, and the asset surface keyed by version_id (2026-06-22, 10cf843b, transcript).
- The protocols module carries zero non-stdlib dependencies beyond grpc and protobuf; protocols/claimproducer is the single canonical Go home for the contract types (no foundation/locks re-exports) (2026-05-04, layer-crystallization; 2026-05-26, collapse-sdk-into-protocols).
- Producer/store connection configuration (e.g. postgres connection strings) never lives in rimsky config in any mode; it lives with the store instance, resolving env-vars at store-load time (2026-07-01, 8a8539a4, transcript, user).
- Bundled claim producers and executors register in-process for the all-in-one path via a lib/services bundled RegisterAll entrypoint and an in-proc claim-producer registry paralleling the executor one; sensors and lifecycle-subscribers are excluded from in-proc bundling (2026-07-01..03, 8a8539a4 / 3f71f90a, transcript).

## Required behaviors (open promises)

- **4-verb + Capabilities protocol lifecycle**: rimsky drives Commit at auto-terminal success, Abandon on failure, Release at lifecycle close; a template referencing a write-semantics the producer doesn't advertise is refused at registration — "a template referencing a write-semantics the producer doesn't advertise is refused at registration." (2026-06-08, corpus-bootstrap, artifact).
- **Unavailable is a first-class outcome, not an error**: producers with nothing to give return Unavailable; the Unavailable claim itself is never Abandoned ("the producer signaled Unavailable, meaning it has no state to abandon — that's the contract"); pass/error lifecycle resolutions Abandon already-opened Available claims; retry does not (producer TTL covers partials) (2026-05-04, service-protocol-contract; 2026-05-05, reactive-loops-and-lifecycle-handlers, artifact).
- **OpenRequest scope envelope**: template_id + instance_id ride OpenRequest as an envelope opaque to rimsky but available to the producer for namespace routing; the selector arrives post-substitution and the producer parses it (2026-05-04, service-protocol-contract, artifact-only).
- **ScopesConflict enforcement**: when advertised, disjoint sub-scopes dispatch concurrently and overlapping scopes serialize; producers not advertising are never asked (2026-05-19, crimefinder; 2026-06-08, corpus-bootstrap, artifact).
- **Pick-policy v2 vocabulary**: pop / pop_and_move / pop_and_delete / recycle across both bundled stores, backed by one shared Action type so strings cannot drift, with a cross-store consistency test; the Action vocabulary lives in the public protocols module as the canonical cross-implementer surface (2026-05-06, fs-store-pick-policy-action-vocabulary; 2026-05-24, repo-reorganization, artifact).
- **Pick-policy validation rules** (filesystem store): on_commit/on_give_up required with no defaults; pop + sync_strategy on_open rejected; recycle + on_drain warns; pop_and_move targets must be same-filesystem (device-ID check after EvalSymlinks), pre-existing, siblings of the policy root; YAML shape is bare string xor one-key map (2026-05-06, fs-store-pick-policy-action-vocabulary, artifact).
- **Postgres store supports only pop and recycle**; pop_and_move / pop_and_delete rejected at config-load and defensively in applyPickAction; no sync_strategy field — "its items table is the source of truth" (2026-05-06, fs-store-pick-policy-action-vocabulary, artifact).
- **sync_strategy closed enum** on the filesystem store: on_open (default) / on_drain / explicit / never; on_drain implements single-pass-then-refresh via the drained sentinel (exactly one Unavailable per drain pass, auto-refresh on next Open); explicit exposes an operator-triggered admin HTTP sync endpoint (2026-05-06, fs-store-pick-policy-action-vocabulary; 2026-06-06, comprehensive-gap-closure, artifact).
- **Retry-budget enforcement does not live in the store**: budget belongs to rimsky's error_types chain at the node level; the pick-policy stays the "what happens to this slot and resource" abstraction (2026-05-06, fs-store-pick-policy-action-vocabulary, artifact).
- **Atomic staging**: with staging enabled, filesystem-store Commit performs a real atomic POSIX rename swap of staging into the canonical view (never copy-then-overwrite); Abandon discards staging leaving canonical untouched; Release of an uncommitted rw claim ≡ Abandon; held subgraphs commit-or-abandon all-or-nothing. A copyable Apache-licensed reference producer ships at examples/atomic-staging-fs-producer/ with a staging-TTL sweep (default 24h) and a same-filesystem startup check (2026-05-14, subscription-cascade-and-quality-of-life; 2026-06-02, acceptance-coverage-recovery; 2026-06-06, comprehensive-gap-closure, artifact).
- **Postgres store staged_async delivered semantically**: Open reserves a real staging schema, Commit performs an atomic schema swap ("never a no-op"); declared error classes pg/swap_failed and pg/claim_unavailable routable through error_types; row_count_ratio verifier check compiles to an aggregate-only query (2026-06-08, corpus-bootstrap, artifact-only — supersedes the 2026-06-02 "no-op by design" position, see Superseded).
- **Fused postgres store**: one binary registers Executor alongside ClaimProducer (verifier role: no_nulls, row_count_absolute, pk_unique checks, aggregate-only SQL; all-pass Success, failure error_class verifier_failed) (2026-05-19, multi-instance-template-ergonomics, artifact-only).
- **DataProcessing mix-in**: seven control-plane methods (Capabilities, BeginCandidate, CommitCandidate, AbandonCandidate, ListVersions, ListPartitions, GetVersionSchema); producer aggregates candidates at Commit and returns version_id, recorded in claim handles and lineage; rimsky stays substrate-agnostic, data motion stays substrate-direct (2026-05-15, data-platform-extensions; 2026-06-08, corpus-bootstrap, artifact).
- **Base Commit response fields are real**: version_id from the base Commit response persists to the claim-handle row; producer_metadata surfaces in the fan-out parent's writeback (2026-06-11, last-mile-stability, artifact).
- **Bundled-store SplitScope shapes**: filesystem accepts {"list": [...]}, {"batch_pick": {"max_items": K}}, {"expand_folder": {filter, depth, kind}}, unknown shapes rejected InvalidArgument; batch_pick against a direct-address parent (no pick policy) requires an explicit policy field naming the queue; postgres accepts {"list": [...]} and {"partition_policy": "@<name>", "params": {...}} with operator-pre-declared partition policies in YAML — zero SQL in the template authoring surface (2026-06-18..19, 9fb55f08 / 8e7e4c10, transcript, user).
- **List pass-through is the cross-producer shape**: its unmarshal helper lives in lib/services/stores/shared/ so any third-party producer can adopt it (2026-06-18, 9fb55f08, transcript).
- **SubScopeDescriptor carries address and payload bytes** threaded through Go types, the peer bridge, and the sub-claim insert path so each fan-out child can read {{claim.<producer>.payload.<key>}}; non-empty address bytes must be JSON-valid, rejected with a clean precondition error (2026-06-19, 8e7e4c10, transcript).
- **Conformance suite**: drives the full lifecycle (Open→Commit, Abandon, Release on real claims, plus a re-issued terminal verb asserting idempotency), the serialization-9b probe, and SplitScope cross-producer checks (rejection when unadvertised, list round-trip, SubScopeDescriptor wire shape incl. SplitScopeListReturnsAllElements / SplitScopePreservesPartitionKey / SplitScopePreservesPayload / SplitScopeAddressFieldPresent); per-check pass/fail, non-zero exit on failure. Substrate-native shapes are tested in each store's own suite, not conformance (2026-06-06, comprehensive-gap-closure; 2026-06-08, corpus-bootstrap; 2026-06-18..19, 9fb55f08 / 8e7e4c10, transcript).
- **WriteSemantics stays a four-value enum** (sync, staged_async, blocking_async, read_only) serving four consumers: capability advertisement, operator narrowing (write_semantics_allowed), per-claim realization from Open, and per-value conformance contracts — "fix it. fix the concept doc, too. fix it all." (2026-06-19, a02fe167, transcript).
- **Producer errors cross the HTTP boundary intact**: error class + message in the body, 422 producer-rejected-input vs 502 producer-failed vs 500 rimsky-internal (2026-06-11, last-mile-stability, artifact).
- **Producer declared_error_classes**: producers may declare an error-class vocabulary in capabilities (stored in discovery cache); template validator range-checks error_types keys against the union of executor classes, acquire/* synthetic family, and reachable producers' classes — advisory warning, never hard rejection, for unattributable keys; policy lookup falls back exact-class → acquire/* → unknown-class default (2026-06-11, last-mile-stability, artifact).
- **abandonOpenedClaim single audited site**: all producer.Abandon calls on opened claims route through one shared helper that builds claim_id and fires Producer.Abandon only, never touching the rimsky_claim_handle row (2026-05-11, log-convergence, artifact-only).
- **Host-agent / proxy contract**: proxy fronts ClaimProducer advertising the full write-semantics envelope (it is pure transport; per-claim realized semantics come from each spawned producer's Open); it maintains a claim-route map recorded at Open so Commit/Abandon/Release (claim_id-only on the wire) route back; late-binding is a Registry GetWithContext method with functional options; terminal resolution keeps bare Get (parent claim already bound at acquire); six proxy error classes ride the existing error_types chain (2026-05-24, host-agent-and-proxy, artifact).
- **Zero-config local orchestration**: an ad-hoc template runs through the all-in-one process with no rimsky.yml, no docker, no external services, driving to terminal against real bundled services doing real work — a stub or canned reply is a falsifier (2026-07-03, 8a8539a4, transcript).
- **In-proc registry semantics**: registration binds name → handler + explicit mix-in advertisement + capabilities as construction data; clients satisfy the same consumer-facing interfaces as gRPC peers with envelope enforcement to parity; calling an unadvertised mix-in errors naming producer and verb; unconfigured bundled services skip with a log line, invalid config aborts boot naming the handler, config-declared names beat bundled handlers, bundled discovery entries are static (2026-07-03, 3f71f90a, transcript).
- **Computed-scope pattern is supported**: Open may compute a requested view returned as payload bytes hoisted via {{claim.<alias>.payload.<field>}}; address bytes may carry a producer-private data-plane endpoint + one-time token (2026-05-19, crimefinder, artifact-only).
- **External consumers touch only public protocol contracts** (executor protocol, claim-producer protocol, control-api), never rimsky source (2026-05-19, crimefinder, artifact).
- **Claim-producer observability**: fetch full producer-side claim detail, stream live claim-state changes, paginate the producer's claim inventory, render producer-declared admin views — all backed by real producer state (2026-06-08, corpus-bootstrap, artifact-only).
- **Big-data write-channel pattern**: genuinely huge outputs stay on the claim-producer write channel (acquire a write claim, stream through it, emit a small attributes_delta with the handle) — deliberately not blob spill (2026-05-08, platform-extensions-for-agent-consumers, artifact-only).
- **"Loop until drained" natively expressible**: self-invalidate on complete + on_acquire_unavailable pass lands the node at last_outcome=passed and the instance terminals cleanly with no dashboard failure (2026-05-05, reactive-loops-and-lifecycle-handlers, artifact-only).

## Intentional absences

- **release_to_head** — dropped entirely, no replacement (unused, LIFO infinite-loop footgun); a future LIFO need gets its own spec (2026-05-06, fs-store-pick-policy-action-vocabulary).
- **Old pick-policy vocabulary and field names** (release_to_back / release_to_head / delete; on_commit_default / on_give_up_default) and **sync_strategy: on_sweep** — dropped with no compat shim; configs fail at config-load (2026-05-06, fs-store-pick-policy-action-vocabulary).
- **Producer-side intent gating** (Commit/Abandon branching on claim intent, per-sub-claim write-back semantics) — explicitly declined as architecturally incorrect work at the wrong layer; bundled stores intentionally do not differentiate by intent after Open (2026-06-18, 8e7e4c10, transcript).
- **Generalizing SplitScope beyond fan_out** (partition-selector template surface, AcquireSubClaims for non-fan-out) — rejected as not-a-defect; single-partition access is already expressible via the producer's selector grammar with substitution (2026-06-19, a02fe167, transcript, user).
- **Message-tied fan-out** (trigger.message, message-created partitions) — "that makes zero sense"; nothing may link fan-out to messages (2026-06-18, 9fb55f08, transcript, user).
- **Rimsky-enforced aggregator vocabulary** — aggregator names are producer-internal, interpreted at Commit; retired as a rimsky concept (2026-05-15, data-platform-extensions; reaffirmed as fan-out invariant 2026-06-22, 10cf843b, transcript).
- **Per-partition attribute-writeback merge onto the fan-out parent** — torn out by decision; fan-out nodes discard partition output attributes; use producer_metadata / data-processing / assets (2026-06-22, 10cf843b, transcript).
- **Object-store (S3/GCS) bundled store** — deferred past v1 (flagged v1.1); when it lands it is a new bundled store reusing the expand-folder shape, not a new partition_request shape (2026-06-18, 9fb55f08, transcript).
- **Per-call pick-action overrides on the commit RPC, per-instance/per-frame queue isolation** — out of scope by design; the policy decides, drain passes are store-global per policy (2026-05-06, fs-store-pick-policy-action-vocabulary).
- **Lifecycle hooks on the producer protocol** — split into the standalone LifecycleSubscriber service (2026-05-04, service-protocol-contract).
- **Bidirectional peer-initiated events; store-internal queue semantics on the wire** — out of protocol scope (2026-05-04, service-protocol-contract).
- **Claim-producers as read-only prompt-context stores; domain stores in rimsky.yml** — documented anti-patterns; claims coordinate writes (2026-05-08, platform-extensions-for-agent-consumers).
- **Per-verb deadline on terminal producer calls (Commit/Abandon)** — a 30-60s context timeout in ResolveClaimHandleTerminal was recommended but deliberately not landed; one hung producer can still block the supervisor's terminal release path (2026-05-04, layer-crystallization-plan-notes, artifact-only; no later entry lands or retires it).
- **Reactive-loops deferrals** — predicate language for handler conditions, frame-end predicate hooks, hard frame timeouts with teeth, per-claim on_unavailable overrides, storage-less workflow-control producer: all explicitly future/out of scope (2026-05-05, reactive-loops-and-lifecycle-handlers).
- **Sensors and lifecycle-subscribers in the in-proc bundling scope** — dropped; only producers and executors bundle in-proc (2026-07-03, 8a8539a4, transcript, user).
- **CLI-against-real-server acceptance coverage** — declared thin pass-through, deliberately unproven (2026-06-02, acceptance-coverage-recovery).
- **Archived claim-producer author guide** — deleted; described a verb-firing model two redesigns old and had already caused published drift (2026-06-11, last-mile-stability).
