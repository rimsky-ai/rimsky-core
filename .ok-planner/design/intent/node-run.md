## Net position

- **No empty-claimant guard bypass** (user ruling 2026-07-17): the queue-level claimed_by guard on release/remove verbs is unconditional — the shipped `""`-sentinel carve-out (enshrined only by a conformance test, blessed by no design artifact) is rejected because a bug that loses the claimant value would silently disarm the very guard meant to catch it. Administrative callers (pure-cascade settle, parked-row sweep) move to an explicitly-named force variant; the conformance suite proves strictness plus the explicit variant instead of the sentinel; the caller-less queue Complete verb is dead code to delete. Queued fix-code.

- A node-run is one execution of one node within a RunScope (and thereby a frame). Frame ⊃ run-scope ⊃ node-run is the hierarchy; a run-scope is one graph instantiation (main/root, sub-graph, fan-out partition), never "one execution of one node" (2026-05-12 artifact; corrected 2026-06-19, 08d65bfe, transcript).
- The table is `rimsky_node_runs` (plural); the Go row struct is `NodeRunRow` (singular). The identifier is `node_run_id` / `NodeRunID` everywhere — bare `run_id`, `RunID`, and `DispatchID` are retired names swept repo-wide (2026-07-05, 3f71f90a: "code base should use 'node_run_id' not 'run_id'. nobody knows what a 'run' is.").
- Node-runs follow a **seven-state machine**: pending, stale, running, held, parked, fresh, failed. fresh and failed are settled states with no outgoing edges. The legacy phase axis (pending/active/held/completed) and its column are retired entirely; state × phase virtual states are collapsed into the single state column (2026-06-20, 8a3b8c19).
- **Only node-runs have state.** Nodes carry no runtime state whatsoever — no lifecycle phase, no retry counter, no policy cursor, no frame engagement. "Fresh" must never be synthesized for a node with no runs; the only honest operator-facing node state is a categorical NodeRunSummary of run counts (2026-06-20/21, 10cf843b + 8a3b8c19).
- **In-flight seal**: cascade never mutates an in-flight run (pending, stale, running, held, parked) — it queues a new pending row. "A node never gets re-invalidated, no matter what" — parked or running (2026-06-20, 8a3b8c19).
- The queue is implicit: any number of pending runs may coexist per (node, run-scope); a not-yet-dispatched run is "just a queue of one" with identical rules for every creation path. At most one stale-or-active run per (node, run-scope): pending→stale transitions are serialized per (node, run-scope) (first line of defense) with the dispatcher's claim-time NOT EXISTS as second. The one-active rule is per node within a run-scope, not per run-scope (2026-06-20 + 2026-06-30, 8a8539a4).
- Attributes exist **exclusively on node_run rows** — no standalone per-node or source attribute store. The bag is built at the pending→stale transition (deep-copied carry-forward from the receiver's prior run + overlay from drained wait-set rows + cascade-mode rule), then claim substitution at stale→running. Exactly two substitution rounds, one uniform code path; the gate-eval bag IS the dispatch bag (2026-06-21, 10cf843b; 2026-07-13, 3f71f90a).
- A queued run's view of its upstreams is pinned at enqueue time by upstream **run identity** (wait-set sender_run_id), not by copied values; substituted values come from those pinned runs once they settle. Sequenced cascade mode preserves per-round snapshots (v1, v2, v3 — not all-newest) (2026-07-13, 3f71f90a).
- **Retry is in-place**: a loop on the same node_run row, same claims, same bag — for executor errors and claim-acquisition errors alike, through one unified policy path. A single node-level max_retries (+ retry_backoff) spans all error classes; each class maps to one action; undeclared classes default give_up; only give_up settles the run failed. A held run never receives an error — errors occur while running (2026-06-22, 10cf843b).
- creation_reason is the closed set {cascade, operator_invalidate, recalculate, message_delivery}; sequence is monotonic per (node_id, run_scope_id) (2026-06-21/23, 10cf843b).
- **Held** is a post-executor state: a run is held while it participates in any unresolved claim_handle (acquirer or co-holder); membership derives from existing claim tables, no new column. Cascade past a held node is deferred until the claim resolves; each holder leaves held only when its full claim portfolio resolves — held→fresh iff all committed, held→failed if any abandoned (poison rule) (2026-06-20, 8a3b8c19).
- **Parked** is strictly intra-frame and a resume state: exactly two exits — time-wake on its own deadline (parked→stale, bag preserved) and watchdog timeout (parked→failed). Never woken by messages, cascade events, or operator actions; /v1/callback rejects parked runs. Resume replays the persisted dispatch-time bag; nothing in the run is updated on resume (2026-06-15, 91ec93d1; 2026-06-19 + 2026-06-22, transcript).
- Await-async keeps the run **running**; async_ack_id + async_ack_registered_at persist on the run row (registry survives supervisor restart); effective max_quiet_period / max_runtime are denormalized onto the row at ack registration; a callback is honored iff the run is in the awaiting state at processing time, checked atomically in the mutation tx, else ack-but-noop (2026-05-22 artifact; 2026-06-17, b31002b8).
- Settled rows (fresh/failed) persist — deleted only by run-scope GC / trace retention (frame + its runs reaped as one unit under trailing-window OR frame-count cap; in-flight never reaped) (2026-06-21, 10cf843b; 2026-06-03 artifact).
- Frame status (running/completed/failed) is a pure function of the frame's node_run states, derived at read time — the persisted frame state column is retired; a frame cannot fail independently of its runs (2026-07-05/06, 3f71f90a).
- Frames are perfectly isolated: node_run state must be structurally unable to leak across frames; at frame start, runs have only default attribute values; messages are the sole state transport (2026-07-05, 3f71f90a).
- Graph execution and cascade order are deterministic and structural, never time-based; in-frame loops are fully supported — there is no "one node-run per node per frame" rule (2026-06-24 + 2026-07-13, transcript).
- State transitions target a specific node_run_id (UpdateState by run id); ambient (node_id, run_scope_id) lookups, state-priority sorts, and cross-frame fallbacks are deleted (2026-07-05, 3f71f90a).
- Executor scratch (opaque bytes) persists on the run and returns verbatim on the next dispatch, carried across in-place retry iterations; rimsky never inspects it (2026-06-14 + 2026-06-22, transcript).
- Vocabulary: node_runs *emit* events and *send* messages; nodes do not emit messages (2026-07-05, 3f71f90a).

## Required behaviors (open promises)

- Seven-state model (pending, stale, running, held, parked, fresh, failed) with creation_reason enum and per-(node_id, run_scope_id) monotonic sequence; phase axis fully retired (2026-06-20, 8a3b8c19, transcript).
- Cascade walker rule (a): cascades accumulate into the receiver's latest pending run with per-sender-node granularity, creating a new pending only when the sender node is already covered; walker never mutates in-flight runs; concurrent walkers serialized by advisory lock per (node, scope, frame) (2026-06-20, 8a3b8c19, transcript).
- Gate evaluator runs synchronously in the terminal-handler tx at wait-set drain: pending→stale only when the wait-set is fully drained and no subscribed upstream has an in-flight run; builds the dispatch input bag (carry-forward + overlay), then applies cascade-mode (2026-06-20, 8a3b8c19, transcript). Refined 2026-06-30: pending→stale serialized per (node, run-scope) — at most one stale-or-active at a time.
- Dispatcher serialization gate covers running/held/parked at claim time; claim CAS split from state transition (claiming does not change state; stale→running fires only after verify-before-run); dispatcher loads the gate-eval-persisted bag by run id — no dispatch-time attribute re-read (2026-06-20, 8a3b8c19, transcript).
- Non-cascade paths (operator_invalidate, recalculate, message_delivery) create runs direct-to-stale with the carry-forward bag built at creation, immune to mode rules, never walker targets; operator invalidate does not jump the queue (2026-06-20/22, transcript).
- In-place retry: executor and claim-acquisition errors retry on the same row via applyErrorPolicy; retry-after-error re-dispatch receives the prior attempt's scratch verbatim (terminal event's scratch copied into the acquisition); policy cursor (retry_counter) persisted on the run row so cap accounting survives supervisor crashes (2026-06-22, 10cf843b, transcript: "'retry' is a loop... no workarounds").
- Both an errored original run and its retry-completed successor carry settling signals — a nil settling signal on the errored run is a bug (2026-06-21, 21306ffe, transcript).
- Persistent async-callback registry: async_ack_id + registered_at on the run row with unique partial index, registration atomic with the transient/await_async signal, so async work survives supervisor restart (2026-06-17, b31002b8, transcript).
- Three orthogonal per-node dispatch deadlines (sync_rpc_deadline default 30s; max_quiet_period default 0=disabled; max_runtime default 0=disabled, wins over quiet-period) with effective values denormalized onto the run row at RegisterAsyncAck so the sweep is a single indexed scan (2026-06-17, b31002b8, transcript: "right. fix everything. implement every missing thing. we want 100%.").
- Opaque executor scratch: attach to terminal event, persisted on the run (inline/handle/handle_backend triple, blob spill), handed back verbatim on next ExecuteRequest; mid-dispatch scratch write is an HTTP callback route on the executor protocol (2026-06-14, 752fe200, transcript).
- Attribute pipeline exactly: carry forward (or seed on first run) → substitutions → schema-validate → execute → schema-validate results. The dispatch-phase validation gate (invariant 12) must be wired on the runtime dispatch path — adjudicated fix-code 2026-07-13 (findings 111/128) after the June-21 message-receiver refactor silently dropped it (2026-06-15, c60b550a + 2026-07-13, 3f71f90a, transcript).
- Carry-forward: the new run gets a complete deep copy of the prior dispatch's bag, then re-substitution against the new dispatch's params/deps (2026-06-30, 8a8539a4, transcript).
- Sequenced mode per-round values: populateSubscribedSenderDeps resolves each round-driving sender's value from its pinned wait-set sender_run_id, falling back to most-recent-settled only for non-driving subscribed senders; proof asserts per-round values. Committed 2d4952e4 (2026-07-13, 3f71f90a, transcript).
- Four cascade gate fixes stand: blocked receivers re-evaluated when blockers settle (reevalDownstreamReceiverGates); cascade-mode drop check before same-node serialization check; most-recent drops a pending whenever a later cascade peer exists; idempotent comparison resolves a still-pending prior peer's bag on demand (2026-07-05, 3f71f90a, transcript).
- attribute/<key>/changed signals are diff-based (prior run's data vs final settled values; empty-bag baseline for a scope's first run so initial values wake subscribers) and emission is uniform across every settle path — no per-path special casing; audit-log emission driven by the same diff (2026-06-22, 10cf843b, transcript).
- Held mechanism (option B): claim resolution walks all holders via CheckAndFireResolution; each transition fires that run's own deferred cascade to non-members; gate evaluator skips held upstreams co-member of the receiver's held subgraph (2026-06-20, 8a3b8c19, transcript).
- Fan-out: parent and children are node_runs of the same node_id (parent in parent scope, one per partition scope); role derived from the scope, not a kind field; guard prevents re-fan-out in non-main scopes; parent transitions running→held via dedicated reason fanout_dispatched and resolves through the same auto-terminal walker (2026-06-19 + 2026-06-22, transcript).
- Message delivery: validate body against schema, create a run directly in stale with creation_reason message_delivery, populate bag from the body, settle via the pure_cascade path firing standard terminal/success cascade (2026-06-22, 10cf843b, transcript). Messages always and only start frames; a message landing in a running frame is a bug (2026-06-30, 8a8539a4).
- Frame-end predicates: "unresolved work" predicates count parked (and pending counts as in-flight for frame-end); "dispatchable now" predicates do not (2026-06-03 artifact + 2026-06-20 transcript).
- Settled rows persist for run summaries, latest-run lookup, new-run-targets-settled-run invariant, and forensics; deletion only via scope GC (2026-06-21, 10cf843b, transcript).
- Control API surfaces the latest terminal run's settling_signal_type on node detail GET and instance-nodes LIST; CLI node summary uses it as the failure reason (2026-06-22, 10cf843b, transcript).
- Operator re-run is idempotent debug tooling: meaningful only when all the node's runs are settled; "run again", never "schedule N future runs" (2026-06-30, 8a8539a4, transcript).
- Force-terminate: a wedged running run reaches failed via the real lifecycle path under reason instance_killed (running→failed, parked→failed; pending→failed with bag unbuilt), main run-scope closes, terminated_at set, DELETE allowed only then — proven full-stack, not with fakes (2026-05-28 + 2026-06-06 artifacts; 2026-06-20 transcript).
- The claude-agent executor emits the NodeRunID (dispatch id) as binding_id — never the Claude session id (2026-07-07, 3f71f90a, transcript).
- compose run default progress output is per-node lifecycle: one line per node-run terminal (timestamp, node ref, outcome, brief failure reason); --quiet/--verbose/--json variants (2026-06-13, 65667e33, transcript).
- Seven-state redesign design artifacts: seven stories (cascade-defers-during-flight, held-commit-cascades-success, held-abandon-cascades-abandoned, operator-invalidate-queues-during-flight, most-recent-coalesces-cascades, sequenced-preserves-cascade-rounds, idempotent-mode-dedupes), each behavior scenario-test-guarded (2026-06-20, 8a3b8c19, transcript). Note 2026-07-03: most-recent-coalesces-cascades as then written conflated message-queue coalesce with the node_run queue and needed rewrite; the other cascade-mode stories stand, with proofs driving intra-frame rounds (self-subscription/loop nodes), not messages (2026-07-05, 3f71f90a).
- Cascade-mode proofs cover: in-flight seal, most-recent coalesce, sequenced ordering, idempotent dedupe, diff-gate suppression — all intra-frame (2026-07-05, 3f71f90a, transcript).
- Breakpoint hit snapshot includes a projection of the node-run row plus held-claims and open wait-set summaries (2026-05-24, instance-debugger, artifact-only).
- Queue-depth metric named rimsky_node_runs_pending (row-count gauge tracks the table rename); rimsky_dispatches_total / rimsky_dispatch_latency_seconds keep the event verb; metric names never renamed silently (2026-05-13, nomenclature-resolution, artifact-only).

## Conflicts needing human ruling
