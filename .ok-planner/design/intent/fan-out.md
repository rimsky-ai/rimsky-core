# Intent Dossier: fan-out

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner
history artifacts (2026-05-04..2026-06-11). Transcript tier outranks artifact tier;
later intent supersedes earlier. Part of the drift-remediation intent ledger.

## Net position

- **Fan-out is literally an operation that clones the calling node** N times — one clone per partition, each in its own child run-scope. It has nothing to do with sub-graph; the cloned node can itself delegate, but that is orthogonal. Fan-out and sub-graph delegation are **distinct mechanisms, not variants of one primitive** (2026-06-23, 10cf843b, transcript: "fan-out is literally just an operation that clones a node. nothing to do with sub-graph." — supersedes the 2026-06-11 child-execution-unification framing "delegation is fan-out with N=1").
- Two settlement modes, implicit in the invocation pattern: carry (delegation, no policy) and **aggregate (fan-out)** with the four-value user-configurable aggregation policy **strict | threshold | best_effort | first**; strict is default and carries the cancel_siblings: true modifier. Settle is intentionally split (SettleFromDelegate / SettleFromFanoutChild, typed inputs, no tagged union); only dispatch shares a thin helper (2026-06-19 + 2026-06-23, 08d65bfe + 10cf843b, transcript).
- **Fan-out is a claim operation**: declared on the parent node via a fan_out: block naming one of its claims and carrying a partition_request; the producer's SplitScope returns N sub-scope descriptors; rimsky opens the parent claim plus N sub-claim handles atomically (sub-claim atomicity, blessed invariant 10) and dispatches N child runs. There is no separate fan-out consumer node (2026-05-19, crimefinder, artifact).
- **The producer decides the partition**: partition_request is opaque bytes whose schema is producer-specific; the producer returns a standardized iterator format that is always, by definition, a list, and all the fan-out node does is iterate it (SplitScopeRequest opaque bytes → SplitScopeResponse list of SubScopeDescriptors) (2026-06-18, 9fb55f08, transcript).
- **partition_request is vanilla substitution** like any other field: it resolves through the standard ResolveContext identical to executor-attribute dispatch — upstream node attributes, claim payloads, instance params, typed messages, static literals all work uniformly (2026-06-18, 9fb55f08, transcript — overturning the messaging consolidation's narrow message-only context).
- **Fan-out is completely orthogonal to messages**: a message payload may substitute into a partition_request like any other source, but nothing may link the two mechanisms; fan-outs must create and resolve within a frame on any supporting producer. There is no trigger.message; {{messages.<type>.<field>}} (sugar for nodes) is the only way messages enter substitution (2026-06-18, 9fb55f08, transcript: "fan-out is a request to a producer. it has *nothing* to do with messages").
- **Parent and children are node_runs of the same node_id**: one run in the parent RunScope (does the SplitScope acquisition and aggregates) and one run per fan-out-partition RunScope (each holds one sub-claim and executes the node's executor). Role is derived from the RunScope a run lives in, not a kind field; a guard skips fan-out logic for runs acquired in any non-main RunScope so children never re-fan-out (2026-06-19, 8a3b8c19, transcript).
- Fan-out does not require a sub-graph: a partition RunScope is a single-node execution context running only the calling node's own dispatch; a fan-out parent whose dispatch is delegate produces a nested sub-graph RunScope inside each partition RunScope (2026-06-19, 8a3b8c19, transcript). The three RunScope kinds (main, sub-graph, fan-out partition) stand — unification declined (2026-06-19, 8a3b8c19, transcript).
- The fan-out parent has no executor dispatch of its own; after dispatching its partition children it transitions running → held with the dedicated transition reason **fanout_dispatched** and releases its queue claim; its resolution unifies onto the same auto-terminal walker as co-holders. A fan-out/aggregation parent can never park — only an executor can park (2026-06-22 + 2026-06-24, 10cf843b + 8a8539a4, transcript).
- **Fan-out does not aggregate child attributes.** Per-partition executor writebacks never reach the parent's bag; the parent's attributes are its own dispatch-time bag only; downstream nodes should not wait on fan-out parent attributes. Sanctioned output channels: producer_metadata on the producer's Commit, the data-processing aggregator mix-in (aggregation inside the producer), and the asset surface keyed by the handle's version_id — written into the concept as an invariant so future agents don't re-invent the merge (2026-06-19..22, 08d65bfe + 10cf843b, transcript).
- Fan-in happens at the **claim-handle level** per the author-chosen aggregation policy: strict (any abandon → parent abandons), threshold (abandons tolerated up to max_failures), best_effort (any commit → parent commits), first (first commit wins, remaining in-flight children cancelled); cancel_siblings proactively force-abandons in-flight siblings under strict without changing the parent's outcome (2026-06-19, 08d65bfe, transcript).
- **A sub-claim is a claim** — parity where it earns its keep: SubScopeDescriptor carries address and payload fields (non-empty address bytes must be JSON-valid, rejected with a clean precondition error); sub-claims inherit realized_write_semantics and **intent** from the parent at insert time (the hardcoded "rw" was a bug); payload persists on ALL claim rows for a uniform code path; root claims do NOT gain partition_key or producer_metadata (2026-06-18, 9fb55f08 + 8e7e4c10, transcript).
- Both bundled stores support SplitScope and advertise supports_split_scope: filesystem dispatches on three partition_request shapes ({"list": [...]}, {"batch_pick": {"max_items": K}}, {"expand_folder": {filter, depth, kind}}; unknown → InvalidArgument), postgres on two ({"list": [...]}, {"partition_policy": "@<name>", "params": {...}} with operator-pre-declared policies — zero SQL in the authoring surface). The {"list": [...]} pass-through unmarshal lives in lib/services/stores/shared/ as the de facto cross-producer shape (2026-06-18/19, 9fb55f08 + 8e7e4c10, transcript).
- Registration gates: fan_out: against a producer not advertising supports_split_scope is rejected; the conformance suite covers the cross-producer contract only (advertisement rejection, list round-trip, SubScopeDescriptor wire shape incl. address/payload); substrate-native shapes are tested in each store's own suite (2026-05-15 artifact + 2026-06-18, 9fb55f08, transcript).
- **Backfill is not a primitive**: the backfill concept, dedicated control-API endpoints, CLI subcommands, and backfill_operation_id lineage column all drop. A backfill is just posting a message whose body carries a partition override that a fan-out node reads via substitution; cancel generalizes to cancel-instance-run (2026-06-14, bfc9febb, transcript).
- Zero sub-scopes from SplitScope → the runner falls through and dispatches the parent as a regular leaf with no sub-claim; executors treat the absent sub-claim address as no-op success (2026-05-19, crimefinder, artifact) (artifact-only).
- Across a holding boundary the fan-out parent is **signal-only**: non-members subscribe to state signals (terminal/success, terminal/error/abandoned) and get no attribute payload; child-produced data must be materialized by the claim's commit into an externally queryable store or written to a sibling regular node. Pass-through propagation of the parent's own substituted attribute values still cascades to subscribers when the value actually changes (2026-06-22/23, 10cf843b, transcript).
- Lineage means attribute lineage; fan-out parents are pass-through nodes that cannot mutate their own attributes and produce no leaf_run lineage artifact by design (fan-out parents and pure-cascade nodes are the only such cases — sub-graph exits are NOT pass-through) (2026-06-23, 10cf843b, transcript).
- Aggregate-parent settlement signals carry an empty attributes_delta (a synthetic parent settlement is not a dispatch); the unreachable parked branch in parentSettlementSignal is replaced with a panic so aggregated-park must be a deliberate future decision (2026-06-24, 8a8539a4, transcript).
- New RunScopes (including fan-out partitions) start attribute hydration from schema defaults with no carried state; carry-forward applies only to successive runs within one scope (2026-06-14, 752fe200, transcript).
- by_match child_key matcher targets a specific partition by identity; empty-string child_key is rejected at the grammar level; ordinal-shaped keys (nth_child, partition_index, …) are loudly rejected — partitions are addressed by identity, never execution order (2026-05-21 + 2026-05-24, artifacts).
- Fan-out child aggregation error leaves are terminal/error/aggregate/{strict,threshold,first}_failed, passing through the generic terminal/error/* prefix by design (2026-05-23, signal-taxonomy, artifact) (artifact-only).

## Required behaviors (open promises)

- fan_out: block on the parent node driving SplitScope → atomic parent-claim + N sub-claim open → N concurrent child runs → parent settles only after all children reach terminal with the aggregate outcome (2026-05-19 + 2026-06-08, artifacts; alive throughout the transcript record).
- The seven locked fan-out stories (2026-06-18, 9fb55f08, transcript): fs-fanout-list-array, fs-fanout-expand-folder, pg-fanout-list-array (no custom producer needed; each child sees its {{child.partition_key}} and per-item payload); fanout-any-substitution-source; messages-as-nodes-substitution (messages.foo ≡ nodes.foo, differing only in validation); sub-claim-payload-substitution ({{claim.<alias>.payload}} resolves for children exactly as for regular claims); fanout-intent-inheritance (intent: r honored on children end-to-end — no producer write-back for read-only, write-back present for rw). Bundled-store support + demos reported closed out (2026-06-19, 8e7e4c10, transcript).
- Both bundled stores advertise supports_split_scope: true, as concept:fan-out's invariant requires for registration to accept fan_out: (2026-06-18, 9fb55f08, transcript: "yes").
- SubScopeDescriptor address + payload threaded through Go types, the runtime peer bridge, and the sub-claim insert; non-JSON address bytes rejected with a clean precondition error (2026-06-19, 8e7e4c10, transcript).
- Sub-claim rows' persisted intent column matches the parent's (proven via direct DB assertion in the rewritten demo) (2026-06-18/19, 8e7e4c10, transcript).
- batch_pick against a direct-address parent claim (no pick policy → no implicit queue) is rejected unless an explicit policy field names the queue (2026-06-19, 8e7e4c10, transcript).
- Parent held via fanout_dispatched (not handler_held) with queue claim released; resolution via the shared auto-terminal walker (2026-06-22, 10cf843b, transcript).
- Guard: runs acquired in a non-main RunScope never fan out again (2026-06-19, 8a3b8c19, transcript; the missing guard's infinite SplitScope recursion is documented drift, 2026-05-22 artifact).
- ScopesConflict consulted during acquisition **including the fan-out sub-claim path** (invariant 4b) when the producer advertises SupportsScopesConflict — flagged as having zero callers at the time (2026-06-06 + 2026-06-08, artifacts) (artifact-only).
- Conformance SplitScope coverage: non-advertising rejection, {"list": [...]} round-trip (any advertising producer must accept it), SubScopeDescriptor wire shape (2026-06-18, 9fb55f08, transcript).
- Data-processing mix-in on fan-out: BeginCandidate per sub-partition, CommitCandidate on leaf success (metadata surfacing in the parent writeback), AbandonCandidate + GC on leaf failure (2026-06-08, corpus-bootstrap, artifact) (artifact-only).
- Base-protocol Commit response persisted: version_id onto the claim-handle row, producer_metadata surfaced in the fan-out parent's writeback (2026-06-11, last-mile-stability, artifact) (artifact-only).
- Pass-through propagation: in A → B → C with B a pass-through (including a fan-out parent), C subscribing to B's attribute changes is invalidated when the passed-through value actually changes (2026-06-22, 10cf843b, transcript).

## Intentional absences

- **Fan-in attribute merging** — the invented mergeChildAttributesIntoHolder first-write-wins merge and its per-key attribute/<key>/changed emit loop were removed entirely; all partitions share one attribute schema, so per-key merging structurally collides on every key and no reasonable merge rule or use case exists (2026-06-22, 10cf843b, transcript). Threading small per-partition values to the parent is future feature work, not a gap (2026-06-19, 08d65bfe, transcript).
- **Direct references to a fan-out child** (e.g. as a substitution source across the run-scope boundary) — "not supported and won't be" (2026-06-23, 10cf843b, transcript).
- **Backfill as a first-class concept** — endpoints, CLI verbs, lineage column all dropped (2026-06-14, bfc9febb, transcript).
- **trigger.message and the {{trigger.message.payload}} substitution channel** — TD-legacy-trigger-message-retirement: the directive, the TriggerMessagePayload/TriggerMessageType ResolveContext fields, and triggerMessageForFrame are removed; legacy templates fail registration with the standard unknown-directive error (2026-06-18, 9fb55f08, transcript).
- **Generalizing SplitScope beyond fan_out** (partition-selector template surface) — rejected as not-a-defect; fan-out is the only real consumer of atomic multi-sub-claim acquisition; single-partition access is expressible via the producer's selector grammar (2026-06-19, a02fe167, transcript).
- **Unifying the fan-out-partition RunScope kind into sub-graph** — declined; three kinds stand (2026-06-19, 8a3b8c19, transcript: "we don't need to unify.").
- **Per-emission event-payload fan-out** ({{trigger.event.payload}}) — named events don't fan out per-emission (wait-set ON CONFLICT + shared visited set collapse N emissions to one dispatch); true per-item fan-out is producer split-scope (2026-05-29, console-upstream-auth, artifact).
- **carry_verbatim as an author-facing aggregation policy** — removed from the enum; a runtime routing tag, not part of the four-value family (2026-06-19, 08d65bfe, transcript).
- **Object-store (S3/GCS) bundled store** — deferred past v1 (v1.1); when it lands it is a new bundled store, not a different partition_request shape (2026-06-18, 9fb55f08, transcript).
- **Ordinal matcher keys and expression matcher values** — loudly rejected at instance-create; identity-only partition addressing (2026-05-21, matcher-overlay, artifact).
- **A lenient substitution marker ({{X?}}) on a source known never to resolve** (the lineage test patch) — rejected; fix the design question, don't paper over it (2026-06-22, 10cf843b, transcript).
- V1-era deferrals still standing unless separately promoted: generator-style fan-out from executor-emitted iterables (fan_out.over), dynamic/multi-dimensional partition types, cancellation-of-in-flight-frame primitives (2026-05-15, data-platform-extensions, artifact).

## Corrections and restorations (drift-fight record)

- **Fan-out tied to messages was ruled a remnant, never intended**: "the concept of fan-out was inexplicably tied to messages, and 'trigger.message' had somehow persisted as a remnant" — general capabilities must not be tied to a single trigger mechanism; the retirement, the substitution widening, and the concept-doc mutation were folded into the 2026-06-18 bundled-stores fan-out spec (2026-06-18, 9fb55f08 + 8a3b8c19, transcript).
- **The child-execution unification over-merged**: the 2026-06-11 "delegation is fan-out with N=1" decision and unified SettleChildren were reversed — the fan-in shapes differ, settle split back into two named paths, concept docs updated to two settlement modes (2026-06-19..23, 08d65bfe + 8a3b8c19 + 10cf843b, transcript).
- **Invented fan-in attribute merging removed** as drift (mergeChildAttributesIntoHolder; see Intentional absences) and the fan-out concept given an invariant against re-inventing it (2026-06-22, 10cf843b, transcript).
- **A lineage test asserted a non-feature** (substitution-ref lineage from a fan-out parent) and was deleted; pass-through nodes produce no lineage artifact (2026-06-23, 10cf843b, transcript).
- **"Fan-out is NOT subgraphs" corrected to "fan-out is distinct from subgraph"**: run-scope exists exclusively for sub-graphs and recursion; a fan-out node can also be (and most often will be) a subgraph — composition, not opposition (2026-06-18, 9fb55f08, transcript).
- **Backfill overrides silently ignored in production**: fan-out acquisition passed template partition_request bytes verbatim without substitution, so every backfill processed the template default while returning 201 — fixed by substitution-aware acquisition (2026-05-29, console-upstream-auth, artifact); regression pinned only at unit level, no full-stack override-to-SplitScope test (2026-05-29, divergences, artifact).
- **{{child.partition_key}} never resolved** (ResolveContext.ChildPartitionKey never set by the dispatch context builder) — fixed (2026-06-02, rimsky-core-remediation, artifact).
- **candidate_handle never reached the leaf and DataProcessing producers were never dialed** — registry threaded through runtime config/run-args/callback server so BeginCandidate actually runs (2026-06-02, rimsky-core-remediation, artifact).
- **Sub-claim node_run_id pointed at the parent run**, so the fanout_partition scope-closure walk matched no partition scope — repointed to the child run (2026-06-02, rimsky-core-remediation, artifact).
- **The 2026-05-22 reshape's motivating bug class**: children re-firing SplitScope in infinite recursion, half-built entry absorption, and 30+ ambiguous WHERE node_id callsites — root cause was fan-out bolted onto a non-fan-out node_run shape; fixed structurally by first-class run scopes (2026-05-22, fan-out-safety-scope-first, artifact).
- **Hardcoded sub-claim intent "rw"** ruled a bug, not a design choice — inherit from parent (2026-06-18, 9fb55f08, transcript).
- **Known coverage shortfalls recorded**: child_key matcher routing e2e never delivered (harness couldn't drive a fan-out producer; unit-level only) (2026-05-21, divergences, artifact); the planned concurrent fan-out / Z-pattern scenarios scoped down (2026-05-20, divergences, artifact). The 2026-05-22 spec's eight full-lifecycle scenarios were the corrective standard.
- **YAML keys cancel_siblings:/max_failures: silently dropped** (json-only tags) — yaml: tags added; bot PR #10 not merged (2026-06-02, rimsky-core-remediation, artifact).
- **The fan-out docs' "| default: <x>" fallback form was a doc bug** — the grammar is `<directive> | <literal>`, no default: keyword (2026-05-29, console-upstream-auth, artifact).

## Superseded / historical

- "Delegation is fan-out with N=1" / unified DispatchChildren+SettleChildren (2026-06-11, artifact) → distinct mechanisms, split settle (2026-06-23, transcript).
- Bundled-store SplitScope rejected as "the shipped concept's documented behavior" (2026-06-06, artifact) → ruled a v1 credibility hole; both bundled stores must support it (2026-06-18, 9fb55f08, transcript) — a clean transcript-outranks-artifact precedent.
- Backfill as message-convention-with-endpoints (partition_request_override, backfill_operation_id lineage, create/list/show/partitions/cancel; 2026-05-15, artifact) → collapsed entirely (2026-06-14, transcript).
- Message-tied / narrow (Params+Claim+TriggerMessagePayload, Deps-omitting) partition_request substitution context → vanilla substitution through the standard ResolveContext (2026-06-18, transcript).
- (parent_run_id, child_key) inline disambiguation on node_runs, GetByParentChildKey → first-class rimsky_run_scopes + two-step lookup (2026-05-22, artifact); the per-instance main RunScope from that spec later gave way to frame-owned root scopes (2026-06-30, transcript, instance-side).
- Aggregation-policy snapshot onto the parent run row with rule-table state propagation and last-child-order sensitivity (2026-05-15/16, artifacts) → counters-on-parent, then the claim-handle-level aggregate settle of the current model.
- "Fan-out children reuse the parent's node row so per-node userdata reaches children verbatim" (2026-05-19, artifact) — the userdata vocabulary itself was collapsed into attributes (2026-05-20); the surviving intent is children-as-clones of the same node.
- Fan-out RunScope creation placed in AcquireSubClaims by the plan → corrected to CreateFanOutChildren; claim tree and run-scope tree are parallel structures each owned by one function (2026-05-22, divergences, artifact).
- Lifecycle event fan-out fail-loud → silent skip for non-subscribing peers (2026-05-04, artifact) — a different sense of "fan-out" (peer event fan-out), noted only to prevent misfiling.
