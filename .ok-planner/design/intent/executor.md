## Net position

- **Unary protocol.** Execute is a unary RPC: `Execute(ExecuteRequest) -> Outcome`, a four-variant oneof `Success | Error | Park | AwaitAsyncCallback`. The only two execution modes are synchronous request/response and async-via-HTTP-callback. (2026-06-16..17, 055468fc/b31002b8, transcript)
- **Uniform terminals.** Every settling terminal (Success, Error, Park) carries one uniform shape: `attributes_delta` + `tags` + `scratch`, all committed atomically at terminal time inside the caller-provided transaction ("an event is an event"; invariant terminal-atomic-commit). The protocol must not privilege Success as the only attribute-writeback carrier. (2026-06-16..17, 055468fc/b31002b8, transcript)
- **Tags, not named events.** Independent named events are retired; tags (a set of strings on the terminal, structurally idempotent) replace them. Executors declare their tag vocabulary via `declared_tags` (renamed from `declared_events`); registration rejects subscriptions on undeclared tags and the supervisor's terminal handler rejects settling outcomes carrying undeclared tags. (2026-06-16, 055468fc, transcript)
- **Liveness = connection state + deadlines + keepalive, never heartbeats.** Sync executors: the gRPC connection plus `sync_rpc_deadline` (default 30s) is the liveness signal. Async executors: opt-in keepalive (`POST /v1/runs/{run_id}/keepalive`) feeding `last_progress_at`, swept against per-node `max_quiet_period` and `max_runtime` (both default 0 = disabled; `max_runtime` wins when both fire). Every deadline/timeout must accept 0 = disabled — a busy LLM must never be artificially stopped. (2026-06-16..17, 055468fc/b31002b8, transcript; general zero-default philosophy re-affirmed 2026-06-24, 8a8539a4)
- **Persistent async-callback registry.** `async_ack_id` / `async_ack_registered_at` live on `rimsky_node_runs`; the in-memory registry is read-through cache only; ack registration is atomic with the `transient/await_async` signal emit; pending callbacks survive supervisor restart (invariant persistent-registry-survives-restart). (2026-06-16..17, 055468fc/b31002b8, transcript)
- **Callback body and determinism.** The async callback is a POST to `${callback_url}/v1/callback/{async_ack_id}` with exactly one oneof outcome key (`success` | `error` | `park`); the legacy `{type: ...}` discriminator is rejected; the ack id comes from the URL path. A callback is honored iff the run's phase is active/held at processing time, checked atomically; anything else is ack-but-noop, HTTP 200, with `ack_status` in the body as the authoritative signal. AwaitAsyncCallback keeps the node running (it is not a park) and cannot chain from a callback. (artifact 2026-05-12..22, confirmed through transcript rewrite; events[] array on the body removed 2026-06-16, 055468fc, transcript)
- **Return-leg auth is peer identity, not a per-call token.** The former per-call run-token (`supervisor_id:node_run_id`) and treating the executor-chosen `async_ack_id` as a credential are both swept: the async-callback return leg is authenticated by the mTLS peer identity under `peer_auth: mtls` and by the trusted-subnet assumption under `none`; `async_ack_id` is purely a correlation key (which run a callback settles), never an authenticator — per-call auth on the return leg with nothing authenticating the outbound leg was security theater, and an executor-chosen id is not a credential the trusted side issued (2026-07-16, peer-auth-posture, transcript; see the peer-auth dossier).
- **Park.** Park-snooze is a deliberately baked-in primitive (reversal ratified 2026-06-16). ParkReason is a closed two-value enum `{await_callback, snooze}` (proto zero-value = AWAIT_CALLBACK). Only an executor can park. A parked node is woken only by invalidate or the snooze sweep, never by `/v1/callback`. Resume state rides attribute carry-forward and, for executor-private session material, `park.scratch` — the resume-context channel (Park.payload, Park.session_token, ExecuteRequest.resume_context) is gone.
- **Scratch.** Opaque executor-private bytes ride ExecuteRequest and every terminal variant; rimsky persists them on the node_run (inline/handle/handle_backend, blob spill) and hands them back verbatim, never inspecting them (inertness). Scratch carries byte-for-byte across in-place retry, stale_recovery, and recalculate. (2026-06-14..22, 752fe200/10cf843b, transcript)
- **Errors.** The executor reports only a hierarchical slash-delimited `error_class` (plus payload); the template's `error_types:` policy chain decides the action. Classes are not globally registered; executors advertise `declared_error_classes` (with trailing `/*` wildcard patterns) and registration range-checks template keys against them, with an allowlist bypass for runtime-synthesized classes. There is no Blocked terminal and no shared synthetic `executor_blocked` / `executor_internal_error` class — each executor uses its own leaf (e.g. `agent/blocked`).
- **Observability handshake.** The optional `ExecutorObservability` service's `Capabilities` RPC carries `expected_attributes_schema` (renamed from `userdata_schema` when userdata collapsed into attributes, 2026-05-20), `declared_tags`, `declared_error_classes`, and `validation_supported_roles` (2026-06-11). Executors should register both gRPC services or their advertised schema silently never reaches validation. Trace endpoints (GetTrace/StreamTrace) are observability-side, not part of the runtime Execute surface.
- **In-process executors.** Utility/builtin executors run in-process behind the same executor Client interface as gRPC/HTTP transports (an "inproc" transport in the ClientPool switch, explicit registry constructed at startup — no init()-time self-registration). They are fully encapsulated: ordinary protocol surface only, no runner-side special-casing, no executor-specific persistence tables. Builtin knowledge lives in exactly one place (lookup helpers both control-api validation and supervisor schema resolution delegate to). (2026-06-14..18, 752fe200/055468fc/8e7e4c10, transcript)
- **Bundled executors are Go and dual-mode.** All bundled executors are ported to Go with gRPC as a shim over the standard in-process interface; the all-in-one process registers them in-proc (lib/services `RegisterAll`, protocols-only interfaces, services import confined to the cmd group) so the same template file runs byte-identically in all-in-one and containerized modes. Config-declared names win over bundled handlers; bundled discovery entries are static. (2026-07-01..04, 8a8539a4/3f71f90a, transcript)
- **Policy is service-side, rimsky-inert.** Operator allowlists (claude-agent MCP + expose-env, `RIMSKY_CLAUDE_AGENT_*` namespaced env vars, unset = open) are enforced by the services themselves, never by rimsky; no policy field appears in rimsky's protocol; a policy rejection surfaces as a normal executor error naming the entry, template, and node. Per-node declarations ride the existing dispatch payload — no rimsky protocol change. (2026-07-01, 8a8539a4, transcript)
- **Secrets.** Rimsky is never handed secrets to substitute for executors; `{{env.VAR}}` substitution is for non-secret config (read supervisor-side); secrets reach agents via executor-side per-node `cli.expose_env` intersected with the operator allowlist; plaintext never lands in the persisted attribute bag. (2026-07-01, 8a8539a4, transcript)
- **claude-agent.** A fully-rigged executor implementor, never a privileged client: inherently async (always pre-replies await_async unless the agent itself cannot be invoked), per-outcome report MCP tools, `dispatch_context_read`, session token via `park.scratch`, `binding_id` = dispatch id (NodeRunID), inline-only three-transport `cli.mcp_servers` (http / stdio / module, http-loopback aliasing module), per-node `cli.expose_env`, Ed25519 sign-off gate over the run's real bound output, progress-aware per-node silence/tool-use timeouts defaulting to 0.
- **Boundary discipline.** External tools consume rimsky only via the public protocol contracts, never rimsky source; the protocols module carries ~zero non-stdlib deps beyond grpc/protobuf; executors discover producer endpoints from claim address bytes in ExecuteRequest, not out-of-band config; a leaf cannot distinguish acquired from co-held claims; conformance is the compatibility gate for third-party executors.

## Required behaviors (open promises)

Protocol and terminal handling:

- Unary `Execute` returning exactly one `Outcome` of `Success | Error | Park | AwaitAsyncCallback`. (2026-06-17, b31002b8, transcript)
- All three settling outcomes carry `attributes_delta` and the runtime actually commits it for every variant — Error via applyTerminalError, Park via applyTerminalPark, inside the caller-provided tx. "right. fix everything. implement every missing thing. we want 100%." (2026-06-17, b31002b8, transcript)
- Tags round-trip: terminals carry tags; registration rejects subscriptions referencing tags outside the emitter's `declared_tags`; the supervisor's terminal handler rejects settling outcomes carrying undeclared tags (executor protocol-violation error) — the runtime gate was explicitly ratified as a plan step "so it would not be silently dropped". (2026-06-16, 055468fc, transcript)
- Scratch: attach opaque bytes to any terminal; persisted on the node_run; handed back verbatim on the next dispatch's ExecuteRequest across recovery; never inspected. (2026-06-14, 752fe200, transcript — "yes, inclue STORY-opaque-executor-scratch")
- In-place retry passes the failed attempt's returned scratch verbatim into the next iteration's Execute request (copy the terminal event's scratch into the acquisition). (2026-06-22, 10cf843b, transcript)
- Async ack registry survives supervisor restart: `Queue.RegisterAsyncAck` called in the same tx as the `transient/await_async` emit; per-row effective deadlines (`effective_max_quiet_period_seconds`, `effective_max_runtime_seconds`) denormalized at registration so the sweep does one indexed scan; a callback for an already-terminal run is rejected. (2026-06-17, b31002b8, transcript; divergence "accept as-is" 2026-06-17)
- Three orthogonal per-node deadlines with 0 = disabled: `sync_rpc_deadline` (default 30s, timeout → `executor_sync_timeout`), `max_quiet_period` (default 0, → `executor_quiet`), `max_runtime` (default 0, → `max_runtime_exceeded`, wins over quiet). (2026-06-16..17, 055468fc/b31002b8, transcript)
- Keepalive endpoint `POST /v1/runs/{run_id}/keepalive`: cancel_token auth, no body, bumps `last_progress_at`, 204 / 404 / 401 / 400. (2026-06-17, b31002b8, transcript)
- Callback determinism: honored iff phase ∈ {active, held} checked atomically; ack-but-noop otherwise with structured log; HTTP 200 both ways with `ack_status` (accepted / rejected_run_terminal / rejected_run_stale / rejected_run_parked / rejected_unknown) and optional `current_dispatch_id`. (2026-05-22, fan-out-safety-scope-first, artifact; parked rejection re-affirmed 2026-06-03, instance-lifecycle-durable-by-default, artifact)
- `prior_dispatch_id` / `prior_dispatch_disposition` populated whenever a dispatch supersedes a prior one; disposition storage values are `stale_recovery` and `recalculate` (see Intentional absences for `retry_after_error`); conformance covers supervisor population and executor readability. (2026-05-22, fan-out-safety-scope-first, artifact; rename PRIOR_STALE_RECOVERY 2026-06-17, b31002b8, transcript)
- Callback advertise: supervisor must fail fast at startup rather than silently stamping `http://0.0.0.0:9100` into `callback_url` when advertise is empty and bind is wildcard; the four host/port scalars collapse to a single advertise base-URL (TLS + proxy path prefixes); `callback.advertise_host` / `RIMSKY_SUPERVISOR_CALLBACK_ADVERTISE_HOST` documented for cross-network executors. (2026-06-21, ecde6dd1, transcript; artifact 2026-05-19 crimefinder)

## Intentional absences

Absent BY DESIGN — do not restore:

- **Server-streaming Execute, ExecuteEvent, StreamClose.** Retired for unary; streaming "was confusing and never actually used for anything but the terminal". (2026-06-16, 055468fc, transcript)
- **Heartbeats — the event type, the liveness mechanism, and all remnants.** "Lazy implementations will just spin up a thread and send a heartbeat even as the main task stalls"; migration 013 drops last_heartbeat_at columns; HeartbeatLostPayload / HEARTBEAT_LOST residue removed with fields reserved (2026-06-24, 8a8539a4). The host-agent→supervisor heartbeat is a different surface and stays. (2026-06-16, 055468fc, transcript)
