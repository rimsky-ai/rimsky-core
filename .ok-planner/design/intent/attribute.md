# Intent Dossier: attribute

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner

## Net position

- Attributes are the sole inter-node data channel. Nodes exchange data only through attributes; events/signals invalidate but never carry a payload from one node to another (2026-06-21, 10cf843b, transcript). Terminal tags are the ephemeral counterpart: tags are emission-scoped and never persist into node state; attributes persist (2026-06-24, 8a8539a4, transcript).
- Attributes exist exclusively on node_run rows. There is no standalone per-node or per-instance attribute store; any "latest value" read must name a specific node_run row (2026-07-13, 3f71f90a, transcript). Rows are the persistent record of what each run produced — explicitly not a cache (2026-05-20, attribute-pull-resolution, artifact).
- Frame isolation is the standing ruling: only a message runs a frame, every message gets a new frame, a node's attributes at frame start are the schema default values, and message payloads are the ONLY cross-frame carrier (2026-07-06, 3f71f90a, transcript: "A node's attributes at frame start are the default values. Message payloads are the ONLY cross-frame carrier."). Carry-forward happens only within a single frame and run-scope; any cross-frame carry-forward in code is a bug (2026-06-30, 8a8539a4, transcript).
- The attribute pipeline per dispatch is exactly: copy forward from the last run in the RunScope (or seed on first run) → apply substitutions → validate against schema → run executor → validate resulting attributes against schema (2026-06-15, c60b550a, transcript). Substitution runs in exactly two rounds on one uniform code path: upstream/attribute substitution at pending→stale (snapshotting), claim substitution at stale→running (2026-06-21, 10cf843b, transcript).
- The substitution grammar is a closed enumeration of six source kinds — claim, params, nodes, messages, child, env — plus the optional `| <literal>` fallback and the lenient `?` marker (2026-06-24, 3b1066c7, transcript). `messages` is a lexical alias for `nodes`, type-checked at registration, with exactly one substitution pipeline underneath (2026-06-19, 8a3b8c19, transcript).
- Substitution reads create no implicit subscriptions. Every substitution ref must be covered by an explicitly declared `subscribes:` entry or registration fails with `substitution_ref_uncovered` (2026-06-14, 37e2ea5e, transcript; closed issue #18 in v0.10.0, 2026-06-24, 3b1066c7).
- Attribute values are structurally inert: rimsky may traverse for transport but never inspects values. Sanctioned read sites are exactly the substitution engine's `walkPath` and the by_match/breakpoint matcher's primitive-equality `attrs.<path>` read (2026-05-04 modeling-layer-contract; 2026-05-21 attribute-overrides-matcher-overlay, artifact).
- `attributes_delta` exists only on the two run-terminating verdicts (terminal/success, terminal/error/<class>), means "what this verdict contributed", never the full bag, and commits inside the same transaction as the terminal apply. Park and infra are not terminals and carry no delta (2026-06-24, 8a8539a4, transcript).
- `attribute/<key>/changed` signals are diff-based and uniform across every settle path, with a same-RunScope-only baseline (2026-06-22, 10cf843b; 2026-07-05, 3f71f90a, transcript).

## Required behaviors (open promises)

### Grammar and resolution

- Six-kind closed grammar: `{{claim.*}}`, `{{params.*}}`, `{{nodes.<X>.attribute.<Y>}}`, `{{messages.<type>[.<field>]}}`, `{{child.partition_key}}`, `{{env.VAR}}` — one repo-wide syntax (2026-06-24, 3b1066c7, transcript: "we think {{env.VAR}} is dandy"). The module header's enumeration of source kinds must match the resolver's live case arms, enforced by an AST-based accuracy test (2026-06-06 comprehensive-gap-closure, artifact).
- `messages.<type>` is sugar for `nodes.<type>`: same Deps lookup, one parser/extractor/resolver, registration typechecks that messages-prefix names are declared message entry points and nodes-prefix names are non-message nodes (2026-06-18/19, 9fb55f08 + 8a3b8c19, transcript).
- `env` is dispatch-time non-graph input like params: no wait-set rows, no subscription edges, no cascade coupling; values read from the supervisor's process environment (2026-06-24, 3b1066c7, transcript). Tag substitution stays restricted to the params kind only — env deliberately excluded (2026-06-24, 3b1066c7, transcript).
- Two resolution modes by input shape: whole-directive mode returns the typed JSON value as-is; embedded mode stringifies and concatenates. Literal text before/after/between directives and multiple directives per source string are admitted (2026-05-19 multi-instance-template-ergonomics; 2026-05-20 userdata-collapse, artifact).
- Path-walking kinds admit an empty trailing path resolving to the kind's JSON root (whole attribute object, whole claim payload, …) (2026-05-19 multi-instance-template-ergonomics, artifact).
- JSON null along a resolution path is treated as missing (ErrMissingSource), not lifted (2026-05-19 multi-instance-template-ergonomics, artifact).
- ErrMissingSource is not a frame-blocking error: fallback literal substitutes, lenient `?` lifts, optional field omitted; only a required strict ref with no fallback escalates to `template_resolution_failed` (2026-06-14, 37e2ea5e, transcript: "not a frame blocking error?"). Substitution-failure handling lives wherever substitution runs: the gate evaluator classifies inline in the sender's terminal transaction, drives the receiver to its policy, lets the sender's settle commit; non-classifiable errors propagate (2026-06-21, 10cf843b, transcript).
- Fallback operator `{{<directive> | <literal>}}`: one directive, one scalar JSON literal; fires only on ErrMissingSource — `false`, `0`, `""` are present values (2026-05-20 attribute-pull-resolution, artifact). There is no `default:` keyword in the fallback grammar (2026-05-29 console-upstream-auth, artifact).
- Lenient `?` marker: a missing source resolves to empty at runtime through the full stack — dispatch succeeds, run completes — proven end-to-end, while the unmarked equivalent fails dispatch with a missing-source error; neither behavior may silently substitute for the other (2026-06-06 comprehensive-gap-closure; 2026-06-08 corpus-bootstrap, artifact). `?` and `|` on the same directive are incoherent and rejected at registration (2026-05-20 userdata-collapse, artifact).
- Per-field `source:` arity is 1, enforced at registration; the arity asymmetry with many-to-many subscriptions is intentional and load-bearing (2026-05-20 multi-source-substitution-decline, artifact).
- Canonical claim-scope spelling is `{{claim.<alias>.claim_scope}}` end-to-end; the legacy `scope` spelling is refused at registration naming the rename (2026-06-06 comprehensive-gap-closure, artifact).
- The dispatch-time substitution context must include held claims, not just locks — a co-holder's `{{claim.<alias>.address}}` must resolve (GH issue #16 fix; 2026-06-10 cascade-and-claim-handoff, artifact).

### Schema, validation, overrides

- Each attribute property is exactly one of three shapes: source-bound, static-default, or executor-written (readOnly) (2026-05-20 userdata-collapse, artifact: "Userdata retires as a distinct concept. Attributes absorb its jobs"). At most one of `source:`/`default:`; the executor is authoritative on readOnly authorship; fourth satisfying condition: a property the executor's schema does not enumerate or constrain is admitted (delegated naming authority) (2026-05-20 userdata-collapse + 2026-05-28 quality-of-life, artifact).
- If a node has attributes they must have a schema; there is no attributes-without-schema shape (2026-06-15, c60b550a, transcript). Effective schema = executor `expected_attributes_schema` merged with L1 template defaults and L2 node schema; type conflicts rejected; `additionalProperties` policy comes from the executor and cannot be relaxed by the template author (2026-05-20 userdata-collapse, artifact).
- Attributes validate twice — post-substitution before the executor call, and at commit on executor writeback; both gates mandatory (invariant 12) (2026-05-04 modeling-layer-contract, artifact). NOTE: adjudicated 2026-07-13 (3f71f90a) that the dispatch-phase gate was silently dropped by the June-21 message-receiver refactor — ruled fix-code, rewire the check.
- Override merge layers: L1 template `defaults.attributes.by_executor` → L2 node schema → L3 instance `by_executor` → L4 instance `by_node` → L5 `by_match` ordered matcher/overlay entries → L6 one-shot breakpoint resume overlay. Most specific wins; schema locked at registration, only values flow (2026-05-20 userdata-collapse; 2026-05-21 matcher-overlay; 2026-05-24 instance-debugger, artifact).
- Override and default values are static — an operator-supplied `"{{X}}"` is a literal string, never substituted (2026-05-20 userdata-collapse, artifact).
- by_match matcher grammar is closed: equality only over node_type, executor, graph, child_key, `attrs.<path>` (primitive values); missing keys wildcard; AND-joined; empty matcher matches all; shared `foundation/matcher` package with breakpoints; empty-string child_key rejected at grammar level; missing/non-primitive attrs path silently no-match (2026-05-21 matcher-overlay; 2026-05-24 instance-debugger, artifact). `child_key` sources from the run's RunScope partition_key (2026-05-22 fan-out-safety, artifact).
- L5 precedence is author declaration order (later wins), evaluated against a snapshot of the post-L4 bag; matcher targets what the executor will see (2026-05-21 matcher-overlay, artifact). The overlay is rimsky-internal: no proto, registration, or executor-visible changes (2026-05-21 matcher-overlay, artifact).
- Match observability is event-derived: each match emits an `attribute_override_matched` operational event at dispatch; the API aggregates counts from the event log at read time (2026-07-06, 3f71f90a, transcript: "option a"). Counting on match (not successful dispatch) semantics carry forward from the original design (2026-05-21 matcher-overlay, artifact).
- L6 resume overlay is per-hit only, never persisted into `rimsky_instances.attribute_overrides`; validated both at control-api and again at the supervisor; breakpoint matchers evaluate a post-L5 snapshot so a later hit never sees an earlier hit's L6 overlay (2026-05-24 instance-debugger, artifact). Resuming with an overlay must cause the next dispatch to actually carry the overlaid attributes (2026-06-08 corpus-bootstrap, artifact).
- The instantiation gate validates statically-knowable attribute config against every referenced service's advertised schema — value constraints, not just shape — refusing the create with a named error (2026-06-08 corpus-bootstrap, artifact-only).
- `required:` fires only at the commit-time gate for executor-written properties; strict directives already gate dispatch (2026-05-20 userdata-collapse, artifact).

### Subscription coupling

- Every substitution ref requires an explicit covering subscription; registration rejects uncovered refs with a structured `substitution_ref_uncovered` error carrying a copy-pasteable suggested entry (2026-06-14, 37e2ea5e, "Approach A"; confirmed shipped 2026-06-24, 3b1066c7, transcript).
- Coverage is asymmetric by design: a wildcard `attribute/*` subscription covers per-field reads, but a per-field subscription does NOT cover a whole-pull read (2026-06-14, 37e2ea5e, transcript).

### Storage, carry-forward, dispatch mechanics

- Per-run storage keyed by node_run_id; every run row contains exactly what the executor saw at dispatch (static defaults snapshotted per run; template mutations never rewrite history) (2026-05-20 attribute-pull-resolution + userdata-collapse, artifact).
- The node_run's persisted bag is the one and only attributes mechanism — no sidecar, no additional table (2026-06-19, 8a3b8c19, transcript: "that should be the one and only mechanism for attributes").
- Fresh-scope defaults realize in two steps: empty bag written at row creation; effective bag (schema defaults + resolved sources) computed and persisted at the substitution moment — pending→stale for cascade rows (2026-07-06, 3f71f90a, transcript).
- Carry-forward: the new node_run gets a complete DEEP copy of the prior dispatch's bag in the same frame and RunScope, then re-substitution overlays it before the executor invocation; default-on for all properties, with documented readOnly-plus-writeback as the canonical stateful pattern (2026-06-14 + 2026-06-30, 752fe200 + 8a8539a4, transcript: "'complete shallow copy' this is concerning. should be a deep copy."). First dispatch in a scope, and any new RunScope, starts from schema defaults.
- Bag build happens at pending→stale only — after queue-resolution semantics, never at enqueue/row-creation for cascade rows; the same code path every time (2026-06-21, 10cf843b, transcript). Non-cascade creations (operator-invalidate, policy-retry, infra-reenqueue) copy the previous run's bag verbatim; operators wanting overrides call set_attribute then invalidate — separate concerns (2026-06-20, 8a3b8c19, transcript).
- The gate evaluator transitions pending→stale only when the wait-set is fully drained and no subscribed upstream has an in-flight run (pending/stale/running/held/parked); at the transition it builds the dispatch input bag, then applies the node's cascade-mode rule (most-recent / sequenced / idempotent) (2026-06-20, 8a3b8c19, transcript).
- The `dispatch_input_bag` is preserved in its own column, never overwritten by writeback: carry-forward reads the live bag; idempotency comparison reads the input bag (2026-06-20, 8a3b8c19, transcript). The dispatcher loads the gate-eval-persisted bag by run id — sender attributes are not re-read at dispatch time (2026-06-20, 8a3b8c19, transcript).
- A queued node_run pins its upstream RUNS (not nodes) at enqueue time via the wait-set row's sender_run_id; its substituted values must come from those pinned runs once settled; its carry-forward seed comes from its own last completed run at execution time (2026-07-13, 3f71f90a, transcript: "the runs *at the time* the new run is enqueued"). Substitution deps are built by reading each upstream sender run's full persisted bag into a dep dictionary via one unified function (BuildAttributeDeps); wait-set rows signal which receiver to evaluate and carry no data (2026-06-23, 10cf843b, transcript).
- Static upstream view: a node-run's view of its upstreams is snapshotted through substitution at dispatch time and reused on resume — a deadline-driven park-and-resume re-invokes with the dispatch-time snapshot, not a rebuilt context (story resume-preserves-snapshot; 2026-06-19, 8a3b8c19, transcript; explicitly survives the seven-state redesign).

### Terminal writeback and signals

- `attributes_delta` rides only terminal/success and terminal/error/<class>; the runtime commits the delta for every settling variant inside the caller-provided transaction, before the error-policy chain runs (terminal-atomic-commit) (2026-06-17, b31002b8; narrowed 2026-06-24, 8a8539a4, transcript).
- `attributes_delta` means the verdict's contribution, never the full persisted bag; a passive auto-terminating holder carries an empty delta; aggregate fan-out parent settlements carry an empty delta (2026-06-24, 8a8539a4, transcript).
- `attribute/<key>/changed` emission is diff-based and uniform: every node at settle, regardless of node type, executor, terminal kind, or code path, diffs final values against the same-RunScope prior run's persisted values and emits only for keys that actually changed; same-value resettlement emits nothing; audit-log emission driven by the same diff (2026-06-22, 10cf843b, transcript). Baseline is same-RunScope only — no cross-scope or cross-frame fallback; a node re-running in a fresh frame has no prior, so the signal fires (2026-07-05, 3f71f90a, transcript).
- Pass-through propagation works uniformly: in A→B→C where B substitutes A's value through (including fan-out parents), C is invalidated when the passed-through value actually changes (2026-06-22, 10cf843b, transcript).
- A message-driven self-loop must genuinely converge via the diff-gate, proven by exact run/message counts, not a frame-count ceiling (2026-06-23, 10cf843b, transcript).

### Messages, sub-graph, fan-out

- A message node IS the message: its attributes are exactly the payload, copied verbatim with no receiver-side substitution; other nodes read via ordinary nodes substitution; there is no special message-substitution path anywhere (2026-06-19 + 2026-06-22, 8a3b8c19 + 10cf843b, transcript). Message-receiver nodes cannot subscribe and cannot substitute in — no subscribes block, no source directives (2026-06-22, 10cf843b, transcript).
- Sub-graphs are sealed (no closure semantics; no free reference to calling-graph upstreams) with one explicit designed channel: the calling node's attributes are copied into the sub-graph's dedicated entry node, and the exit (terminal) node's attributes are carried verbatim back onto the calling node's row at settle, cascade firing to the caller's subscribers (2026-05-20 attribute-pull-resolution, artifact; 2026-06-19 + 2026-06-22, 08d65bfe + 10cf843b, transcript).
- Fan-out: the parent's attributes are its own dispatch-time bag only; no child-attribute aggregation, no parent emission of child changes, downstream must not wait on parent attributes for child results; per-partition metadata rides `producer_metadata.<partition_key>`; direct reference to a fan-out child across the run-scope boundary is not supported and won't be (2026-06-22/23, 10cf843b, transcript). Small per-partition threading to the parent is future feature work, not a gap (2026-06-19, 08d65bfe, transcript).
- `partition_request` is vanilla substitution through the standard ResolveContext, identical to executor-attribute dispatch (2026-06-18, 9fb55f08, transcript, overturning the deliberate message-only narrow). `{{child.partition_key}}` must actually resolve on fan-out leaves (2026-06-02 remediation, artifact).

### Executor surface, bundled services, security

- Executors mutate attributes ONLY by returning `attributes_delta` on a settling outcome — no mid-flight get/set channel of any kind (2026-06-24, 8a8539a4, transcript).
- Claude-agent session continuity: the CLI conversation continues across dispatches within one RunScope via a readOnly `session_token` attribute written on every settling terminal and passed as `--resume`; fresh RunScope starts fresh (2026-06-14, 752fe200, transcript). Rimsky only needs to carry the session token; executors may retain session state locally (2026-06-30, 8a8539a4, transcript).
- Bundled `loop_counter` utility node: required `max` input, executor-written `count` carrying forward within a RunScope, signaling loop-continue vs done — bounded iteration without a custom executor (2026-06-14, 752fe200, transcript; its original named-event signaling shape is superseded, see below).
- Plaintext secrets must never land in the persisted attribute bag; rimsky is not handed secrets to substitute for executors; claude-agent expose-env is per-node (`cli.expose_env`) intersected with an operator allowlist, off-allowlist declarations rejected with a named error (2026-07-01, 8a8539a4, transcript: "rimsky should not be handed secrets to subtitute for the executor").
- Verifier check results must reach `attributes_delta` intact (sql-checks structpb regression pin) (2026-06-17, b31002b8, transcript).
- Forensic last-attribute: control-api/observability return a node's most recent resolved bag from real persistence (GET /nodes/{id}) (2026-06-06 + 2026-06-08, artifact-only; caveat: its original keying referenced the since-retired per-instance main RunScope — the promise stands, the mechanism must be re-derived from current scope rules).
- Blob spill: values under `persistence.blob.spill_threshold_bytes` stay inline, larger spill transparently to the configured backend; readers always see values as values (2026-05-08 platform-extensions, artifact-only).
- Rimsky-side substitution observable via the `attributes_substituted` event listing schema-source fields (2026-05-04 public-docs-architecture, artifact-only; predates the June signal-taxonomy overhauls — verify against the current event vocabulary before enforcing).

## Intentional absences

- **`hard_dep: true`** on attribute properties — replaced entirely by the more expressive `subscribes:` block configuration (2026-06-14, 37e2ea5e, transcript). A template carrying it gets whatever the schema validator does with unknown properties; no special catch added (2026-06-14, 37e2ea5e).

## Corrections and restorations (drift-fight record)

- **Invariant-12 dispatch gate dropped (2026-07-13, 3f71f90a):** the June-21 message-receiver refactor silently removed Validate/CheckEffectiveAttributesSchema from resolveAttributes, leaving validation-error policy legs unreachable. Adjudicated fix-code (findings 111/128 = one defect). Precedent: validation gates are load-bearing; silent removal during refactor is drift.
- **Cross-frame baseline widening (2026-07-05, 3f71f90a):** the diff-gate prior-run lookup was widened to prior frames (commit 20724e96) and a concept:signal clause documented it; ruled "absolutely breaks isolation," fully reverted, concept clause included. Precedent: even persisted settled state is off-limits across frames; docs canonizing drift get corrected too.
- **Shallow carry-forward copy (2026-06-30, 8a8539a4):** loadReceiverCarryForward shared nested references; ruled a mutation footgun even if unmutated today; fixed to deep copy immediately.
- **Carry-forward race (2026-06-24, 8a8539a4):** "pre-existing failures" framing rejected — regression traced to gate evaluation reading the prior dispatch's gate-eval-seeded input bag instead of the executor's committed writeback while the prior run was in flight (stale session-resume values). Precedent: regressions must be traced, not waved through.
- **Invented fan-in merge (2026-06-22, 10cf843b):** drift-introduced mergeChildAttributesIntoHolder and its emit loop removed wholesale.
- **Gate-evaluator messages-into-deps side path (2026-06-22, 10cf843b):** message substitution had drifted into a parallel special path; ruled that messages are literally nodes at runtime with zero special substitution support.
- **Snapshot-at-creation bug (2026-06-20, 8a3b8c19):** the user's own snapshot-at-creation choice was self-corrected hours later — multi-upstream runs must exist without a snapshot until the wait-set drains; forced the pending state and pending→stale bag build. A refactor subagent later re-introduced snapshot-at-enqueue and broke 29 integration tests; corrected again (2026-06-21, 10cf843b).
- **Deferral forbidden (2026-06-21, 10cf843b):** deferring punchlist items (B1 dispatch re-read removal, NodeRow derived-state stripping) was overruled: "that work has to be done some time, and that time is now."
- **CarryExitWriteback aspirational (2026-05-20, artifact):** the exit-writeback invariant existed only in docstring form — writebacks validated then dropped; completed to persist to the parent run's row in-transaction.
