# Intent Dossier: frame

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner
history artifacts (2026-05-04..2026-06-11). Transcript tier outranks artifact tier;
later intent supersedes earlier. Part of the drift-remediation intent ledger.

The frame concept was fundamentally redesigned in the transcript era (the June 14–17
message-schema work and the June 30–July 7 frame-isolation work). Most May-era artifact
positions on frame creation, resolution modes, and cross-frame mechanics are superseded;
they are recorded under "Superseded / historical" and must not be used to justify code.

## Net position

- A frame is, by product definition, "one complete run of the graph with no side effects from earlier runs or against future runs" — this was always the intent (2026-07-06, 3f71f90a, transcript).
- Only a message creates a frame. Nothing else — not park-wake, not cron, not cascade, not operator invalidation, not instance creation (2026-06-15, 91ec93d1, transcript: "*nothing* creates a new frame except a message").
- One message = one frame, exactly. N messages posted in succession produce N distinct frames; multiple messages in one frame is impossible by design; messages cannot queue on a node or node_run (2026-06-14 and repeatedly after, transcript).
- Messages trigger frames; they do not "land in" them — triggering and landing are one action. A message can never enter, affect, or be scooped into an already-running frame (2026-06-30 and 2026-07-03, transcript).
- Frames have no queued state: a frame is created and then immediately runs. Pending work waits as messages in a per-instance message queue; the next message creates a new frame IFF no currently non-resolved (open or parked) frame exists for that instance (2026-07-05, 3f71f90a, transcript).
- At most one frame may ever be executing per instance; frames are strictly serial per instance with no queue-skipping (2026-07-05, 3f71f90a, transcript; corroborated by 2026-05-04 artifact).
- Perfect frame isolation: a node's attribute values at frame start MUST be the schema default values; there is never carry-forward between frames; message payloads are the ONLY mechanism for carrying state across frames; nothing that happens in a frame changes instance or node identity rows (2026-06-30 and 2026-07-05, transcript).
- A frame is a tree of RunScopes. Each frame's start creates a fresh root RunScope owned by that frame (frame row carries root_run_scope_id); a RunScope is never in more than one frame (2026-06-30, 8a8539a4, transcript).
- Every frame row carries a NOT NULL triggering_message_id pointing at the message-ledger entry that opened it — the schema-level guarantee that no internally-created frame can exist (2026-06-14, bfc9febb, transcript; nullable proposal rejected 2026-06-19).
- Frame lifecycle state (running/completed/failed) is derived at read time from node_run states plus ended_at; the stored rimsky_frames.state column is retired. A frame cannot fail independently of its node runs — failed iff a node_run terminated failed (2026-07-06, 3f71f90a, transcript).
- The frame row is cascade-immutable: cascade processing never stores state in a frame row. Sanctioned bookkeeping writes only: the reaper stamps ended_at exactly once (atomic RowsAffected==1 gate), and the liveness heartbeat last_progress_at (2026-07-06, 3f71f90a, transcript). One-open-frame-per-instance is preserved via a partial unique index WHERE ended_at IS NULL.
- A frame ends only when every node_run in it is resolved — none stale, running, or parked. A parked node_run holds its frame open. Parking is strictly intra-frame: parked exists only on node_runs, waking resumes the same frame, and parked never carries into a new frame (2026-06-15, 91ec93d1, transcript; 2026-06-03 artifact corroborates the frame-end predicate).
- Cascade is intra-frame machinery. In-frame loops are explicitly supported — a self-subscribed node or an N-node back-edge cycle can loop indefinitely within a single frame; there is no "one node-run per node per frame" rule (2026-06-24, 3b1066c7, transcript). Cascade modes (most-recent/sequenced/idempotent) govern the intra-frame node_run queue only and have nothing to do with messages (2026-07-03, transcript).
- Only one node_run per node in a runscope can be active at a time; there is no limit on pending node_runs in a runscope; pending→stale transitions are serialized per (node_id, run_scope_id) (2026-06-30, 8a8539a4, transcript).
- No asynchronous ad-hoc invalidation of any node: nodes dispatch in an orderly fashion, and while a node is being resolved either all upstreams are resolved or its view of upstreams is static (2026-06-19, 8a3b8c19, transcript).
- Operator interaction with a frame is confined to the debug-override channel, legal only when the instance is explicitly paused or an unresumed pause-mode breakpoint hit blocks a runner; parked and stuck frames do NOT qualify (2026-06-14, bfc9febb, transcript).
- Cross-frame state propagation is possible exclusively through message-passing; any other cross-frame carrier in code or docs is a bug (2026-06-30, 8a8539a4, transcript).

## Required behaviors (open promises)

- An empty message (type "") posted to a live instance opens exactly one frame whose triggering_message_id matches the returned message id and stale-marks every structural root via the normal subscriber-side cascade; non-roots untouched; Idempotency-Key replay returns the original id and opens no second frame; author-declared empty message types are rejected at template validation (2026-06-16/2026-06-17, 4c42fe5b/b95ff4a7, transcript; "signed off").
- After the empty-wake unification (commit 80a11733), message receipt and delivery treat the empty type identically with every declared type — one code path, no branch named for the empty case (2026-07-05, 3f71f90a, transcript).
- Instance creation is idle: POST /instances writes the row and nothing else — no frame, no envelope, no node-runs; exactly one OnInstanceCreated fires. Proven by an e2e scenario test the user signed off (2026-06-15..17, 91ec93d1/b95ff4a7, transcript: "creating an instance has nothing at all do do with invoking it").
- A parked node_run holds its enclosing frame open, and an async-callback-pending node also holds its frame — two structurally distinct load-bearing properties, each with its own dedicated e2e test (a coverage substitution between them was caught and remediated) (2026-06-17, b95ff4a7, transcript).
- The held-frames diagnostic surfaces frames held by parked nodes (scoped to phase='parked') (2026-06-17, b95ff4a7, transcript; diagnostics promise also 2026-06-08 corpus-bootstrap, artifact).
- When an operator disables/terminates an instance, the currently running frame finishes and then the instance stops: no new frames, new messages rejected, queue drains without effect; terminated means disabled-with-row-persisting, not delete (2026-07-06, 3f71f90a, transcript).
- In-frame loop shapes carry executable proof: 2-node back-edge re-fire tests (cascade_two_node_backedge_in_frame_test.go, cascade_two_node_backedge_via_attribute_test.go) pin the per-sender-node walker accumulation rule, complementing the single-node self-loop proof loop_counter_cap_e2e_test.go (2026-06-24, 3b1066c7, transcript: "let's write one and prove that it either works or doesn't").
- The restored cascade proof tests drive multiple cascade rounds inside a single frame via self-subscription/loop-node patterns, proving intra-frame node_run queue semantics: in-flight seal, most-recent coalesce, sequenced ordering, idempotent dedupe, diff-gate suppression (2026-07-05, 3f71f90a, transcript).
- A message-driven self-loop genuinely converges via the diff-gate, proven by exact run/message counts — a frame-count ceiling is not a convergence proof (2026-06-23, 10cf843b, transcript).
- The loop_counter builtin's test happens entirely in a single frame and asserts only counter semantics (2026-06-15, 4c42fe5b, transcript).
- A message arrives, kicks off a frame, and its payload is copied verbatim into the message node's attributes — the message node IS the message; other nodes read via ordinary nodes substitution (2026-06-19, 8a3b8c19, transcript).
- Claude-agent session resume works as a simple intra-frame loop: one trigger message → one frame, a worker self-edge cascade subscription producing serially-settled dispatches in one frame/RunScope, session_token chained via intra-RunScope carry-forward (2026-06-30, 8a8539a4, transcript).
- Cascade-emit idempotency key is cascade-emit:<node_id>:<frame_id> (stable across re-enqueue), pinned by tests asserting one envelope per (node_id, frame_id) (2026-06-15, 91ec93d1, transcript).
- Fresh-scope attribute defaults are two-step: empty bag at row creation; effective bag (schema defaults overlaid by substitution sources) computed and persisted at the substitution moment (pending→stale gate for cascade rows). Tests prove fresh-scope defaults and frame-row cascade-immutability on both backends (2026-07-06, 3f71f90a, transcript).
- Whether a frame is unresolved is derivable at runtime from node_run states alone, with no additional persisted state (2026-07-05, 3f71f90a, transcript).
- The operator API surface for frame state (state JSON field, ?state= filter) is unchanged by the stored-column retirement — state is derived via SQL CASE (2026-07-06, 3f71f90a, transcript).
- Lineage records capture frame-trigger fields — the code self-declares the gap ("NOT YET plumbed"); settled intent is capture; adjudicated fix-code, finding 442 (2026-07-13, 3f71f90a, transcript).
- Frame liveness is progress-based: last_progress_at on the frame row is a sanctioned write updated on node state transitions; the frame timeout means "no progress in window" and remains a soft structured-log warning with no automatic frame-fail (2026-05-05, reactive-loops, artifact-only for the timeout semantics; last_progress_at as a sanctioned write is transcript-ratified 2026-07-06). Schema enforces frame_timeout_ms >= 60000 (2026-05-05, reactive-loops-notes, artifact-only).
- Dispatch eligibility: a stale run is not dispatch-eligible while any subscribed upstream has an in-flight run in the same frame — two-condition predicate (no undrained wait-set rows AND no in-flight subscribed upstream) (2026-06-11, last-mile-stability, artifact; corroborated by the 2026-06-19 transcript orderly-dispatch constraint). The multi-hard-dep settled-this-frame guard's reproducing test stands as the regression pin (2026-06-12, last-mile-stability-completion-report, artifact).
- Predicates split by intent: "does this frame still have unresolved work" counts parked; "is there work eligible to dispatch now" does not (2026-06-03, instance-lifecycle-durable-by-default, artifact — consistent with all later transcript rulings).

## Intentional absences

Absence of each item below is BY DESIGN. Do not restore.

- **frame: in|next per-subscription / per-emit modifier** — retired entirely; cross-frame triggering is explicit message emission; "frame: next" quietly violated the only-messages-create-frames rule (2026-06-14, 37e2ea5e, transcript; reaffirmed 2026-06-15, 4c42fe5b: "the retired per-subscription 'frame: next' declaration is not restored").
- **coalesce and frame-resolution modes** — frame_resolution_mode (template field), frame_delivery_mode (instance column), the queued-coalesce partial index, and "frame-resolution mode" as an author surface all dropped (2026-06-14, bfc9febb, transcript: "the work here is to remove coalesce and limit direct invocation").
- **Queued frame state** — both queued-frame coalesce designs (eager-at-receipt, lazy-at-pickup) rejected; pending work waits as messages, not frames (2026-07-05, 3f71f90a, transcript).
- **Parallel frame execution** (N running frames per instance) — omitted entirely; its own future design problem (2026-06-14, bfc9febb, transcript).
- **Generalized cancel** (queued frame / in-flight run / pending message) — explicitly omitted; backfill's cancel does not survive and is not replaced (2026-06-14, bfc9febb, transcript).
- **Synthetic-envelope wake mechanism** — EnqueueSyntheticWakeFrame, wake_node_ids and wait_set_pairs payload fields, all four runtime type-paths (instance/root, node/reset, asset/materialize, node/invalidate), and the frame-engine wake reader all deleted; also the test-harness InvalidateNode helper. A dedicated POST /instances/{id}/wake endpoint was rejected as a parallel non-message wake path (2026-06-16/17, 4c42fe5b/b95ff4a7, transcript; verified by absence, signed off).
- **Stored rimsky_frames.state column** — retired; state derived at read time (2026-07-06, 3f71f90a, transcript).
- **frames.source_node_ids column** — retired as redundant (derivable from triggering message) (2026-06-14, bfc9febb, transcript).
- **rimsky_nodes.frame_id mutable column** — removed; node identity rows are immutable during frame processing (2026-07-05, 3f71f90a, transcript).
- **instance.MainRunScopeID / per-instance main RunScope** — removed; the root RunScope is per-frame (2026-06-30, 8a8539a4, transcript).
- **Auto-terminate / terminate_after_run** — scrubbed entirely: flag, MarkInstanceTerminatedIfDone, column (dropped by migration), story:terminate-after-run, decision:instance-self-termination. Termination is operator-initiated only (2026-07-06, 3f71f90a, transcript).
- **Cross-frame diff-gate baseline** — there is no such thing as a cross-frame diff-gate; the GetPriorRunData widening (commit 20724e96) was ruled a frame-isolation violation and fully reverted; baseline is same-RunScope only; a node re-running in a fresh frame has no prior, so the signal fires — correct behavior (2026-07-05, 3f71f90a, transcript).
- **story:queue-drain-converges** — retired outright; queue drain needs no cross-frame support (empty queue → no message emits → no next frame); its cross-frame-convergence test deleted (2026-07-05, 3f71f90a, transcript).
- **story:cross-frame-coupling** — retired/split; "coupling" framing wrong (frames are isolated; messages are loose one-way delivery); intra-frame substance survives as story:iterative-workflows-converge (2026-07-05, 3f71f90a, transcript).
- **Wait-set topic_kind 'message'** — retired (migration 011 narrows the CHECK); nodes may only block on events resolvable within the current frame; wait-set records only within-frame edges (2026-06-15, 91ec93d1, transcript).
- **advanceOneFrame parked-aware wake branch + wakeParkedReceiverInTx** — backed out; since park is intra-frame the guarded scenario is unreachable (2026-06-15, 91ec93d1, transcript).
- **Message-tied fan-out triggering** — fan-out is a claim request to a producer, completely orthogonal to messages; fan-outs create and resolve within a frame; "trigger.message" must not exist (2026-06-18, 9fb55f08, transcript).
- **kill_requested column / kill-poll in-flight cancellation** — retired; in-flight work runs to terminal (2026-05-04, modeling-layer-contract, artifact; never contradicted).
- **Synthetic messages** — no runtime-fabricated envelope on a special code path; implied triggers must be real default messages bundled with an operation (2026-06-15, 91ec93d1, transcript).
- **Cumulative excise list** ratified 2026-07-07 (3f71f90a, transcript) — must not appear as current anywhere: stored frames.state, terminate_after_run, emits_message, named-event (incl. {{nodes.X.event.Y}} grammar and event/ and message/* signal families), per-instance main RunScope, wake_on_change flag, auto-instance-termination, queued frames, wait_set.subscription_scope (migration 016), attribute_overrides_match_counts (migration 020).
- Artifact-era deferred set, never revived: predicate language for handler conditions, generalized frame-end predicate hooks, hard frame timeouts with teeth, per-claim on_unavailable overrides (2026-05-05, reactive-loops, artifact-only).

## Corrections and restorations (drift-fight record)

Precedents for adjudication — each is a case where code or docs drifted and the user ruled.

- **The frame/RunScope model drift (June 30).** Docs (concepts/run-scope.md "Main RunScope: one per instance", "frames and RunScopes are orthogonal") and implementation were both wrong — not new intent, drift traced by forensics to the 2026-05-22 fan-out-safety-scope-first spec, which "specified the wrong model into existence" and landed spec+plan+code+docs atomically (commit 899c9cb1) with no review boundary. Ruling: fix code and docs to the frame-rooted model; concepts edited directly; decisions frame-isolation and run-scope-is-per-frame added (2026-06-30, 8a8539a4, transcript).
- **Recurring cross-frame state reintroduction (July 5–6).** Agents repeatedly reintroduced cross-frame state (diff-gate widening commit 20724e96) because design docs themselves pointed backward (story:queue-drain-converges, concept:signal documenting the two-step prior lookup). Ruling: the docs were the drift; excise every backward-pointing surface — concept docs, stories, decisions, identifiers, and green tests proving illegitimate mechanisms — or a future session will reintroduce it. North star: frame isolation (2026-07-05/06, 3f71f90a, transcript).
- **Empty-wake scope override.** cascadeEmptyMessageWakeInTx set the receiver's scope to the receiver's latest run's scope from any frame — a hard frame-isolation violation; deleted; the frame's root scope is always used (2026-07-03, 3f71f90a, transcript).
- **Empty-wake partial implementation.** History forensics confirmed the feature shipped with the exact rejected alternative (hard-coded matched-on-empty branch), a runtime lazy map instead of the persisted template, and no empty-string receiver node; the offending commits (12243806, 6a62f50f) bypassed the brainstorm/plan/execute pipeline (2026-07-05, 3f71f90a, transcript). Fixed by the unification commit 80a11733.
- **Cascade-mode proofs broken silently.** All six proofs passed before frame-isolation commit 6a62f50f broke them; a too-tight Makefile test timeout masked the failures for days. They were supposed to be reimplemented with the node_run cascade (2026-07-03, 3f71f90a, transcript).
- **"One node-run per node per frame" false claim.** The assistant treated GitHub issue #19 as a design gap; user ruled the cascade absolutely supports in-frame loops; scenario tests were written as proof (2026-06-24, 3b1066c7, transcript).
- **One-message-per-frame restated repeatedly.** "litrally not possible, as one message creates one and only one frame. we keep having to re-state this. why?" — recurring drift on this rule is itself documented (2026-06-22, 10cf843b, transcript).
- **Operator re-run as a typed message.** A test used a cosmetic 'operator/worker-rerun' typed message; ruled the wrong primitive — a message would open a new frame; re-run is for debugging a stuck node (2026-06-30, 8a8539a4, transcript).
- **Carry-forward race.** Fix is serializing pending→stale per (node_id, run_scope_id), NOT preventing multiple pending rows; any message landing in a running frame is a separate bug (DeliverPendingMessages must deliver only the frame's own triggering message) (2026-06-30, 8a8539a4, transcript).
- **Frame-failure hedge.** Assistant claimed an independent frame-failure mode and proposed a failure_reason column; ruled nonexistent — frame failure is a pure derivation from node_runs (2026-07-06, 3f71f90a, transcript).
- **Vocabulary: messages "landing" in frames** — wrong; they trigger them, same action (2026-07-03, 3f71f90a, transcript). **"Coupling"** for cross-frame messaging — wrong; nothing is coupled (2026-06-23, 10cf843b, transcript).
- **Message/node_run queue conflation.** Message-pool coalesce ("keep latest queued message") vs node cascade modes (node_run queue) must never be conflated; story most-recent-coalesces-cascades as written conflated them (2026-07-03, 3f71f90a, transcript). Cascade/event stories must not use frame or message vocabulary; the diff-gate's power is "no cascade occurs", never "no more frames open" (2026-07-03, transcript).
- Artifact-era precedents: the frame concept doc contradicted itself on parked-holds-frame-open and the code followed the wrong half — both drivers' predicates corrected to count parked (2026-06-03, artifact); the frame_resolution_mode column rename landed without sweeping SQL accessors — genuine bugs converged (2026-05-13, nomenclature-resolution, artifact); a message POSTed to a quiescent instance was never delivered — fixed in-transaction (2026-06-02, acceptance-coverage-recovery, artifact; the mechanism was later redesigned, but the never-strand-a-message expectation stands).

## Conflicts needing human ruling

- **RESOLVED 2026-07-14 (user ruling, transcript tier): retire the frame timeout entirely.** User rationale: "'timeout' seems wrong... most frames that do anything substantial will take minutes, maybe hours. so either downgrade it further or drop it and let operators set alert on frame progress in other ways. soft timeout seems like a blunt instrument and not that useful" — confirmed drop. Consequences: (a) `frame_timeout_ms` (template key, rimsky_frames column, the >=60000 CHECK, default/floor constants) and the stuck-frame warn sweep (`frame.stuck.observed`) are retired, erase-completely, no compat shim (pre-v1); (b) `last_progress_at` STAYS — it is the progress clock for orphan detection and quiet-period reaping and the raw signal for operator-side alerting via the frames/diagnostics surface; (c) a generalized alerting mechanism, if ever wanted, is a fresh spec over that clock — nothing from the retired timeout feeds it. Findings that assume soft-warning semantics or the 60s floor adjudicate as fix-code/fix-doc toward retirement, not restoration.
- **RESOLVED 2026-07-14 (user ruling, transcript tier): the park-timeout watchdog is retired.** Initially recorded here as "stays" by over-reading the park-vs-callback ruling; the user corrected same day: a park's duration is the executor's declaration and the scheduler fully controls the wake, so a "timeout" on park is a flat refusal to honor it. `max_park_duration`, the parked→failed sweep, and error_class `park_timeout` go, erase-completely; a park's sole exit is its own resume_at time-wake. Foundation now auto-remediates nothing — no frame timeout, no park watchdog; wedged-state visibility is diagnostics' job and remediation is the operator's, through ordinary terminal paths. (Full ruling text in the parked-state dossier.)
