# Intent Dossier: persistence-database

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner
history artifacts (2026-05-04..2026-06-11). Transcript tier outranks artifact tier;
later intent supersedes earlier. Part of the drift-remediation intent ledger.

## Net position

- Dual backend: Postgres for production, SQLite for dev/test, selected by config; both backends must behave identically wherever the runtime depends on them, proven by test (parity/conformance suites), not by review (2026-06-08, corpus-bootstrap, artifact; 2026-06-11, last-mile-stability, artifact).
- Pre-v1 the migration chain has no compat value: schema rethinks rewrite a single fresh baseline schema per backend (001-initial.sql) rather than appending compat migrations; dev databases are nuked and templates redeployed; upgrading a populated old-schema database is unsupported (2026-06-20, 8a3b8c19, transcript: "we don't see the point of these pre-v1. why not just start with a fresh schema definition?"; consistent with 2026-05-12/2026-05-17/2026-05-24 artifact flattenings).
- One persistence driver per process is a blessed invariant: role runners (scheduler, supervisor, control-api) accept an injected persistence.Database; every caller opens exactly once through the shared seam and owns the lifecycle (2026-06-14, f0176bde, transcript).
- Rimsky's binaries coordinate exclusively through the database: advisory locks (Postgres pg_advisory; SQLite flock-based) own the scheduler tick and migrations; cross-process signaling is DB polling, never a new IPC channel (2026-05-04, foundation-contract, artifact; 2026-05-24, instance-debugger, artifact; 2026-06-11, last-mile-stability, artifact).
- The persistence layer must not know about executor specifics — no executor-named tables; any executor state surface is generic and exposed through the protocol (2026-06-14, 752fe200, transcript).
- Node-run model: a single unified `state` column (seven states, incl. pending/parked/held), the phase column is gone; settled rows are immutable (invalidation creates a new stale row); rows carry `sequence` (monotonic per node/run-scope/frame) and `creation_reason` (cascade, operator_invalidate, policy_retry, infra_reenqueue) (2026-06-20, 8a3b8c19, transcript).
- Nodes carry no runtime state: EvaluatorState (retry counter, action index, current error class) is node_run-local and persisted on rimsky_node_runs; rimsky_nodes holds only template-derived identity and scheduling metadata, and its mutable frame_id column is removed (2026-06-22, 10cf843b, transcript; 2026-07-05, 3f71f90a, transcript).
- Frame rows: every frame carries a NOT NULL `triggering_message_id` (schema-level proof that no internally-created frame exists) and a `root_run_scope_id`; the stored `state` column is retired (running/completed/failed derived at read time from ended_at + node_run states); `ended_at` remains as the reaper's one-shot idempotency gate and one-open-frame-per-instance is a partial unique index WHERE ended_at IS NULL; the frame row is cascade-immutable — cascade processing stores no state in it, though bookkeeping writes (ended_at stamp, last_progress_at heartbeat) are sanctioned (2026-06-14, bfc9febb; 2026-06-30, 8a8539a4; 2026-07-05/06, 3f71f90a; all transcript).
- Attribute rows are the persistent record of what each node-run produced — per-run, keyed by node_run_id, explicitly not a cache; the node_run's persisted bag (initialized at dispatch from substitution) is the one and only attributes mechanism, with the dispatch-time input preserved separately in `dispatch_input_bag`, never overwritten by executor writeback (2026-05-20, attribute-pull-resolution, artifact; 2026-06-19/20, 8a3b8c19, transcript).
- Plaintext secrets must never land in the persisted attribute bag (2026-07-01, 8a8539a4, transcript).
- State-machine writes for a single run are tx-atomic (read-to-decide and write in one transaction) — a blessed invariant (2026-05-22, fan-out-safety-scope-first, artifact). UpdateState takes a node_run_id and transitions that row directly; ambient (node_id, run_scope_id) lookups, state-priority sorts, and cross-frame fallbacks are deleted (2026-07-05, 3f71f90a, transcript).
- The async-callback registry is persistent on the dispatch row (rimsky_node_runs.async_ack_id + async_ack_registered_at, unique partial index), registered in the same transaction as the transient/await_async emit; in-memory caches are read-through only; callbacks survive supervisor restart and are rejected for already-terminal runs (2026-06-17, b31002b8, transcript).
- Whether a frame is unresolved is derivable from node_run states alone — no additional persisted state (2026-07-05, 3f71f90a, transcript).

## Required behaviors (open promises)

Backend parity and drivers:
- The claimant-guard predicate (blessed-invariant 4) is written exactly once per driver via an internal helper all guarded mutations route through; a driver-parity conformance suite proves on both backends that wrong-supervisor mutations change nothing (2026-06-11, last-mile-stability, artifact).
- The driver-parity suite extends until every queue, claim-handle, and frame behavior the runtime depends on has a both-driver test: "two ~10k-line hand-mirrored drivers drift; parity by test beats parity by review" (2026-06-11, last-mile-stability, artifact).
- SQLite is safe for multiple rimsky processes sharing one DB file: read-then-write sites are transactional (immediate mode), tick/migration locks are flock-based; deliberately no startup gate ("gating a deliberate config choice is not this platform's policy"); separate files per process and network filesystems stay unsupported (2026-06-11, last-mile-stability, artifact).
- sqliteMaxOpenConns is 8 (raised from 1, which let one long transaction block every Begin) (2026-06-14, f0176bde, transcript). Legacy MaxOpenConns=1 deadlock avoidance patterns remain precedent: in-tx table methods must exist where calls happen inside open transactions (ListDeliveredForFrame, 2026-05-29, console-upstream-auth, artifact; invalidateInFrame resolve-outside/mutate-inside, 2026-05-22, fan-out-safety, artifact).
- One-driver-per-process is structurally asserted (TestStartUnifiedStack_OneDriverAcrossRunners pointer-identity test) (2026-06-14, f0176bde, transcript).
- Scenario/behavior tests run against real Postgres testcontainers; the cycle cost is accepted (2026-06-20, 8a3b8c19, transcript). Persistence test packages run with t.Parallel(); persistence is excluded from the -race -count=3 slice (keeps -race -count=1) (2026-06-21, 21306ffe, transcript).

Self-host / one-shot persistence:
- One-shot runs reuse the SQLite backend (no third in-memory backend — maintaining a third conformance implementation rejected) (2026-06-13, 65667e33, transcript).
- One-shot persistence is not operator-visible configuration: no new driver or config key; the CLI configures the launcher internally (2026-06-13, 65667e33, transcript).
- One-shot runs persist to a file-backed SQLite DB under a .rimsky folder; the in-memory-only option is dropped — the file is a post-run audit artifact openable with stock sqlite3 (.rimsky/latest/state.db + filesystem blob backend at <runDir>/blobs) (2026-06-13/14, 65667e33/f0176bde, transcript).

Schema and row semantics:
- Non-cascade creation paths (operator-invalidate, policy-retry, infra-reenqueue) create rows directly as stale with the carry-forward bag built at creation; immune to cascade-mode rules; never walker accumulation targets; the serialization gate (no other run for the node/run-scope in running/held/parked) lives at the dispatcher claim site; sequence ordering means operator invalidates do not jump the queue (2026-06-20, 8a3b8c19, transcript).
- The policy-evaluation cursor is persisted on the node_run row so policy-cap accounting survives supervisor crashes (2026-06-22, 10cf843b, transcript).
- Attribute-diff baseline when no prior run exists in the RunScope is the empty bag — a first run emits attribute-changed for every key (initial values must wake subscribers); prior-run data is loaded at settle time from existing per-run rows, no new column (2026-06-22, 10cf843b, transcript).
- Claim-handle payload persists on ALL claim rows (regular and sub-claims) for a uniform path surviving retries and co-holder reads past the acquire tx; sub-claims inherit the parent's declared intent — the hardcoded "rw" was a bug (2026-06-18, 9fb55f08, transcript; 2026-06-10, cascade-and-claim-handoff, artifact).
- Effective dispatch deadlines are denormalized onto node_runs (effective_max_quiet_period_seconds, effective_max_runtime_seconds) at RegisterAsyncAck time so the sweep does one indexed scan (divergence accepted as-is by the user) (2026-06-17, b31002b8, transcript).
- AffirmNodeRunRow stays a lazy, narrow INSERT-if-no-in-flight primitive; callers must not depend on its return shape beyond error/no-error (lazy↔eager allocation must remain a no-op rewrite) and read the row separately (2026-05-22, fan-out-safety-scope-first, artifact).
- All persistence methods key on a required runScopeID; the legacy runID disambiguator and nil escape hatches are gone; partition lookups use the two-step GetFanoutPartition → GetInFlightRunForNode pattern (2026-05-22, fan-out-safety-scope-first, artifact).
- Deleting an instance drops everything beneath it — the drivers cascade through the run-scope tree at runtime because the FKs lack ON DELETE CASCADE (2026-05-22, fan-out-safety-scope-first, artifact).
- Wait-set: the persisted per-frame ledger drives dispatch eligibility, one drain rule per (frame, sender); SelectCandidates carries the NOT EXISTS undrained-wait-set gate (2026-05-14 + 2026-05-20, subscription-cascade-qol / attribute-pull-resolution, artifact); topic_kind 'message' is retired — the wait-set records only within-frame edges (2026-06-15, 91ec93d1, transcript).
- Once-per-frame dispatch guard (HasRunForNodeInFrame + intra-terminal visited set); self-edges intentionally bypass the cross-terminal guard so drain-my-own-queue idioms work (2026-05-23, signal-taxonomy, artifact).
- Blob spill: values above persistence.blob.spill_threshold_bytes (default 64KB) transparently spill to the configured BlobBackend; reads are transparent; a backend-mismatch read falls back to the inline column rather than erroring (2026-05-08, platform-extensions, artifact).
- SelectCandidates locks only the node_runs rows (FOR UPDATE OF d SKIP LOCKED) — never the joined instance row (2026-05-24, instance-debugger, artifact). SetPaused uses SELECT FOR UPDATE then UPDATE in one tx so racing pausers keep the 409 distinction (2026-05-24, instance-debugger, artifact).
- Retention: run-tree/lineage sweeps are wired into the scheduler tick and on by default; the per-instance trace (frames + node_runs + event logs) is one thing under one policy — reaped when older than cfg:retention.trace_trailing (default 30d) OR beyond cfg:retention.recent_frames_kept (default 100), whichever retains less; either dimension alone must reap; in-flight frames (incl. parked-held) are always exempt; event logs are time-keyed only; explicit 0 disables a dimension, absent key gets the default, negative rejected (2026-06-02 + 2026-06-03, rimsky-core-remediation / instance-lifecycle-durable-by-default, artifact).
- Audit query surface rejects un-indexed ?target= filters with 400 rather than silently full-scanning (reject-don't-degrade posture) (2026-05-29, console-upstream-auth, artifact) (artifact-only).
- Table-access house pattern: every table method takes a nullable Tx; Tables.Transaction is the wrapper; injected clocks where middleware needs per-request time (2026-05-15, control-plane-mcp-and-auth, artifact).
- Naming: tables plural (rimsky_node_runs, rimsky_claim_handles, ...), Go row structs singular; the umbrella vocabulary is Database → Tables() → per-row-type <RowKind>Table accessors; Config.Driver stays as the adapter-selector string (2026-05-12/13, nomenclature-resolution, artifact).
- Breakpoint hits carry both seq BIGSERIAL (pagination cursor) and id UUID (API identity), instance_id denormalized (2026-05-24, instance-debugger, artifact) (artifact-only).
- testpg lives as its own opt-in test-only module carrying the testcontainers+pgx deps; pgmigrate is test scaffolding under test/support, not a migration runner (2026-05-26 + 2026-05-27, collapse-sdk-into-protocols / root-folder-reorg, artifact).

## Intentional absences

- Numbered append-only migration history as a compat surface — pre-v1 there are no incremental compat migrations; the 15 accumulated migrations were deleted for a fresh baseline (2026-06-20, 8a3b8c19, transcript). Earlier flattenings (001-baseline 2026-05-12; direct baseline edits 2026-05-17; consolidated 001-schema 2026-05-24) are the same policy.
- An in-memory persistence backend as a third peer of postgres/sqlite — rejected (conformance maintenance cost); ephemeral-by-default one-shot state also dropped in favor of the kept file (2026-06-13, 65667e33, transcript).
- The phase column and the state×phase product on node runs — collapsed into one state column (2026-06-20, 8a3b8c19, transcript). (Makes the 2026-05-04 phase='completed'-never-emitted divergence moot.)
- rimsky_frames.state stored column and its CHECK constraints — retired; derived at read (2026-07-06, 3f71f90a, transcript). The initially-approved option that would have retired ended_at entirely was walked back — ended_at stays as bookkeeping (2026-07-06, 3f71f90a, transcript).
- instance.MainRunScopeID (singleton per-instance main runscope) — removed; each frame owns a fresh root RunScope (2026-06-30, 8a8539a4, transcript). This also retires the mutual deferrable-FK arrangement built for it (2026-05-22, artifact).
- rimsky_nodes.frame_id and every trace of cross-frame state on node identity rows (2026-07-05, 3f71f90a, transcript); EvaluatorState columns on rimsky_nodes (2026-06-22, 10cf843b, transcript).
- frame_delivery_mode column and the queued-coalesce partial uniqueness index — dropped with coalesce retirement (2026-06-14, bfc9febb, transcript). source_node_ids on frames — retired as derivable (2026-06-14, bfc9febb, transcript).
- A stored `kind` column on rimsky_run_scopes — declined; derivable (2026-05-22, fan-out-safety, artifact).
- Executor-specific tables (e.g. a pending-timer table) — declined on principle (2026-06-14, 752fe200, transcript).
- A SQLite path in the scenario-test harness — declined; Postgres testcontainers, pay the cycle cost (2026-06-20, 8a3b8c19, transcript).
- Wait-set topic_kind 'message' and the message/<...> subscription taxonomy — retired; cross-frame blocking on message arrival is forbidden (2026-06-15, 91ec93d1, transcript).
- A sidecar table for the park-resume attribute snapshot — declined; the existing per-run bag is the snapshot (2026-06-19, 8a3b8c19, transcript). The parked_payload_*/session_token/wake_reason columns are dropped with the resume-context channel (2026-06-17, b31002b8, transcript).
- A claimant guard on sqlite UpdateNodeRunID — deliberately omitted, matches postgres, sanctioned by a conformance carve-out test; the drift finding claiming it missing was refuted (finding 1215) (2026-07-13, 3f71f90a, transcript).
- rimsky_migrations / rimsky_named_locks as authored baseline tables — never existed; rimsky_migrations is bootstrapped by the driver; the plan listing them was in error (2026-05-24, instance-debugger, artifact).
- GetByParentChildKey and the old fanout-disambiguator conformance tests — structurally removed/retired, inexpressible under (node_id, run_scope_id) keying (2026-05-22, fan-out-safety, artifact).
- GetLatestRunInScope and other ambient-lookup shapes, the state-priority sort, and the cross-frame failed-state fallback in UpdateState (2026-07-05, 3f71f90a, transcript).

## Corrections and restorations (drift-fight record)

- Each role runner independently calling persistence.Open in unified mode (three drivers contending for the sqlite writer slot) contradicted the design; corrected to one shared injected driver, then hardened into the blessed invariant + structural test (2026-06-13/14, f0176bde, transcript).
- Retention sweeps were dead code — implemented but never invoked by the tick, and the retention: config never parsed, which also stranded the claim-handle and message-idempotency sweeps; wired, plumbed, defaulted-on (2026-06-02, rimsky-core-remediation, artifact).
- rimsky_messages.sender_kind CHECK left as ('operator','sensor','instance') while the wire handler enforced ('operator','publisher') — inserts would fail the CHECK; a swept-every-surface-but-the-baseline miss (2026-05-17, sensor-messaging-unification, artifact).
- Baseline rename landed without sweeping SQL accessors: frames.go readers still read legacy column names after the frame_resolution_mode rename — "genuine bugs" converged across both drivers (2026-05-13, nomenclature-resolution, artifact).
- SQLite park-resume silently broken (TEXT scanned into sql.NullTime, error swallowed); fixed with NullString+parseTime, regression test, and a tree-wide audit for other sql.NullTime uses (2026-05-08, platform-extensions, artifact).
- Retry-no-progress counter reset to zero on every retry (delete-and-reenqueue lost the count); cap never tripped; carried-forward count now set in the re-enqueue transaction (2026-05-08, platform-extensions, artifact).
- The CTE-based SetPaused hid the 409 already-paused race (statement-snapshot prior-value read); replaced with SELECT FOR UPDATE + UPDATE (2026-05-24, instance-debugger, artifact).
- Postgres partial-index predicate with NOW() is invalid (STABLE, not IMMUTABLE); shipped index predicate narrowed and time filters applied at query sites (2026-05-24, instance-debugger, artifact).
- Match-counter increment SQL diverged from plan for correctness: chained jsonb_set on one path collapses increments; aggregated per unique index in Go; the plan's ->> text-cast array indexing would not have worked (2026-05-21, attribute-overrides-matcher-overlay, artifact).
- 30+ ambiguous WHERE node_id callsites returning arbitrary rows under fan-out motivated the RunScope-first reshape — the bolted-on data model was the root cause (2026-05-22, fan-out-safety, artifact).
- A git-checkout misstep silently reverted driver.go / worker_requests.go / the sqlite initial migration mid-refactor; hand-reconstructed — flagged as a potential drift origin for those files (2026-05-04, layer-crystallization, artifact).
- The sqlite migration-021 data-loss bug was fixed with a falsifiability-checked regression test; mechanical review findings are fixed without per-item discussion, judgment items walked with the user (2026-07-06, 3f71f90a, transcript).
- The planned tags-column migration test (default empty array + GIN index existence) never landed — a known unclosed assertion gap (2026-05-19, multi-instance-template-ergonomics, artifact) (artifact-only).
