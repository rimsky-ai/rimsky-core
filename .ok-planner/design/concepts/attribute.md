# Attribute

## What it is

Attributes are the typed inputs, outputs, and configuration of a node, declared by a schema in the template's attributes block. Each schema property is one of three shapes: source-bound (a substitution directive resolved at the moment the node-run's persisted bag is built, per `concept:node-run`), static-default (a default value resolved at registration), or executor-written (populated at commit by the executor; marked read-only in the executor's expected-attributes schema). Persisted writeback lives on the per-run attribute ledger. Validation runs twice (dispatch post-substitution + commit post-writeback).

## Purpose

Attributes give nodes a typed, validated contract for their inputs and outputs. The substitution grammar lets downstream nodes consume upstream outputs and live claim payloads without rimsky understanding the data; the schema gates catch shape problems on both sides.

## Boundaries

Owns: the schema, the substitution grammar, the three property shapes, the override merge layers L1 through L5 — L1 template `by_executor` defaults, L2 node schema declaration, L3 instance `by_executor` override, L4 instance `by_node` override, L5 `by_match` matcher/overlay entries — the two validation gates, the writeback ledger. A further L6 one-shot resume overlay applies after this concept's L5 merge and is owned by `concept:breakpoint`. Does NOT own: claim payload (lives on `claim`), assets (assets are claims, not attributes — see `concept:asset`), semantic validation (there is no separate semantic-validation concept; the verifier-executor pattern, a co-holding verifier node that runs shape checks, covers that surface). Adjacent: `node`, `inertness`, `asset`, `terminal-tag`, `breakpoint`.

An attributes delta is carried on the two run-terminating executor verdicts — `terminal/success` and `terminal/error/<class>` — and is committed atomically with the verdict in the same persistence transaction. The delta also appears in the emitted signal payload so subscribers can predicate over `payload.attributes_delta` via CEL. Alongside the verdict channel, a long-running executor may post incremental attribute writebacks mid-dispatch through the supervisor's callback surface: each writeback merges a delta onto the run's own per-run attribute row and bumps the run's progress timestamp in the same transaction — a genuine writeback is itself a liveness signal (see `decision:writeback-bumps-progress`). Mid-dispatch writebacks touch only the in-flight run's own row (never a settled row, never another run's row), emit no signals, and never fire cascade — cascade-visible attribute changes ride only the settling verdict. Park (`transient/park/*`) is dispatch-internal — it ends a dispatch but not a run — and does not write attributes; an executor that needs to thread state across a park-and-resume boundary uses scratch (see `concept:parked-state`), and the executor's next run-terminating verdict after the wake is the next opportunity to settle the attribute row. Async executors with no attribute updates signal liveness via the dedicated keepalive endpoint without touching the attribute bag (see `decision:keepalive-endpoint`).

Clarifying note: attributes are typed node I/O; assets are claims with `lifetime: durable` against a data-processing-capable producer. Templates author both side-by-side — attributes for transient run inputs/outputs, assets for durable datasets. Don't conflate.

Clarifying note on arity: per-field substitution is 1:1 by design — one `source:` directive names one value. Multi-upstream fan-in is the cascade vocabulary's job, expressed through `concept:node-subscription` (N upstreams per receiver) and optional schema fields (the dispatch path omits non-required fields on a missing source). The arity asymmetry is load-bearing — see the per-field-arity invariant.

Clarifying note on subgraph sealing: subgraphs are sealed. Internal nodes can read from siblings of the same invocation, the calling node's attributes, and the always-available source kinds (`params`, claims, delivered messages by type, `child.partition_key`, host-environment variables) — but not from upstream nodes in the calling graph by free reference. The calling graph's namespace is not visible inside the subgraph. Authors thread calling-graph state through the calling node explicitly.

Cascade-shape configuration tied to a substitution ref is declared on the receiver's subscriptions via the per-edge upstream-refresh flag. The substitution grammar carries no cascade-shape tokens.

## Non-goals

Patterns considered carefully during platform design and **decided against** — positions, not deferrals.

- **Cross-frame attribute caching.** A `{{nodes.X.attribute.Y}}` read at receiver R's dispatch resolves only against the X-run pinned as R's upstream sender at enqueue time (the wait-set entry's sender-run identity, fixed within this frame), read once that run settles. Reads of X-runs from earlier frames return a missing-source error. The per-run attribute rows are the persistent record of what each node-run produced — not a cache. **No mechanism in rimsky (substitution, diff-gate, cascade-mode, or any other runtime path) reads an attribute row from a prior frame while making a decision in the current frame.** State that must travel across frames belongs in the message payload (the sole cross-frame carrier — see `concept:frame`), in `params`, in claim payloads, or in threaded subgraph inputs.
- **Function-form substitution grammar.** No `{{coalesce(X, Y)}}`, `{{newest(X, Y)}}`, `{{merge(X, Y)}}`, or other in-grammar functions. The grammar stays a closed enumeration of source-kind directives plus an optional literal fallback. Aggregation and transformation logic lives in receiver executors, not in the substitution layer.
- **Multi-pipe fallback chains.** A single directive admits at most one `| <literal>` fallback. Multi-directive chains (`{{X | Y | Z}}`) and composite literals (`{}`, `[]` as fallbacks) are not admitted. Per-directive `?` marker and `| <literal>` fallback are mutually exclusive (incoherent: `?` says null on missing, `|` says literal on missing — pick one).
- **Closure semantics for subgraphs.** Subgraph internal nodes cannot read attributes from upstream nodes in the calling graph by free reference (see Boundaries above). Calling-graph state threads through the calling node explicitly.
- **`force_fresh: true` (always-re-execute) and `trigger_if_missing: true` (lazy upstream initialization).** These flags do not exist. Authors expressing "re-execute on every dispatch" structure templates around explicit invalidation rather than a per-read flag, and authors expressing "lazy upstream initialization" use the cascade's proactive-upstream-pull mechanism declared on the receiver's subscription.

## Invariants

- Validation gates twice: dispatch (post-substitution) and commit (executor writeback). Both mandatory (invariant 12).
- The substitution grammar is a closed enumeration of source kinds covering upstream-node attributes, co-held claim fields, instance params, delivered-message payloads addressed by type (any message delivered to the frame, not only a triggering one), the per-child partition identifier, and host-environment variables (read from the supervisor process's environment during the substitution round that resolves them, scalar string values, name shape `[A-Za-z_][A-Za-z0-9_]*`, unset is a missing source). Per-emission data rides on the send-node's attributes delta and is read via the upstream-node source kind. Each path-walking kind admits an optional-empty trailing path; with an empty trailing path the directive resolves to the kind's JSON root. Resolution is either whole-directive (the input is exactly one directive modulo whitespace; returns the value verbatim) or embedded (the input has literal text alongside directives; stringifies and concatenates). The grammar also admits a per-directive literal fallback returning the directive's value if present, else the literal (a JSON scalar). Multi-directive chains and composite literals are not admitted. Out-of-grammar references are rejected at registration.
- Errors omit value bytes (cite path tokens only) to preserve invariants 20/21.
- Attribute storage is per-run, keyed by the node-run identity (a cascade-deleting foreign key to the node-run row). A denormalized node-id column supports forensic / observability lookups by latest-per-node; the substitution path looks up by run against the specific upstream sender runs pinned to the receiver's wait-set entries at enqueue time (each entry fixes which run to read; the wait-set entry itself carries no attribute data), read once each pinned run settles.
- Substitution for cascade-driven rows runs in two rounds on one code path, each committed in its own transaction (see `concept:node-run`). The first round, at the gate evaluator's pending→stale transition, resolves every source kind against the context available at that point and persists the resulting bag; a claim- or child-scoped reference not yet resolvable there (the claim isn't acquired yet) is deferred rather than failed. The second round, immediately before dispatch, resolves the deferred claim- and child-scoped references against the acquired claim context and persists the completed bag; the dispatcher then loads this persisted bag by run id rather than re-reading sender attributes. Substitution failures (missing-source, schema-validation) are classified and applied to the receiver's `template_resolution_failed` error-class policy in the same transaction as the round that produced them — for the first round that is the sender's settle transaction (so the sender's terminal apply commits regardless of the receiver's substitution outcome). Message-delivery rows are not substituted at all: the delivered payload is copied verbatim onto the receiver's row as both its attribute bag and its dispatch input bag, with no schema-defaults or substitution pass (see `concept:message`).
- Substitution reads are scoped to the current frame. A `{{nodes.X.attribute.Y}}` directive resolves to the X-run pinned as the sending upstream at enqueue time (always within this frame); reads of X-runs from earlier frames return a missing-source error. The per-run attribute rows are the persistent record of what each node-run produced — not a cache; the runtime never reads them across frame boundaries. State that must be available across frames rides on the message payload (the sole cross-frame carrier), or on `params`, claim payloads, or threaded subgraph inputs.
- Every new frame's root RunScope starts fresh. No prior node-runs of any node exist in a new frame's root RunScope at frame open; the first dispatch of any node inside that scope uses schema-default values. Carry-forward across a frame boundary is impossible by construction, not by convention: RunScopes never span frames (`concept:run-scope`), so "the prior run in the current scope" is always intra-frame.
- Signal-emission decisions (the `attribute/<key>/changed` diff-gate, `cascade_mode` bag-equality dedup, and any other cascade / gate decision) consult only attribute rows produced inside the running frame. Persisted rows from earlier frames are audit-observable but never read by the runtime.
- The `attribute/<key>/changed` diff-gate is same-RunScope-only: it compares a run's final bag against the most recent prior run of the same node in the same RunScope. For a scope's first run of a node, the baseline is the schema-default bag, not an empty bag — a first run that writes exactly its schema defaults fires no `attribute/<key>/changed` signal; a key that is missing from the defaults and then appears, or a key whose value differs from its default, fires. This keeps the diff-gate consistent with the fresh-scope-defaults guarantee: a key only reads as "changed" when it actually diverges from its initial value, empty or defaulted.
- A per-field substitution source admits literal text and one or more directives. Each directive resolves independently against its source kind. Per-directive strict-default with an opt-in lenient marker. Lenient missing rendering depends on resolution mode: in whole-directive mode the directive lifts to a null value; in embedded mode the directive contributes the empty string so the surrounding template still concatenates cleanly. The lenient marker is mutually exclusive with the literal-fallback operator. Multi-source array forms and multi-pipe chains are not admitted. Many-to-many fan-in across upstreams lives in the cascade vocabulary (subscriptions over multiple senders, plus optional schema fields whose dispatch-time missing-source is silently omitted by the schema-substitution path). Enforced at registration by the template validator (rejects the declined forms). The arity asymmetry between subscriptions (many-to-many) and per-field substitution (1:1 per directive) is intentional: subscriptions sum signals across upstreams; substitution names a single value per field. Per-directive composition within a source string concatenates, it does not sum.

- Each property has at most one of a source binding or a static default. Each property satisfies one of: has a source binding, has a static default, is marked read-only in the executor's expected-attributes schema (executor writeback populates at commit), or it is a property the executor does not enumerate, under an executor schema that does not constrain it — either the executor declares no enumerated properties block (a fully permissive schema), or it declares its additional-properties hook in a non-closed form. In both cases the executor has delegated naming authority for unenumerated properties. Properties failing all of these checks are rejected at registration, or at dispatch if the executor's schema wasn't visible at registration time. The registration-time check soft-fails the read-only fallback leg when the discovery cache hasn't populated yet (no hook wired, executor not yet handshaked, or executor advertises no schema) — under those conditions, runtime dispatch reapplies the rule once the schema is visible. Enforced by the template validator at registration and at dispatch.

- The template-author L2 declaration cannot mark a property read-only that the executor's schema does not also mark read-only. Rejected at registration. The executor is authoritative on which of its attributes it produces vs consumes. The same open-schema carve-out applies: an unenumerated property under an executor schema that does not constrain it may be author-marked read-only, since the executor has delegated naming authority for unenumerated properties. Enumerated properties remain fully checked.

- A fifth override layer (L5) extends the four-layer merge: an ordered list of matcher/overlay entries declared on the instance's attribute overrides. The matcher predicate is equality-only over a fixed key set; evaluated against the dispatch context at runtime; missing keys are wildcards; AND across present keys. Each matching entry's overlay folds on top via a recursive deep-merge in declaration order — later entries win. An empty matcher matches every dispatch. The matcher reads from the post-L4 merged bag (overrides applied through L4 are visible to the matcher). Ordinal-shaped matcher keys and expression-shaped values are rejected at registration. Enforced by the override validator at registration and the runtime override applier at dispatch.

- A sixth override layer (L6) applies after this concept's L5 merge: a one-shot resume overlay owned by `concept:breakpoint`, never persisted into the instance's stored overrides. See `concept:breakpoint` for its mechanics.

## Self-state carry-forward

On each dispatch of node X in RunScope S, the attribute bag is hydrated from the most-recent prior node-run of X in S (a JOIN of the per-run attribute ledger with the node-run rows, ordered by recency for (node, scope)), then per-field `source:` substitution overlays on top. First dispatch of X in S uses the schema's static-default values. Executor-written `readOnly: true` properties carry forward unchanged unless overwritten by a subsequent executor writeback.

Carry-forward is bounded by the RunScope, and RunScopes never span frames (per `concept:run-scope`, `concept:frame`). So carry-forward is intra-frame by construction: it copies the previous cascade round's bag into the next cascade round's bag within the same frame. When a new frame opens, its root RunScope is freshly created and contains no prior node-runs of any node — the very first dispatch of X in that new root scope uses the schema's static-default values, exactly as if it were the first-ever dispatch. There is no "prior frame's bag" for the new frame to hydrate from; there is no path in the persistence layer that would supply one. Cross-RunScope hydration is forbidden in every direction (sub-graph and fan-out RunScopes start with schema defaults; new frame root RunScopes start with schema defaults). Self-state carries via copy within one RunScope; cross-node values within a frame flow via substitution; cross-frame values flow via message payloads (per `concept:frame`). The three channels are orthogonal and operate on different sources.

The canonical stateful-property pattern for a receiver reading its own prior work within one frame's cascade rounds is `readOnly: true` plus executor writeback; carry-forward is its expected behavior. Authors expecting state to persist across frames explicitly thread it through the message payload — no persisted attribute row is ever consulted across a frame boundary.

Clarifying note on when defaults materialize: the fresh-scope defaults guarantee is realized in two steps, not one. At row creation the per-run attribute row is written with an empty bag — there is no prior run in the scope to copy, and schema defaults are not materialized at this moment. The effective bag — schema defaults overlaid by resolved substitution sources — is computed and persisted at the substitution moment (see the substitution-timing invariant above): for cascade rows that is the pending→stale gate transition, so a pending row's ledger entry reads empty until its gate fires; for a non-cascade row created by message delivery, the payload is copied verbatim as the bag in the row-creation transaction with no defaults or substitution pass; other non-cascade row creations (operator-invalidate, policy-retry, infra-reenqueue) carry forward the previous run's bag verbatim rather than recomputing from defaults. Execution-time behavior always matches the guarantee — no dispatch ever runs against the empty bag — but a reader inspecting the raw ledger row of a not-yet-gated run sees an empty bag, not the defaults. Do not read the ledger expecting defaults to be present before the substitution moment.

## Static-default properties

A schema property declared with a static default and no source binding is a static-default property. Its value is set from the effective schema at registration; instance-level executor-keyed and node-keyed overrides replace the default at dispatch.

Static-default properties carry per-node executor configuration (model selection, command-line flags, fixed prompts) declared by template authors and overridable by operators at instance time. The substitution grammar does not apply to default values; an operator-supplied directive-shaped string in an override is a literal string.

Static-default values are persisted per node-run alongside source-resolved and executor-written values on the per-run attribute ledger, providing dispatch-time forensic clarity. Template-default mutations do not retroactively rewrite history.

## Matcher overlay

A third routing dimension on the attribute overrides, alongside the static executor-keyed and node-keyed maps. It is an ordered list of matcher/overlay entries where the matcher is a content-keyed predicate over dispatch-time identity — solving the problem that static routes can't differentiate among children of a fan-out node that share node type and executor.

The matcher grammar is intentionally small: equality only, over a fixed key set. The per-child partition-identifier key is the recommended anchor for fan-out routing (the producer-emitted per-sub-scope identifier from `concept:fan-out`, stable across dispatch reorderings); attribute-path matching covers non-fan-out differentiation. Ordinal-style addressing (any "third call" / "index N" semantics) is rejected at registration: matchers address partitions by identity, never by execution order.

The per-child matcher key sources its value from the dispatched run's RunScope's partition key (per `concept:run-scope`); the equality semantics and ordinal-rejection vocabulary are fixed. Non-fan-out dispatches see an empty per-child key (the parent / sub-graph RunScope's partition key is empty).

Override values are static — no substitution applied. The matcher reads from the post-L3+L4 bag, meaning earlier-layer overrides are visible to the matcher's attribute-path comparisons.

Per-entry match observability is event-derived: each match emits an operational event at dispatch time. Operators and tests read match counts aggregated from the event log at read time and assert on which entries fired. Entries that never match report a zero count — the "silent miss becomes loud miss" discipline that makes matcher-overlay testing safe against producer key-scheme changes.
