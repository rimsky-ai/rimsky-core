# Twenty traps the corpus has no opinion on: align each to what a user expects

## Problem

`/document` at release `d977250c` recorded 70 traps at `.ok-planner/documentation/traps/`. A trap is a belief a user plausibly forms from the public surface. An experiment contradicted each one. A triage on 2026-08-23 (`.ok-planner/workbench/2026-08-23-trap-triage.md`) read each trap against the design corpus. For the 20 traps below, no decision, concept, or story speaks to the measured behavior. The fix changes no product behavior and no design artifact. No one chose the behavior. The corpus gives no reason for the surprise. On 2026-08-24, 18 further silent traps moved to `issue:ruled-traps-inspect-the-decisions`, because their fixes change product behavior or the corpus.

The table gives, per trap, the belief the user holds and the behavior the tree shows today. The triage's evidence column names the code sites.

## Candidates

- Make each behavior match the user's belief, and record no decision: the belief was the sensible default all along.
- Keep a behavior where a reason emerges during the work, and write that reason as a decision so the corpus is no longer silent.

## Ruling

Fix every one of the 20 to match what a user expects. The belief in the table is the target behavior. Where the work uncovers a real reason to keep the current behavior, that reason becomes a decision in the corpus instead of a fix. The owner ruled live on 2026-08-24, and directed that this work precedes the review of the 40 traps in (`issue:ruled-traps-inspect-the-decisions`).
