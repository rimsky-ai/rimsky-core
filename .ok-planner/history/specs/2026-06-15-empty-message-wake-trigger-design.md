# Empty-message wake trigger and synthetic-envelope retirement

This spec retires the runtime-synthetic-envelope mechanism in favor of message-driven cascade through typed messages, including a runtime-managed implicit empty-message type that wakes every structural root. Three operator-facing surfaces narrow as a consequence: instance-create becomes idle, the asset-materialize endpoint retires, and the node-reset endpoint trims to a pure retry-budget clear. The scenario test harness's `InvalidateNode` helper migrates off the synthetic-envelope path onto the debug-channel surface. The unifying principle: no direct-node-targeting outside the debug-channel surface; invalidation flows through typed messages exclusively.

## User outcomes

### STORY-instance-create-is-idle

As an operator, I can create an instance of a deployed template and have nothing happen as a side effect, so that "creating an instance" and "invoking work on the instance" are separate operator actions I drive independently.

**Acceptance:** I `POST /instances` with `{template, instance_key?, params, attribute_overrides?}` against a deployed template. The instance row appears in `GET /instances/{id}` with `paused: false` and no terminal timestamp; the instance's frame collection (returned by `GET /instances/{id}/frames`) is empty; the instance's message ledger (returned by `GET /instances/{id}/messages`) is empty; no node-runs exist yet; the lifecycle-subscriber's `OnInstanceCreated` callback fires once. The supervisor does not dispatch anything for this instance until a sender posts a message.

**Falsifier:** the create call returns success but a frame row exists for the instance with no operator-posted triggering message; OR a synthetic envelope appears in the message ledger immediately after create; OR a node-run row exists with no operator emission having occurred.

**Proof:** executable proof — `POST /instances` followed by `GET /instances/{id}/frames` and `GET /instances/{id}/messages` returning empty collections; one lifecycle-subscriber callback recorded.

### STORY-empty-message-wakes-roots

As an operator (or publisher) of a live instance, I can send an empty message to wake every structural root of the template without crafting a typed envelope, so that "start the default work" is a first-class one-call operation that uses the same path every other message does.

**Acceptance:** I `POST /instances/{id}/messages` with an empty body (`{}`, or with `type: ""` explicit) and an `Idempotency-Key` against a live (unpaused) instance. A frame opens with `triggering_message_id` pointing at the empty-message envelope; every structural root — every node in the template whose author-declared `subscribes:` block is empty or absent — stale-marks in that frame and becomes dispatch-eligible; the frame proceeds through dispatch and settles as any other message-triggered frame does. A replay of the same emit with the same `Idempotency-Key` returns the original `message_id` with `200 OK` and opens no second frame. N empty messages with distinct keys produce N frames, each waking the roots.

**Falsifier:** the empty-message emit lands in the ledger but no frame opens; OR the frame opens but no structural root stale-marks (no node-runs created); OR a non-root node with author-declared *direct* subscriptions (a `subscribes:` entry naming a specific upstream node-type, not the cross-cutting `instance: true` form) also stale-marks (the trigger overreaches); OR `Idempotency-Key` replay opens a second frame. Cross-cutting (`instance: true`) subscribers may legitimately fire when their `when:` predicate matches the empty-message virtual's `terminal/success` emission; their firing is not a falsifier.

**Proof:** executable proof — emit empty message; observe one new frame with `triggering_message_id` matching the emit; observe stale-mark and dispatch on each structural root; observe non-root direct subscribers untouched (and cross-cutting subscribers fire iff their predicate matches); replay with the same key observes the original message id and no second frame.

## Technical decisions

**TD-empty-message-as-root-trigger** — The empty `""` type-path is the universal root-trigger mechanism, declared implicitly in every template.
**Choice:** at template registration, the runtime seeds an implicit `""` entry into the per-template declared-types set (the map `code:lib/runtime/subscription_loaders.go::templateDeclaredMessageTypes`, populated lazily by `declaredMessageTypesForTemplate` from the template's `messages:` block). The entry carries a null body schema (no fields, no substitution surface). An author-declared `messages:` entry of type `""` is refused at registration as reserved-for-runtime.
**Rationale:** collapses the four prior runtime-synthetic envelope types onto the typed-message path; the receipt handler stays uniform with no `type == ""` branch; the cascade walker, the substitution validator, and the dead-letter audit all treat empty as just another type.
**Alternatives:** a dedicated control endpoint (`POST /instances/{id}/wake`) — rejected because it would re-introduce a parallel non-message wake path; a receipt-handler special-case branch on `type == ""` — rejected because the runtime branch named for a specific case is the kind of asymmetry the spec is otherwise trying to retire.

**TD-structural-root-edge-injection-at-registration** — The inverse-edge map is augmented at template registration with structural-root edges keyed by sender=`""`.
**Choice:** `code:lib/graph/node/subscription_edges.go::BuildSubscriptionEdges` identifies structural roots (template nodes whose `subscribes:` block is empty or absent) and adds one entry per root receiver to the per-template inverse-edge map, keyed by sender=`""`, with `wake_on_change: true`, `force_upstream_refresh: false`, and a type-pattern matching `terminal/success`. The augmented map remains process-globally cached in `code:lib/runtime/subscription_loaders.go::templateSubscriptionEdges`, immutable per template_hash.
**Rationale:** structural roots are fully template-determinable — `attribute_overrides`, `params`, and `late_bind_services` do not change subscription topology — so per-instance storage would be gratuitous redundancy. The augmentation lives on the runtime's derived in-memory map; the canonical template hash is over the spec bytes only and is unaffected by the derived view.
**Alternatives:** per-instance overlay (new column on `rimsky_instances` or new table) — rejected because every instance of a given template carries identical augmentation, so the redundancy is gratuitous; receipt-time or cascade-walk-time computation — rejected because it requires a special-case branch in the cascade walker for sender=`""`, which violates the uniformity property the spec is built on.

**TD-empty-sender-key-edge-disambiguation** — The inverse-edge map's `""` sender-key currently holds cross-cutting (`instance: true`) subscriptions; structural-root edges must coexist there without semantic conflation.
**Choice:** add a `SenderBoundToEmpty bool` field to `code:lib/graph/node/subscription_edges.go::SubscriptionEdge`. Cross-cutting edges set the field false (the walker consults them on every settled sender, regardless of the actual sender's type). Structural-root injected edges set the field true (the walker consults them only when the actual settling sender's type is `""`). The cascade walker reads the field on every `""`-key lookup.
**Rationale:** preserves a single edge data structure and a single walker code path; the disambiguation is a one-field branch at lookup time. Cross-cutting subscribers continue to fire on every emission (including the empty-message virtual when their predicate matches); structural-root injected receivers fire only on the empty-message virtual.
**Alternatives:** separate sentinel key (`__sender_empty__`) for structural-root edges — viable but doubles the lookup surface for one logical sender; semantic-overload of the `""` key without disambiguation — rejected because it conflates the two edge kinds.

**TD-node-reset-as-pure-retry-budget-clear** — `route:POST /nodes/{id}/reset` becomes a pure state-machine-counter-clear verb. The endpoint already gates to failed-terminal nodes today; the spec preserves that gate and removes the wake.
**Choice:** the handler at `code:lib/control/controlapi/nodes.go::handleResetNode` retains its existing state gate at lines 195-200 (which refuses non-failed state with `409 Conflict` and an error citing the current state), and retains its calls to `code:lib/foundation/persistence::NodeTable.UpdateError(id, EvaluatorState{})` (clears the error budget), `NodeTable.ResetFailedTerminalSettlingSignalType` (clears the stale failed-flavor signal type), and `NodeTable.SetFrameID(id, nil)` (defensively clears the leftover frame_id). The trailing `runtime.EnqueueSyntheticWakeFrame` call is removed entirely; the endpoint no longer enqueues an envelope or opens a frame. The operator's workflow for retrying an errored node becomes two explicit steps: reset (clears the retry budget) then `POST /messages` (empty for whole-instance, typed for partial) to invalidate the node so a fresh dispatch is attempted.
**Rationale:** separates state-machine recovery from invalidation; preserves the principle "no generic node-invalidation outside the debug-channel surface" while keeping a non-debug-mode operator recourse for retry-exhausted nodes. The clear-then-message two-step is explicit and idempotent; conflating them into one endpoint is what introduced the synthetic-envelope path the principle rules out.
**Alternatives:** retire the endpoint entirely — rejected because it leaves no non-debug operator recourse for retry-exhausted nodes; fold reset into the debug-channel surface — rejected because it requires the operator to pause the instance first, a heavier workflow for what is the common-case error recovery.

**TD-asset-materialize-endpoint-retired** — `route:POST /instances/{id}/assets/{alias}/materialize` retires from the control-api surface, along with its CLI subcommand, MCP tool schema, and action-permission row.
**Choice:** the handler at `code:lib/control/controlapi/assets.go::handleAssetMaterialize` is deleted along with its route registration, its body types `materializeRequest` and `errAssetMaterializeUnknownNode`, and `findNodeByType` if no other site uses it. The CLI's `rimsky asset materialize` subcommand is deleted. The `asset_materialize` MCP tool schema at `code:lib/control/controlapi/mcp_route.go` line 160 is deleted. The `asset:materialize` action-permission row at `code:lib/control/controlapi/actions.go` lines 510-512 is deleted (this also removes the action from role-template grants that mention it). The endpoint returns `404 Not Found` post-spec. The asset list / detail / versions / materialization-history / delete endpoints stay unchanged. Operators wanting re-materialization use the empty-message trigger (whole-instance re-run) or a template-author-designed typed message routed to the producer node(s) via author-declared subscription edges.
**Rationale:** the materialize-by-alias verb was sugar on "ad hoc invalidate one specific node" — exactly the surface the principle rules out. Partial re-materialization with arbitrary upstream-staleness is a footgun: the asset produced by a full instance run can differ from the asset produced by a one-off invalidation of just its producer, because upstreams may carry stale values. Template authors who want partial re-runs own the safety question by choosing where the subscription edges land.
**Alternatives:** auto-inject `asset/materialize` typed messages with `when:` predicates routing to each producer — rejected because it re-introduces a runtime-managed partial-invalidation surface with the same footgun under a different name; keep the synthetic-envelope chokepoint for this one caller — rejected because it preserves the architectural debt with no offsetting benefit once the other two callers retire.

**TD-synthetic-envelope-mechanism-retired** — The entire runtime-synthetic-envelope mechanism retires.
**Choice:** the four runtime-internal type-paths `instance/root`, `node/reset`, `asset/materialize`, and `node/invalidate` (the complete inventory `code:lib/runtime/synthetic_envelope.go` currently synthesizes per the file header) cease to exist as runtime concepts. `code:lib/runtime/synthetic_envelope.go::EnqueueSyntheticWakeFrame` and `code:lib/runtime/synthetic_envelope.go::expandWakeWithUpstreamRefresh` are deleted; the file is removed. The `wake_node_ids` and `wait_set_pairs` payload fields disappear from the wire. The receipt-side reserved-field check (`errPayloadCarriesReservedField` at `code:lib/control/controlapi/messages.go` lines 191-238) is removed. The registration-side reserved-property check that refuses templates declaring a `body_schema:` with the `wake_node_ids` property is removed from `code:lib/graph/node/template_validator.go` around line 3296. The frame engine's `wake_node_ids` reader and the `wait_set_pairs` pre-emptive wait-set install branch at `code:lib/graph/frame/engine.go::advanceOneFrame` (lines 338-382) are removed. The `@blessed-invariant 21` sanctioned-payload-read-site enumerations in `code:lib/graph/attribute/substitution.go` (lines 485-499 and 547-559) drop the `wake_node_ids` reader from the list; the remaining four sanctioned read sites stay. `node/invalidate`'s sole caller — the test-harness helper — retires per TD-test-harness-invalidate-node-retired.
**Rationale:** the chokepoint exists only to serve callers that bypass the subscriber-side cascade; with all four callers retired (instance creation becomes idle; asset/materialize retires; node/reset trims to no-wake; the harness migrates to debug-channel), the chokepoint has no remaining role. Receivers wake exclusively via the subscriber-side cascade walker, consulting the augmented inverse-edge map.
**Alternatives:** keep the chokepoint for future use — rejected (dead code with structural surface, including the load-bearing reserved-property and reserved-field checks); keep it specifically for asset/materialize — rejected per TD-asset-materialize-endpoint-retired.

**TD-test-harness-invalidate-node-retired** — The scenario test harness's `InvalidateNode` helper retires entirely (both branches). The 19 dependent call sites split into three buckets, each treated differently.
**Choice:** delete `code:test/support/scenario/harness.go::InvalidateNode`. Two tests whose subject was the retired operator-invalidate surface — `code:test/scenarios/lifecycle_handlers_test.go::TestOperatorInvalidateTargetOnly` and `code:test/scenarios/parked_lifecycle_test.go::TestParkedLifecycleResumeOnExternalInvalidate` — retire alongside the helper; their reason for existing went away with the operator-invalidate surface. The 13 scaffolding tests that used `InvalidateNode` to drive a second firing while testing some other property are reinstrumented with legitimate triggers. For non-parked targets the trigger is a test-only typed message: each affected template fixture gains a `messages:` entry (e.g., `test/wake`) plus a `subscribes:` entry on the target node with `wake_on_change: true` and `force_upstream_refresh: false`, and the test body emits the typed message via `Client.CreateInstanceMessage` (Idempotency-Key derived from the test name and call site). For parked-state targets (`TestParkedHoldsFrame_EndToEnd`) the trigger is the real executor + callback path — the test's executor stub emits the park outcome; the test posts to the callback URL to wake the parked run. The 4 story-proof call sites (3 stories — `code:test/scenarios/claim_handoff_durable_e2e_test.go::TestClaimHandoff_Durable`, `code:test/scenarios/explicit_attribute_context_read_test.go::TestStoryReadWithoutWaking`, `code:test/scenarios/per_run_attributes/hard_dep_test.go::TestPerRunAttributes_HardDepPullsUpstream` and `TestPerRunAttributes_HardDepPullsUpstream_DirectInvalidateOfReceiver`) reinstrument with the same typed-message-driven invalidation pattern; their stories' `Acceptance` and `Proof` fields are unchanged (the user-observable outcome each proof exhibits is the same — only the in-test trigger mechanism changes from helper-call to typed-message emit).
**Rationale:** the harness's `InvalidateNode` was itself the principle violation, just relocated to the test layer — a test-only ad-hoc-node-invalidation surface that lets test code do precisely what the principle rules out for user surfaces. Keeping it via debug-channel migration was structurally incoherent: `code:lib/control/controlapi/debug_override.go::applyDebugOverride` requires a running frame to mutate (the early `GetRunningFrameID` returns nil on quiescent instances and the function returns `mutated=0`), the harness is called on quiescent instances, and pausing before posting an empty message blocks the frame engine from promoting the queued frame so the running-frame precondition is never satisfied. Keeping the helper via a test-only state-injection helper (direct persistence write of a frame row + stale node-run) preserved an internal mechanism that production no longer supports, creating maintenance debt with no offsetting benefit. Reinstrumenting tests with the legitimate trigger keeps the test-to-production trigger-path identical end-to-end — tests exercise what the system actually does in production, not a test-only artificial path. The 13 fixture changes are small (a `messages:` block and a `subscribes:` entry per affected node) and each test's behavioral subject is preserved.
**Alternatives:** debug-channel migration of the helper — rejected per the rationale above. Test-only state-injection helper — rejected per the rationale above. Per-test retain-and-migrate (give the helper a new mechanism, keep tests unchanged) — rejected because the helper itself is the principle violation; individual tests using a reshaped helper would still exercise a synthetic invalidation path that production does not support.

**TD-test-harness-create-instance-wakes-roots-after-create** — The scenario test harness's `CreateInstance` helpers gain an internal empty-message wake step after the create POST so existing `waitForRootDispatch` semantics still hold.
**Choice:** `code:test/support/scenario/harness.go::CreateInstance` (line 507) and `code:test/support/scenario/harness.go::CreateInstanceWithOverrides` (line 516) add an internal step between the create POST and the existing `waitForRootDispatch(id, 5*time.Second)` call (line 557): emit an empty-bodied message to the new instance via `Client.CreateInstanceMessage`, using a deterministic Idempotency-Key derived from the instance id (e.g., `harness-wake-<instance_id>`). The 19 existing tests calling `CreateInstance` continue to receive a dispatched instance from the helper without per-test change.
**Rationale:** pre-spec, instance creation auto-fired the structural roots via the synthetic-envelope mechanism, which is what `waitForRootDispatch` waited for; post-spec, instance creation is idle and a wake message is the only legitimate trigger. Folding the wake into `CreateInstance` keeps the helper's existing contract intact and avoids per-test churn for a mechanism that's identical across every caller (every test wants the wake-all-roots behavior the old auto-fire delivered). Tests that need to observe the idle-on-create behavior (`STORY-instance-create-is-idle`) use the control-api `Client` directly, not the harness, so the helper's wake-after-create does not interfere.
**Alternatives:** split into `CreateIdleInstance` + `CreateAndWakeInstance` and migrate every call site — rejected: every existing caller wants the wake-after-create behavior, so the split adds two-name confusion with no payoff. Require per-test wake emission — rejected: identical cost-of-call across 19 tests, no test specifically wanting an idle-after-create outcome from the harness.

**TD-compose-driver-emits-empty-message-after-create** — The compose driver emits an empty message to each declared instance after creating it, so the operator-facing one-shot contract is preserved.
**Choice:** `code:cmd/rimsky/cli/compose/run.go` after each instance create, emits an empty-bodied message to that instance via the same `*cli.Client` HTTP path it already uses for the instance-create call (the compose driver talks to the in-process role stack over HTTP, not via direct in-process call), using a deterministic Idempotency-Key formed as `compose-wake-<instance_key>` (so a re-run of the same manifest with the same instance_keys is idempotent on the wake step). The empty-message emit precedes the wait-for-terminal loop. No new flag, no manifest change, no operator-visible behavior change.
**Rationale:** the compose driver's user-facing contract (`story:one-shot-to-terminal`) is unchanged — declared instances reach terminal in one invocation. The implementation absorbs the now-explicit wake step internally; the operator does not have to add wake messages to their compose manifests.
**Alternatives:** require the operator to add wake messages to the compose manifest — rejected because it breaks the compose UX; add a convenience flag at instance-create that bundles the wake — rejected per the user's earlier decision that instance-create is strictly two-step.

## Mechanism narrative

**Instance creation.** The handler at `code:lib/control/controlapi/instances.go::handleCreateInstance` drops its tail call to `runtime.EnqueueSyntheticWakeFrame`. After the create transaction commits, the instance row exists with `paused: false`, the per-instance node rows exist with state `fresh`, no frame is enqueued, and `OnInstanceCreated` fires through the lifecycle-subscriber path as today. `GET /instances/{id}/frames` and `GET /instances/{id}/messages` both return empty collections until a sender emits.

**Empty-message receipt and delivery.** A sender posting to `route:POST /instances/{id}/messages` follows the existing flow at `code:lib/control/controlapi/messages.go::handleCreateMessage`. The receipt-time registry-membership check is unchanged in shape — only the data it reads against differs: the implicit `""` entry is present in every template's declared-types set, so an empty-typed message passes without a special branch. Body validation is permissive on `""` (no body schema means no fields to validate and no substitution references possible against it; the message body is persisted in the ledger but is not surfaceable for substitution).

At the next frame boundary, `code:lib/runtime/message_delivery.go`'s message-delivery sweep promotes the envelope to a new frame. The virtual `""` message-type-node settles in the new frame with `terminal/success`. The cascade walker reads the augmented inverse-edge map under sender=`""`, finds structural-root edges (`SenderBoundToEmpty: true`), and for each: inserts a wait-set row (cascade-walk insertion path, per `concept:wait-set`), stale-marks the receiver node-run, and the receiver becomes dispatch-eligible once its wait-set row is drained at the virtual sender's settlement. Cross-cutting subscriptions (`instance: true`, `SenderBoundToEmpty: false`) under the same key are consulted on every settled sender, including this one — they fire iff their `when:` predicate matches `terminal/success`. The supervisor's dispatch loop picks up the now-eligible structural roots, acquires their claims, and dispatches them. Cascade propagates downstream through author-declared subscription edges as in any other frame.

**Force_upstream_refresh on typed-message wakes.** With the synthetic-envelope mechanism gone, the cascade walker's existing upstream-refresh handling (via the per-template hard-dep edge map at `code:lib/runtime/subscription_loaders.go::templateHardDepEdges`) covers the `force_upstream_refresh: true` case for typed-message receivers naturally. When a receiver wakes via cascade walk and has a subscription with `force_upstream_refresh: true`, the walker consults the upstream-refresh edge map and stale-marks the upstream sender; a wait-set row keyed `(receiver_run, upstream_run)` inserts via path (a), the same cascade-walk insertion path used for the receiver. The structural guarantee — upstream candidates are evaluated before receiver dispatch begins — comes through the same eligibility predicate. No pre-emptive synthetic-envelope-time install needed.

## Design changes

- **Concept: mutate `concepts/message.md` in place.** Replace the "Two external emit sites and one internal" paragraph with: "Two external emit sites and one internal: operator API (`POST /instances/{id}/messages` with `sender_kind: operator`), publisher emissions (the same endpoint with `sender_kind: publisher` + a publisher-subscription capability token), and cascade-emit (a message-emitter-node's dispatch, with `sender_kind: instance` and sender `instance:<id>`).
