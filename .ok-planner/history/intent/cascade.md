## Net position

- Cascade is an **intra-frame** mechanism operating on **node_runs**, never on nodes: "cascade only involves node_runs"; there is no ambient node state, and state transitions target a specific node_run row by id (2026-07-05, 3f71f90a, transcript).
- Cascade order is **deterministic and structural**, not time-based. A cascade "round" is one firing of the walker at a receiver caused by one upstream settle, materialized as one cascade-driven pending node_run for (receiver, run-scope) (2026-07-13, 3f71f90a, transcript).
- The engine is **signal-blind**: subscription firing is gated purely on (edge type-path match) AND (CEL `when:` predicate); the engine never branches on the signal type itself (2026-06-10 artifact, reaffirmed 2026-06-18 transcript).
- The cascade-firing signal set is: `terminal/success`, `terminal/error/<class>`, `transient/retry/<n>/<class>`, `attribute/<key>/changed`. `event/<name>` no longer fires cascades. `terminal/park`, `terminal/infra`, `transient/await_async` are audit-only because the node resumes rather than settling (2026-06-17..18, transcript). AMENDED 2026-07-14 (user ruling): `transient/retry` removed from the firing set — only settling events cascade-fire or are subscribable; the set is exactly {terminal/success, terminal/error/<class>, attribute/<key>/changed}. See the signal dossier's resolved conflict for the full ruling.
- **Every terminal outcome continues the cascade** — terminal/error cascades exactly like terminal/success (2026-06-18, 8a3b8c19, transcript).
- Node_runs follow a **seven-state machine** (pending, stale, running, held, parked, fresh, failed) with the core seal invariant: cascade **never mutates an in-flight run** (pending, stale, running, held, parked) — it only queues a new pending row. "A node never gets re-invalidated, no matter what" (2026-06-20, 8a3b8c19, transcript).
- Cross-frame propagation happens **exclusively through messages**; cascade never creates frames. "Only a message runs a frame. Every message gets a new frame. A node's attributes at frame start are the default values. Message payloads are the ONLY cross-frame carrier" (2026-07-06, 3f71f90a, transcript).
- In-frame loops are **first-class**: self-edge, 2-node, and N-node back-edge cycles can iterate indefinitely within one frame; there is no "one node-run per node per frame" rule (2026-06-24, 3b1066c7, transcript).
- Reactive coupling is declared **receiver-side, explicitly**: implicit edge generation from substitution refs is retired; every substitution ref requires a covering declared subscription; `force_upstream_refresh` is the only per-subscription cascade flag remaining (2026-06-14 + 2026-06-23, transcript).
- Ad hoc node invalidation does not exist. Nodes can only be directly targeted from a breakpoint debug channel; there is no generic invalidate-a-node surface (2026-06-16, 4c42fe5b, transcript).
- Rimsky-as-circuit-graph is the design direction: anything beyond managing a node cascade can be fully modeled with nodes and propagation; special cases are defects (2026-06-14 + 2026-06-18, transcript).
- The rework shipped with **no back-compat**: the codebase must never carry multiple cascade implementations, remnants, or workarounds side by side (2026-06-20, 8a3b8c19, transcript).

## Required behaviors (open promises)

- **Signal-blind delivery, one code path.** Every cascade-firing signal type is delivered by the same code path, in exact and trailing-`*` subscription shapes, per-sender and cross-cutting; a new cascade-firing type automatically becomes observable (2026-06-10, cascade-and-claim-handoff, artifact; locked in transcript 2026-06-18: "we've been assured in earlier sessions that terminal/error will continue the cascade").
- **Per-sender `terminal/error/*` subscriptions fire** whether the sender settles via `give_up` (failed-color) or `pass` (fresh-color) — the issue #15 fix (2026-06-10, cascade-and-claim-handoff, artifact).
- **Walker accumulation rule (a).** A cascade reaching a receiver with a pending run accumulates the sender into that pending's wait-set only if the sender node is not already represented there; if the same sender node re-cascades, a new pending run (new round) is created. Handles diamond and diamond-with-extra-root topologies (2026-06-20, 8a3b8c19, transcript: "if it's not in the wait set, accumulated. but if it is, create new"). Natural-cascade wait-set inserts dedupe by sender_run_id; the walker reads all wait-set rows, not only drained ones (2026-06-20..21, transcript). Concurrent walkers serialize via an advisory lock per (node, scope, frame).
- **Gate evaluator at the wait-set drain site.** Runs synchronously inside the terminal-handler transaction. A pending run transitions to stale only when its wait-set is fully drained AND no subscribed upstream has an in-flight run (in-flight = pending, stale, running, held, parked). At the transition it builds the dispatch input bag: carry-forward from the prior run's persisted bag plus overlay from drained wait-set rows, then applies the node's cascade-mode rule (2026-06-20, 8a3b8c19, transcript).
- **The gate-eval bag IS the dispatch bag.** The dispatcher loads the persisted dispatch input bag by run id; sender attributes are not re-read at dispatch time (2026-06-20, 8a3b8c19, transcript).
- **Bag snapshot moment is pending→stale**, after queue-resolution semantics — never at enqueue/row-creation; claim substitution is applied at stale→running, the same code path every time (2026-06-21, 10cf843b, transcript: "we snapshot at pending->stale, *after* queue resolution semantic").
- **Enqueue-time upstream-run pinning.** Each enqueued node_run has its own distinct set of upstream runs, pinned at enqueue via the wait-set row's sender_run_id (runs, not nodes); its substituted values must come from those pinned runs once they settle. Local/carry-forward attributes come from the receiver's own last completed run at execution time (2026-07-13, 3f71f90a, transcript — confirmed as the original pre-June-22 design).
- **Sequenced cascade mode preserves per-round snapshots**: upstream settling v1, v2, v3 while the receiver is held must yield three dispatches seeing v1, v2, v3 respectively — not all reading the newest run. Finding 2337 adjudicated fix-code (2026-07-13, 3f71f90a, transcript).
- **Cascade modes govern the node_run queue only** (most-recent coalesce, sequenced ordering, idempotent dedupe) — one mode per node; nothing to do with messages (2026-07-03, 3f71f90a, transcript). Idempotent-mode bag comparison uses JCS (RFC 8785) canonicalization (2026-06-21, 10cf843b, transcript). Under idempotent mode, repeated identical cascade rounds must not produce one dispatch per round (2026-06-22, 10cf843b, transcript).
- **Gate-fix set ratified 2026-07-05** (3f71f90a, transcript): a receiver blocked by an upstream in-flight run is re-evaluated when the blocking run settles (reevalDownstreamReceiverGates); the cascade-mode drop check runs before the same-node serialization check; most-recent drops a pending whenever a later cascade peer exists regardless of iteration order; idempotent comparison resolves a still-pending prior peer's bag on demand.
- **Serialized pending→stale per (node_id, run_scope_id)**: a pending row may not transition to stale while another row for the same node and runscope is past pending and non-terminal. Multiple pending rows are explicitly allowed (2026-06-30, 8a8539a4, transcript).
- **Held state and held-cascade rule.** A node-run is held while it participates in any unresolved claim_handle as acquirer or co-holder (membership derived from existing claim tables, no new state columns). During the hold, cascade flows only among held-subgraph members; on claim resolution each holder transitions per its full claim portfolio (all committed → fresh; any abandoned → failed, poison rule) and fires its own deferred cascade to non-members only — terminal/success at commit, terminal/error/abandoned at abandon. Nodes that never executed during the hold broadcast nothing (2026-06-20..21, 8a3b8c19/10cf843b, transcript).
- **Parked runs are sealed.** Cascade never wakes or mutates a parked run; it queues a new pending and the parked run stays parked. Parked has exactly two exits: time-wake on its own deadline (parked→stale) and watchdog timeout (parked→failed) (2026-06-20..22, transcript: "we need to figure out the recurring fixation on adding back other ways to wake parked nodes"). Cascade information arriving during a park must be preserved and produce a later dispatch — never dropped (2026-06-19, 8a3b8c19, transcript).
- **Await-async-callback is not a park**: the run stays `running` and inherits the standard in-flight seal; cascade during the wait queues new pendings per the standard rule (2026-06-20, 8a3b8c19, transcript).
- **Static upstream view / snapshot survives resume.** A node-run's view of its upstreams is fixed for its lifetime; a park-and-resume re-invokes the executor with the dispatch-time substitution snapshot, not a rebuilt context (story resume-preserves-snapshot, 2026-06-19, 8a3b8c19, transcript — explicitly survives the seven-state redesign).
- **Diff-based `attribute/<key>/changed` emission, uniform across all node types.** On settle, every node — regardless of node type, executor, or settle path — diffs final attribute values against the prior run's persisted data (or its own dispatch_input_bag when no prior run) and emits changed signals only for keys that actually moved. Same-value resettlement emits nothing (2026-06-22..23, 10cf843b, transcript).
- **Signal payloads never propagate down the cascade.** A payload has exactly two consumers: the CEL when-predicate at walk time and the audit row. Wait-set rows carry no payload; receivers read sender attribute stores (2026-06-23, 10cf843b, transcript).
- **Stepwise execution**: a node fully settles at its terminal before any downstream subscriber sees its signals or dispatches; named events batch at terminal, no mid-stream cascade firing (2026-06-16, 055468fc, transcript).
- **Executor event uniformity**: Success, Error, and Park can all trigger cascade, so all must be able to carry an attributes_delta — "an event is an event" (2026-06-16, 055468fc, transcript).
- **`force_upstream_refresh` structural guarantee.** Within a run scope, force-upstream dispatch happens structurally before the dispatching node: all upstream candidates evaluated before dispatch begins; on dispatch only the most recently completed node_runs are selected as immediate upstreams. No callbacks, no completion flags, no extra state (2026-06-15, 4c42fe5b, transcript). A direct wake of a receiver pulls that receiver's own force_upstream_refresh upstreams into the frame (2026-06-15, b106a350, transcript).
- **In-frame loop proofs.** Scenario tests pin 2-node in-frame back-edge re-fire (test/scenarios/cascade_two_node_backedge_in_frame_test.go, cascade_two_node_backedge_via_attribute_test.go) and single-node self-loop (loop_counter_cap_e2e_test.go) (2026-06-24, 3b1066c7, transcript). Back-edge cycles work only within a single frame; a cross-frame queue drain is a different, message-layer capability needing its own proof (2026-07-05, 3f71f90a, transcript).
- **Five foundation cascade proofs stay green** — attribute-changed diff-gate, sequenced-preserves-cascade-rounds, idempotent-mode-dedupes, cascade-defers-during-flight, most-recent-coalesces-cascades (the latter re-homed to the message-queue layer) — driven by in-template loops (cascade self-edges bounded by CEL `when:`), not by posted messages. "No deferrals, no follow-ups... this is foundation, so we won't accept any unknowns" (2026-07-05, 3f71f90a, transcript). The seven seal/held stories from the redesign each carry a passing postgres-backed scenario proof (2026-06-20, 8a3b8c19, transcript).
- **Non-cascade re-run paths go direct-to-stale**: operator_invalidate (debug channel), policy_retry, infra_reenqueue settle the old row in place and enqueue a new stale row with the matching creation_reason, carrying the attribute bag forward verbatim from the previous run's persisted bag (2026-06-20, 8a3b8c19, transcript).
- **UpdateState targets a node_run_id directly.** The ambient (node_id, run_scope_id) lookup, state-priority sort, cross-frame failed-state fallback, and GetLatestRunInScope are deleted (2026-07-05, 3f71f90a, transcript).
- **Frame rows are cascade-immutable**: cascade processing never stores state in a frame row. Bookkeeping writes are sanctioned — the frame-engine reaper stamps ended_at exactly once (atomic RowsAffected==1) and the liveness heartbeat writes last_progress_at (2026-07-06, 3f71f90a, transcript).
- **Message-cascade uses the identical code path**: the message virtual node exists precisely so cascade-from-message is the same walk as cascade from any settled run; no "this cascade came from a message" branching anywhere (2026-06-22, 10cf843b, transcript).
- **Pass-through propagation is uniform**: in A→B→C where B substitutes a value through (including a fan-out parent), C's attribute-change subscription fires when the passed-through value actually changes (2026-06-22, 10cf843b, transcript).
- **Structural-root edges** are injected at template registration into the cached inverse-edge map (canonical template hash unchanged), keyed by sender `""`; cross-cutting vs structural-root edges under the shared `""` key are discriminated by SenderBoundToEmpty, with both directions pinned by edge-map unit tests (2026-06-16, 4c42fe5b, transcript).
- (artifact-only) **Cross-RunScope cascade at exactly two boundaries**: sub-graph entry-success and fan-out parent settlement; partition-internal cascades don't propagate outward; sub-graphs are externally opaque — outside cascade fires the calling node and never descends (2026-05-15 + 2026-05-22, artifact; never revisited in transcripts).
- (artifact-only) **Parent-settlement cascade bridge fires inside the settle-children primitive**, within its settlement transaction, so no caller can settle child executions without cascading (2026-06-11, last-mile-stability, artifact).
- (artifact-only) **Pure-cascade (no-executor) runs are excluded from supervisor dispatch eligibility** and advance through the scheduler's pure-cascade path (2026-05-15, data-platform-extensions, artifact; the empty-executor message-receiver path builds on it, 2026-06-22 transcript).
- (artifact-only) **Test-placement rule**: tests of generic cascade/scheduler/supervisor behavior are authored against the stub store (2026-05-24, repo-reorganization-test-audit, artifact).

## Conflicts needing human ruling

- **RESOLVED 2026-07-14 (user ruling, transcript tier): the three May cascade-bridge rules are ratified as current intent**, restated in July vocabulary — a frame contains a tree of run scopes ("a frame contains a tree of run scopes", user, 2026-07-14), and these rules govern cascade crossing run-scope boundaries *within* a frame (a different axis from cross-frame propagation, which remains messages-only). (1) Two-boundary rule: cascade crosses a run-scope boundary at exactly two places — sub-graph invocation (caller success seeds internals) and fan-out parent settlement; partition-internal cascades never propagate outward. (2) Sub-graph opacity: outside cascade fires the calling node and never descends into internals. (3) Settle-children bridge: parent-settlement cascade fires inside the settle-children primitive's transaction, so no path settles children without cascading. Formerly artifact-only; now transcript-tier by ruling. Adjudicators treat violations of any of the three as defects.
- **RESOLVED 2026-07-14 (verified against the live proof): the idempotent-mode dedup gap is CLOSED, not obsoleted.** TestIdempotentModeDedupes_QueueComparison run 2026-07-14 against real Postgres: PASS — four upstream cascade rounds with a byte-identical resolved bag produce exactly ONE downstream dispatch under cascade_mode=idempotent-queue (modeDropIfPriorEqual JCS-compares the new pending's resolved bag against the prior cascade stale's bag and drops on equality). The 2026-06-22 deferred off-by-one is closed by the 2026-07-05 idempotent-comparison fix; the current proof asserts strictly stronger behavior than the old gap described. Findings resting on the 06-22 gap adjudicate as fixed/stale.
