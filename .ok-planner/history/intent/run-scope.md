# Intent Dossier: run-scope

Distilled 2026-07-13 from session transcripts (2026-06-12..2026-07-13) and ok-planner
history artifacts (2026-05-04..2026-06-11). Transcript tier outranks artifact tier;
later intent supersedes earlier. Part of the drift-remediation intent ledger.

## Net position

- **Termination closes the whole scope tree** (user ruling 2026-07-17): administrative instance termination closes every remaining open run-scope in the instance's frames — child scopes (sub-graph, fan-out partition) included, not just frame roots — and fires each closed scope's run-scope-terminal peer fan-out, so peers tracking per-scope state (e.g. data-processing candidates under a partition scope) hear about scopes the kill orphaned. Code currently closes root scopes only (queued fix-code). Settlement rendezvous remains the only run-side closure path; termination is the sole administrative exception.

- A RunScope is one graph instantiation — the execution context that owns a set of node-runs. It never represents one execution of one node; that is a node-run (2026-06-19, 08d65bfe, transcript).
- RunScope is **frame-rooted, not instance-rooted**: every frame's start creates a fresh root RunScope, the frame row carries `root_run_scope_id`, and there is no per-instance main RunScope (`instance.MainRunScopeID` removed) (2026-06-30, 8a8539a4, transcript; reaffirmed 2026-07-06).
- A RunScope is IN exactly one frame, never more than one; a frame is a tree of RunScopes; RunScopes never cross a frame or instance boundary. The entirety of frame state is held in run scopes and node_runs (2026-06-30 and 2026-07-05, transcript).
- Three kinds — root (formerly main), sub-graph, fan-out partition — distinguished purely by structural fields (parent presence, partition_key). Kind is derivable, never stored. The kinds are deliberately not unified (2026-05-22 artifact; 2026-06-19 transcript).
- RunScope exists exclusively to handle sub-graphs and recursion. Fan-out composes with it: a fan-out partition RunScope can be a single-node execution context (just the calling node's executor with the partition's sub-claim), and a delegating fan-out parent nests a sub-graph RunScope inside each partition RunScope (2026-06-18 and 2026-06-19, transcript).
- A sub-graph RunScope's parent is whatever RunScope created it — nothing to do with the frame's root; any RunScope can spawn a child RunScope (2026-06-30, transcript).
- Persistence shape: first-class `rimsky_run_scopes` table; node runs carry a non-null `run_scope_id`; partial unique in-flight index on (node_id, run_scope_id); at most one OPEN fan-out partition scope per (parent_run_id, partition_key) (2026-05-22, artifact).
- Concurrency invariants ("rimsky 101", 2026-06-30, transcript): no limit on pending node_runs per (node, run-scope); pending→stale transitions are serialized per (node, run-scope); at most one stale-or-active node_run per (node, run-scope); only one node_run per node can be active in a run-scope.
- Attribute state is scope-local: carry-forward happens only within a single frame and run-scope; a new RunScope (and every new frame) starts from schema defaults. Cross-RunScope hydration is forbidden as *implicit* reach; the explicit entry/exit attribute copy of sub-graph delegation is the designed channel (2026-06-14, 2026-06-22, 2026-06-30, transcript).
- A closed RunScope (`closed_at` set) means its parent-run rendezvous has fired; settlement carries the outcome back atomically and fires the cascade bridge inside the settlement transaction; terminal node-run rows persist until run-scope garbage collection. Old kind-specific closure triggers stand except the retired main-per-instance case; an instance that never ran a frame has no scope to close, so terminating it fires no OnRunScopeTerminal (2026-05-22 artifact; 2026-06-11 artifact; 2026-07-07 transcript).
- RunScopes are per-instance (within frames of one instance); cross-instance coordination uses messages and triggers (2026-05-22, artifact).

## Required behaviors (open promises)

- First-class `rimsky_run_scopes` table with non-null `run_scope_id` on node runs, replacing (parent_run_id, child_key) inline disambiguation; the legacy runID pointer parameter is gone from persistence methods (2026-05-22, fan-out-safety-scope-first, artifact): "Complete rimsky's fan-out and sub-graph dispatch safety by replacing the current (parent_run_id, child_key) inline-disambiguation model".
- Every frame's start creates a fresh root RunScope owned by that frame; the frame row carries `root_run_scope_id` (2026-06-30, 8a8539a4, transcript): "The frame row should carry the root runscope."
- Kind stays derivable from structural fields; at most a derived helper enum method on the RunScope object, never a stored column (2026-06-19, 08d65bfe, transcript): "no need to add a column. a helper on the RunScopt object that returns an enum value based on derived type will do".
- Lazy node-run row allocation per RunScope via AffirmNodeRunRow (INSERT-if-no-in-flight-row keyed node_id + run_scope_id); callers must not depend on its return shape beyond error/no-error, preserving lazy↔eager as a no-op rewrite; cascade walkers use affirm-then-read (2026-05-22, fan-out-safety-scope-first, artifact).
- Closed-scope semantics: AffirmNodeRunRow on a closed scope returns ErrRunScopeClosed; the cascade walker reaching into a closed scope is a defensive-check bug; late callbacks into closed scopes are rejected by the phase-based determinism rule (2026-05-22, artifact). Downstream consumers must not assume every dispatch produces a terminal event (2026-05-22, artifact).
- Cross-RunScope cascade occurs at exactly two boundaries — sub-graph entry-success and fan-out parent settlement; partition-internal cascades never propagate outward (2026-05-22, artifact).
- Pending→stale transitions serialized per (node_id, run_scope_id); multiple pending rows may coexist (that is the queue's purpose); at most one stale-or-active node_run per (node, run-scope) at any moment (2026-06-30, 8a8539a4, transcript): "a pending row may not transition to stale ... *not* to prevent multiple pending rows from being created."
- Attribute carry-forward: on each dispatch, all attribute values copy from the node's previous node_run in the same scope, then substitutions overlay; first dispatch in a scope and any new RunScope starts from schema defaults (2026-06-14, 752fe200, transcript): "the value of all aiitrubtes are copied from the previous node_run, then substitutions are updated. end of story."
- The attribute pipeline per dispatch is exactly: copy-forward-or-seed → substitutions → schema validation → executor → schema validation of resulting attributes; no extra filtering (2026-06-15, c60b550a, transcript).
- Force-upstream-refresh dispatch is structurally guaranteed before the dispatching node within a run scope: all upstream candidates evaluated before dispatch begins; on dispatch only the most recently completed node_runs are selected as immediate upstreams — no callbacks, no flags, no extra state (2026-06-15, 4c42fe5b, transcript).
- Fan-out parent and children are node_runs of the same node_id — one run in the parent scope (acquires, aggregates), one per partition scope (holds one sub-claim, executes); role derived from the scope a run lives in; a guard skips fan-out logic for runs in non-root scopes so children never re-fan-out (2026-06-19, 8a3b8c19, transcript).
- A fan-out partition need not contain a sub-graph — a single-node partition scope running the calling node's executor is legal and intended (2026-06-19, 8a3b8c19, transcript): "just the executor of the calling node? (which is fine - more flexible than requiring a sub-graph)."
- Node-run sequence is monotonic per (node_id, run_scope_id) — deterministic latest-run ordering across frames (2026-06-21, 10cf843b, transcript).
- Terminal node-run rows (fresh or failed) are never deleted at settlement; deletion only via run-scope GC when the whole scope closes (2026-06-21, 10cf843b, transcript).
- The parent-settlement cascade bridge fires inside the settle-children primitive, within the settlement transaction; settlement is the only run-side path closing child execution contexts (instance termination is the administrative exception); carry-back is atomic with closing (2026-06-11, last-mile-stability, artifact).
- Message delivery always targets the frame's root scope — the empty-wake path included; any scope override from another frame's runs is a frame-isolation violation (2026-07-03, 3f71f90a, transcript).
- The attribute diff-gate baseline (GetPriorRunData) is same-RunScope only, no cross-scope or cross-frame fallback; a node re-running in a fresh frame has no prior, so the signal fires (2026-07-05, 3f71f90a, transcript).
- Late-bound child processes are isolated per run-scope: one spawn per (run-scope, binding) with run-scope lifetime, reaped on that scope's termination (SIGTERM then SIGKILL after grace), so concurrent run-scopes never share executor process state; this requires run_scope_id on the dispatch wire (ExecuteRequest/OpenRequest) (2026-05-24 artifact; corrected and re-promised 2026-06-06 and 2026-06-08, artifact): "concurrent run-scopes never share executor process state".
- OnRunScopeTerminal fires from the rimsky-side process owning the state transition's post-commit fan-out (supervisor for sub-graph / fan-out-partition scope terminals, synchronous in-tx), with DB-tracked idempotency (2026-05-24, host-agent-and-proxy, artifact) — the main-scope/control-api-polling half of that design is superseded by the frame-rooted model.
- The claude-agent executor's dispatch_context_read MCP tool returns dispatch_id, run_scope_id, prior_dispatch_id, prior_dispatch_disposition verbatim from ExecuteRequest (2026-06-19, 8e7e4c10, transcript).
- Claude-agent CLI session continuity: the conversation resumes across dispatches within one RunScope via a session_token attribute carried forward and passed as --resume, and starts fresh in a new RunScope; demonstrated by the self-edge loop test (one message → one frame → three serially-settled dispatches in one frame/RunScope) (2026-06-14, 752fe200; rewritten 2026-06-30, 8a8539a4, transcript).
- Deleting an instance drops everything beneath it through the run-scope tree (runtime-cascade deletes on both backends) (2026-05-22, artifact-only).
- The attribute matcher-overlay's child_key key sources its value from the dispatched run's RunScope partition_key (empty for non-fan-out) (2026-05-22, artifact-only).
- Forensic by-node attribute lookup takes a runScopeID so fan-out picks the right partition's attributes (2026-05-22, artifact-only).
- Callback handling resolves the run directly by dispatch id (FOR UPDATE); run_scope_id is non-null by schema, so silent nil-parent-context success is impossible (2026-05-22, artifact-only).
- RunScope persistence conformance coverage (scope lifecycle, AffirmNodeRunRow, in-flight lookup by node+scope, state-write isolation by scope, recovery-aware dispatch population) runs on both Postgres and SQLite (2026-05-22, artifact-only; predates the frame-rooted correction — verify suite reflects the corrected model, not the retired main-per-instance one).

## Intentional absences

- **Stored kind column on rimsky_run_scopes** — declined at design (2026-05-22, artifact) and re-declined against the loose-ends sketch (2026-06-19, 08d65bfe, transcript).
- **Per-instance main RunScope / `instance.MainRunScopeID`** — removed with the frame-rooted correction (2026-06-30, 8a8539a4, transcript); named in the excision list (2026-07-07, 3f71f90a, transcript). The deferrable mutual FKs instance↔main_run_scope are moot with it.
- **Automatic instance termination** — retired with the per-instance-scope model (2026-07-07, 3f71f90a, transcript).
- **Cross-instance RunScope linking** — out of scope by decision; messages and triggers are the cross-instance mechanism (2026-05-22, artifact).
- **Run-scope/run-tree state exposure through the claude-agent MCP surface** (run_scope_id, parent_run_id as tools) — declined as rimsky-state access breaching the not-a-privileged-client tenet; partition identity arrives via `{{child.partition_key}}` substitution (2026-05-28, artifact). (dispatch_context_read, 2026-06-19, later deliberately exposes the wire-visible ExecuteRequest fields only — not tree walking.)
- **`_rimsky.run_scope.*` reserved attributes** — sketch-only, deliberately dropped (2026-06-06, comprehensive-gap-closure, artifact).
- **RunTreeTable.GetByParentChildKey, the legacy runID disambiguator, and (parent_run_id, child_key) on rimsky_node_runs / DispatchRequest** — structurally removed (2026-05-22, artifact).
- **Direct reference to a fan-out child** (e.g. as a substitution source across the scope boundary) — "is not supported and won't be" (2026-06-23, 10cf843b, transcript).
- **Unifying fan-out-partition into the sub-graph kind** — considered and declined: "we don't need to unify" (2026-06-19, 8a3b8c19, transcript).
- **Runtime depth-gating safety net** — always aspirational ("future capability"), never wired; adjudicated fix-doc: the invariant is reworded enabled-not-built, not implemented now (2026-07-13, 3f71f90a, transcript; closes the 2026-05-22 artifact promise).
- **Eager run-row allocation and operator UI for the RunScope tree** — explicitly out of scope; lazy allocation stands with eager preserved as a future no-op rewrite (2026-05-22, artifact).
- **Old fanout-disambiguator conformance tests** — retired; inexpressible under (node_id, run_scope_id) keying (2026-05-22, artifact).
- **Any cross-frame carry-forward or cross-frame prior lookup** — always a bug; frames run in perfect isolation (2026-06-30 and 2026-07-05, transcript).

## Corrections and restorations (drift-fight record)

- **The frame/runscope model drift (the defining incident).** Implementation and concepts/run-scope.md both carried "Main RunScope: one per instance" and "frames and RunScopes are orthogonal". The user ruled this was not new intent — docs and implementation were wrong; forensics traced the drift to the 2026-05-22 fan-out-safety-scope-first spec ("the single, fatal mistage of an agent misunderstanding in a spec that RunScope is frome-rooted, not instance-rooted"), which landed spec+plan+code+docs atomically in commit 899c9cb1 with no review boundary. Restoration: bugs fixed first, then concept docs corrected directly (rewritten run-scope.md with Root/Sub-graph/Fan-out-partition kinds and root-created-at-frame-start; frame.md gains root-RunScope ownership and perfect isolation; new decisions frame-isolation and run-scope-is-per-frame) (2026-06-30, 8a8539a4; 2026-07-06, 3f71f90a, transcript). Precedent: the 2026-05-22 artifact is *known-canonized-inaccurate* on frame/scope rooting — transcript rulings win.
- Precursor correction: the 2026-05-22 frame note's "a frame spans multiple RunScopes" must be read "contains", not "spans" — a RunScope is contained within its frame (2026-06-03, instance-lifecycle-durable-by-default, artifact).
- Empty-wake delivery's scope override (receiver's latest run's scope from any frame instead of the new frame's root scope) ruled a hard frame-isolation violation and deleted (2026-07-03, 3f71f90a, transcript).
- The diff-gate baseline widening to prior frames (commit 20724e96) ruled a frame-isolation violation and fully reverted (2026-07-05, 3f71f90a, transcript): "you said some things that made us think we have once again reverted to introducing cross-frame state".
- "A run-scope does not represent one execution of one node" — agent misconception corrected mid-session (2026-06-19, 08d65bfe, transcript).
- Multiple pending node_runs per (node, scope) is deliberate (queue-and-coalesce); a proposal to prevent them contradicted the design and was rejected (2026-06-30, 8a8539a4, transcript): "a node may absolutely have multiple node_runs pending. look at the commit history."
- Spawn-dedup drift: proxy keyed spawns on instance id (wire lacked run_scope_id), making the designed reap-on-run-scope-terminal a no-op (ids never match). Recorded as a landed defect (2026-05-24 divergences, artifact); corrected intent re-asserted: per-run-scope isolation with run_scope_id on the wire (2026-06-06, artifact).
- Fan-out sub-claim node_run_id repoint (to the child run) fixed the partition-scope closure walk that had matched no partition scope (2026-06-02, rimsky-core-remediation, artifact).
- 2026-05-22 verification sweeps restored real regressions: the sub-graph exit cascade bridge in applyTerminalCompleteSubgraphExit, run_scope_id missing from MarkSourceNodeStale's INSERT on both backends, a missing affirm before recalculation in the pure-cascade path, and the message-subscriber cascade walker (cascadeMessageSubscribersInTx) needing the same affirm-per-receiver reshape the plan omitted (2026-05-22 divergences, artifact).

## Conflicts needing human ruling

- **RESOLVED 2026-07-14 (user ruling, transcript tier): a frame's settlement closes its root run scope, at settlement.** Every scope that opens fires OnRunScopeTerminal exactly once: nested scopes at their rendezvous, root scopes when their frame settles (no runs left stale/running/parked), and the instance-teardown closure (2026-07-14 control-api ruling) is purely the emergency backstop for what a cut-short frame left open — nothing, on the graceful path. Rationale: instances are durable and terminate only by operator action; deferring root-scope closure to termination would accumulate unbounded open scopes holding per-scope producer state hostage. Defect class: a settled frame leaving its root scope open, or firing the lifecycle event only at termination. Phase 2 guard test: one frame settlement → exactly one OnRunScopeTerminal for its root scope.
