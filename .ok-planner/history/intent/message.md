# Intent Dossier: message

later intent supersedes earlier. Part of the drift-remediation intent ledger.

## Net position

- **Messages are the only way work happens.** Only a message runs a frame; every message gets a new frame; one message = one frame. Nothing else creates a frame — no runtime-internal path may open one (2026-06-15, 91ec93d1, transcript: "*nothing* creates a new frame except a message"; restated 2026-07-06, 3f71f90a: "Only a message runs a frame. Every message gets a new frame.").
- **Messages never touch a running frame.** They may arrive mid-frame but wait their turn in the per-instance queue; "there should be no possible way for a message to change anything happening in an already-running frame" (2026-06-30, 8a8539a4, transcript). Messages don't "land" in frames — they trigger them; triggering and landing are the same single action (2026-07-03, 3f71f90a, transcript).
- **Message payloads are the ONLY cross-frame state carrier** (2026-07-06, 3f71f90a, transcript). Attributes are the sole method of exchanging data between nodes; there is no notion of one node sending a payload to another node (2026-06-21, 10cf843b, transcript).
- **Messages are typed and schema'd.** The template's `messages:` registry declares each type (type-path grammar shared with signal/node types) plus a body schema; message bodies are typed attribute blocks served by the same substitution code and grammar as node attributes, validated in both read and write directions at registration (2026-06-14, bfc9febb, transcript).
- **Messages ARE nodes at runtime.** Each declared type materializes as a literal message-receiver node row at instance creation — an empty-executor pass-through. Delivery = validate body against schema, create a node-run directly in stale with creation_reason message_delivery, populate its bag from the body verbatim, let the scheduler settle it via the pure-cascade path, firing standard terminal/success cascade. "The message node *is* exactly the message, and its attributes are exactly the message payload" (2026-06-19 + 2026-06-22, transcript). No special cascade-from-message code path exists.
- **The empty message ("" type) is the universal wake**: it triggers all structural roots through the identical typed-message path — one code path, no branch named for the empty case; the empty type is implicit in every template's declared set and reserved for the runtime (2026-06-17 + 2026-07-03..05, transcript).
- **Instance creation is inert** — no frame, no envelope, no auto-fire; invocation is always a message landing (2026-06-15, 91ec93d1, transcript).
- **Each instance has its own message queue** with `message_queue_mode: backlog (default) | coalesce`; the next queued message creates a new frame IFF no non-resolved (open or parked) frame exists for that instance. Frames have no queued state — created, then immediately run (2026-07-05, 3f71f90a, transcript).
- Vocabulary: messages are **SENT** (directed push into a specific instance's queue, mailbox semantics, payload fully self-contained); signals are **EMITTED**. node_runs send messages; nodes do not emit them (2026-07-03..05, 3f71f90a, transcript).
- Message payload bytes are **inert** — read only via named-path substitution; never logged, formatted, transformed, or included in error messages (2026-05-15 artifact, blessed invariant; never retracted).

## Required behaviors (open promises)

- **Loud refusal of undeclared types.** A message whose type is not in the template's `messages:` registry is refused at receipt (HTTP 400-class) naming the unknown type and the declared set — no silent dead-lettering. A declared type persists to the ledger and opens a frame (2026-06-14, bfc9febb, transcript).
- **Mandatory Idempotency-Key.** POST /instances/{id}/messages refuses a missing header with 400 and persists nothing; fresh insert returns 201, same-key replay returns 200 with the identical message_id and no second envelope/frame. Dedup tuple is five columns: (instance_id, sender_kind, sender, sender_subject, idempotency_key) (2026-06-06 + 2026-06-08, artifact; reaffirmed by transcript-era empty-wake acceptance 2026-06-17, b95ff4a7). A per-status control-api test matrix pins every idempotency and publisher-capability outcome to its exact HTTP status (2026-06-06, comprehensive-gap-closure, artifact).
- **Publisher capability check.** A publisher-authenticated send must resolve publisher_subscription_id against an active row scoped to that instance (403 on unknown/cross-instance/stopped, 400 on missing id); rimsky overwrites sender from the authoritative row so publishers cannot spoof (2026-05-17, sensor-messaging-unification, artifact; proven end-to-end 2026-06-02, acceptance-coverage-recovery, artifact).
- **Auth context is the sender discriminator.** sender_kind is dropped from the wire envelope; the server stamps the persistence row's sender_kind (operator | publisher | instance) from the auth path; `instance` is stamped only by the runtime cascade-send path and never appears on the wire. One URL for operator and publisher ingress (2026-06-19, 8a3b8c19, transcript).
- **Empty-message wake** (STORY-empty-message-wakes-roots): posting an empty-bodied keyed message opens exactly one frame whose triggering_message_id points at the envelope; every structural root (no author-declared subscribes) stale-marks via the normal subscriber-side cascade; non-roots untouched; N empty messages produce N frames. Author-declared empty-string types are rejected at template validation. The "" receiver NodeRow is appended at instance creation alongside author-declared receivers (option ii — persisted spec and template hash unchanged); post-unification (commit 80a11733) receipt and delivery treat the empty type identically with every declared type (2026-06-16..17 + 2026-07-05, transcript).
- **Message-receiver node constraints**: receiver nodes cannot subscribe and cannot substitute in — no subscribes block, no source directives; attribute values come exclusively from delivered bodies. Otherwise they are ordinary nodes (2026-06-22, 10cf843b, transcript). Instance node listings include materialized receiver nodes; node_count reports the user-declared template count (2026-06-22, 10cf843b, transcript).
- **`{{messages.<type>.<field>}}` is an alias for `{{nodes...}}`**: one substitution pipeline (one parser, one reference type, one extractor, one resolver), type-checked at registration (messages-prefix names must be declared message types, nodes-prefix must be non-message nodes); an undeclared message reference is rejected at registration naming the offender; coverage checking treats messages.<type> identically to nodes.<type>, with **no auto-subscribe** (2026-06-18..19, transcript).
- **Message-sender node** (message sending as a node dispatch mode): a node declares the sent type instead of an executor, subscribes to graph nodes with full attribute substitution, and its dispatch builds a message whose body IS its resolved attribute set — the sender's attribute schema must exactly match the destination body schema, no mapping layer (2026-06-14, bfc9febb, transcript). Architecturally a built-in utility executor (inproc emit_message) wired by template sugar; the envelope inserts in its own transaction during the handler call, with at-most-once delivery across retries via the deterministic idempotency key `cascade-emit:<node_id>:<frame_id>` (one envelope per node+frame, pinned by tests) (2026-06-15 + 2026-06-23, transcript).
- **Per-instance message queue modes.** `message_queue_mode` declared on the template as a default, copied into each instance row at creation, operator-overridable per instance. backlog: queue grows, every message runs in sequence. coalesce: discard all queued messages except the next — regardless of message type; the validator warns when a coalesce-mode template declares ≥2 distinct message types (2026-07-05..06, 3f71f90a, transcript).
- **Frame origin audit**: every frame row carries a NOT NULL triggering_message_id pointing at the ledger entry that opened it — the schema-level proof that no internally-created frame can exist; frame-to-message and message-to-frames queries supported (2026-06-14 + reaffirmed by rejection of nullable proposal 2026-06-19, transcript).
- **Instance-create is idle; wakers are explicit.** Every path that creates an instance and expects it to run sends a follow-up empty message: harness CreateInstance, CLI run, the compose driver (deterministic compose-wake-<instance_key> key) (2026-06-15..16, transcript). One message-post idiom per layer: Harness.PostInstanceMessage test-side, Client.CreateInstanceMessage cli-side (2026-06-16, 4c42fe5b, transcript).
- **Messages never wake parked runs.** Posting a typed message after a park does NOT transition the parked run; pinned by the negative proof TestParkedHoldsFrame_TypedMessageDoesNotWake (2026-06-22, 10cf843b, transcript). Since one message = one frame, no receiver in a fresh frame can be parked; delivery has no business probing prior-frame parked runs.
- **DeliverPendingMessages delivers only the frame's own triggering message** — any message landing in an already-running frame is a bug (2026-06-30, 8a8539a4, transcript).
- **Instance disable/terminate semantics**: the running frame finishes, then the instance stops — no new frames, new messages rejected, pending messages cancelled. "Terminated" = disabled-and-ignore-future-messages with the row persisting. The terminate path must call CancelPendingForInstance — a July-5 queue redesign made lifecycle events cancel pending messages but terminate was never updated; **finding 437 adjudicated fix-code** (2026-07-06 + 2026-07-13, 3f71f90a, transcript).
- **`rimsky watch --until idle|terminated`** (idle default; idle = no open frame and no pending messages), backed by a ?pending=true message filter through persistence, control API, and CLI, with conformance coverage on both backends (2026-07-07, 3f71f90a, transcript).
- **Delivery routing is purely message_type matched against node-subscription edges** — no per-subscription target-node routing (2026-06-19, a02fe167, transcript).
- **Remove the messages.* auto-subscribe edge injection.** The June-18 coverage-check unification requires explicit subscribes; substitution refs do not contribute coverage; the leftover injection code is the drifted side. **Finding 1312 adjudicated fix-code** (2026-07-13, 3f71f90a, transcript).
- (artifact-only) **Payload inertness invariant**: message bytes read only via named-path walk for substitution and the persistence fetch; never logged/formatted/validated-beyond-schema/transformed (2026-05-15 + 2026-05-17, artifact — never retracted; the substitution surface it names has since moved to messages.<type>).
- (artifact-only) **Publisher protocol reconciliation**: Capabilities/Subscribe/Unsubscribe/ListSubscriptions; after a rimsky restart, rimsky calls ListSubscriptions and reconciles to steady state without re-subscribing active subscriptions; bundled publishers generate per-fire idempotency keys (cron: subscription+fire-window; http: subscription+body-SHA; object-store: subscription+etag; webhook: subscription+inbound header) (2026-05-17 + 2026-06-08, artifact).
- (artifact-only) **Pause does not silence external producers**: publisher/sensor messages persist and accumulate as pending while an instance is paused, draining after resume (2026-05-24, instance-debugger, artifact — stated in retired frame_delivery_mode vocabulary; the principle presumably maps onto the message queue).

## Intentional absences

- **The entire May envelope model**: `kind` field (single legacy kind `invalidate`), envelope `target` field, the `message` subscription topic kind with kind/sender/sender_kind/target filters, `target: self` semantics, and wait-set topic_kind 'message' — all retired by the June-14 message-schema redesign and June-15 follow-through (transcript). Routing is subscription-side; the kind field renamed to `type` carrying the type-path.
- **`{{trigger.message.payload.X}}` and all trigger.* substitution** (TriggerMessagePayload/TriggerMessageType ResolveContext fields, triggerMessageForFrame), plus the retired `deps.<X>` prefix and their back-compat error shims — retired 2026-06-18..23 (transcript): "there is no such thing as trigger.message"; `{{messages.<type>.<field>}}` is the only way messages enter substitution, and it reads any delivered message in the current frame, not a single triggering message.
- **Backfill as a first-class primitive** — concept, dedicated endpoints, CLI verbs, backfill_operation_id lineage column all drop (2026-06-14, bfc9febb, transcript); a backfill is just a message whose body carries a partition override read via substitution.
- **Fan-out↔message coupling** — fan-out is a claim request to a producer, completely orthogonal to messages; requiring a message to create a partition is broken by design (2026-06-18, 9fb55f08, transcript).
- **frame_delivery_mode (serial_queue / coalesce delivery)** including conflict-aware coalesce and the nil-resolver escape hatch — "coalesce goes away" with the June-14 one-message-per-frame ruling (transcript). The July message_queue_mode coalesce is a new, different, queue-level capability.
- **supersede_pending** (per-type latest-wins replacement of queued messages) — omitted despite acknowledged value (2026-06-14, bfc9febb, transcript).
- **Operator manipulation of the instance message queue** — deliberately left out of the message-schema spec, not even mentioned; future session (2026-06-14, bfc9febb, transcript).
- **Generalized cancel** (queued frame / in-flight run / pending message) — omitted; each lifecycle state has different cancel semantics, its own future design surface (2026-06-14, bfc9febb, transcript).
- **Synthetic envelopes and synthetic messages of any kind** — EnqueueSyntheticWakeFrame, wake_node_ids, wait_set_pairs, and the four runtime type-paths (instance/root, node/reset, asset/materialize, node/invalidate) all deleted; implied triggers must be real default messages bundled with an operation (2026-06-15..17, transcript).
- **POST /instances/{id}/wake** — rejected as a parallel non-message wake path (2026-06-16, 4c42fe5b, transcript).
- **Asset-materialize endpoint** (POST .../assets/{alias}/materialize) — retired; re-materialization is expressed only through messages (2026-06-15, 4c42fe5b, transcript).
- **deliver_at timer messages and their cancel primitive** — the cut-snooze/timer-message decision was superseded the same session (2026-06-16, 055468fc) when park-snooze was kept; the timer-message primitive dropped out of final scope.
- **payload_template pre-shaping** (and OnObservationSpec) — publishers send raw bytes; templates carrying payload_template fail registration with the standard unknown-field error (2026-05-17, artifact).
- **Special sensor-observation route** (POST /sensors/{watch_id}/observations) — deleted in favor of the generic messages endpoint (2026-05-17, artifact).
- **Cron in core** — schedule: field, rimsky_schedules table, scheduler cron-fire path, force-fire admin endpoint; cron is the bundled sensor publisher (2026-05-15, artifact).
- **target_node on publisher subscriptions** — dead routing removed end-to-end (proto, YAML, validator, column via migration 014, sensors, conformance, docs) (2026-06-19, a02fe167, transcript).
- **Wire sender_kind enum** — dropped from the envelope (2026-06-19, transcript); persistence keeps the three values for audit only. per-subscription last_observed_at also dropped (2026-05-17, artifact) — observability is a message-table query.
- **Dead-lettering of unmatched messages** (2026-05-15, artifact) — superseded by the typed registry's loud 400 refusal of undeclared types.
- **Harness.InvalidateNode** and the tests whose subject was ad hoc invalidation — retired; tests reinstrumented with declared typed messages / real park-exit paths (2026-06-16, 4c42fe5b, transcript). A test-only state-injection helper was explicitly declined.
- **STORY-trigger-message-payload-rejection** (a bespoke error story for the retired form) — declined as backward-looking; legacy templates just fail with the standard unknown-directive error (2026-06-18, 9fb55f08, transcript).
- **Operator re-run as a typed message** — can't be: a message would open a new frame; re-run is a debug-channel action on a stuck node (2026-06-30, 8a8539a4, transcript).
- **Queued-frame designs** (eager-at-receipt and lazy-at-pickup 1:1 message→queued-frame) — rejected; pending work waits as messages, frames are created-then-run (2026-07-05, 3f71f90a, transcript).
- **instance:true cross-cutting subscription** judged an antipattern; and the empty string is not a wildcard-sender grammar — it denotes the empty message (2026-07-05, 3f71f90a, transcript).
- **Cross-frame declarative loop termination inside rimsky** — a multi-frame message-driven loop can only terminate via state persisted outside rimsky or threaded through message payloads; there is no "cross-frame diff-gate" (2026-07-05, 3f71f90a, transcript). story:queue-drain-converges retired outright: when the queue is empty, no message is sent and no next frame opens (2026-07-05, transcript).
- (artifact-only) **V1 deferral of cross-instance messaging** — envelope and endpoint shapes accommodate it; only addressing rules unspecified (2026-05-15, artifact; cross-instance coordination reaffirmed as the message mechanism's job 2026-05-22, artifact).

## Conflicts needing human ruling

- **RESOLVED 2026-07-14 (user ruling, transcript tier): per-sender dedup buckets ratified.** User: "if we have sender types, they should dedup in separate buckets." Message idempotency dedups per (instance, sender_kind, sender, sender_subject, idempotency_key): publishers by name, keyed operators by api-key id, anonymous-mode posts in the `anonymous` bucket. sender_kind is derived server-side from the auth identity (dedupSenderKind), never wire-supplied — this composes the 2026-06-08 bucket discipline with the 2026-06-19 wire-field removal. Findings claiming a wire sender_kind should exist are refuted; the anonymous bucket is alive as the anonymous-mode face of operator traffic.
- **RESOLVED 2026-07-14 (user ruling, transcript tier): pause-drain rides the normal message_queue_mode path.** Pause changes WHEN delivery happens, never WHETHER messages are accepted: ingest stays open while paused (ledger + dedup as usual), no frames open, and on resume the ordinary delivery path picks the queue back up governed by message_queue_mode — backlog delivers in order, coalesce keeps the latest and cancels the rest, with no pause-specific carve-out (a paused backlog is just a longer queue). The May "drain per frame_delivery_mode" phrasing is stale-doc (retired knob); findings referencing it adjudicate as fix-doc.
