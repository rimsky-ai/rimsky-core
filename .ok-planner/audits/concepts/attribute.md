# Attributes: the substitution grammar, the six override layers, the two validation gates, and the substitution-timing invariant

Unsupported, on one clause of the substitution-timing invariant. That invariant claims substitution runs in two rounds "each committed in its own transaction", and that the second round, immediately before dispatch, "persists the completed bag" which "the dispatcher then loads by run id". Only the first half is real: the gate evaluator resolves and persists both the live bag and the dispatch input bag and transitions the row in one transaction. The second round commits nothing — the dispatcher opens a read-only transaction to load the round-one bag, then fills the deferred claim- and child-scoped references, merges schema defaults, applies the override layers and the resume overlay entirely in memory, and hands that bag to the executor; the completed bag first reaches the ledger at settle. So the dispatcher loads the round-one bag, not the round-two bag the invariant describes, and the ledger holds no completed pre-dispatch row. Everything else checks out. The grammar is a closed six-kind enumeration — upstream-node attributes, co-held claim fields, instance params, delivered-message payloads by type, the per-child partition key, and host environment variables under the name shape the concept states — validated at registration in one place that rejects out-of-grammar bodies, rejects multi-pipe chains and non-scalar fallback literals, rejects the lenient marker together with a fallback, admits an empty trailing path on exactly the three path-walking kinds, and requires a key segment on params alone. Resolution is whole-directive or embedded as described, with the lenient marker lifting to null in the first and to the empty string in the second, and missing-source errors carry the directive text only, never the value. Storage is per-run: the ledger's primary key is the node-run id under a cascading foreign key, beside a denormalised node-id column indexed for latest-per-node lookups. All six merge layers are present and ordered as claimed, with the matcher evaluated against the post-L4 bag over a fixed five-key set, equality only, missing keys as wildcards, an empty matcher matching everything, and later entries deep-merging last; registration rejects the four ordinal-shaped keys by name and restricts matcher values to primitives without inspecting a string's shape, and per-entry matches are recorded as event-log rows counted by index at read time. Validation gates twice, at dispatch post-substitution and at commit post-writeback. Both cross-frame prohibitions hold structurally: every prior-run lookup the runtime makes — the diff-gate baseline, the carry-forward hydrate, and all four mode comparisons — filters on run scope, and run scopes never span frames; the diff-gate falls back to the merged schema-default bag on a scope's first run, with a scenario test on that baseline. Mid-dispatch writebacks take a row lock, refuse any state but running or held, merge onto the in-flight run's own row, bump the progress timestamp in the same transaction, and emit nothing. Message-delivery rows are written verbatim as both bags with no defaults or substitution pass, and neither of the two rejected flags exists anywhere in the tree.
