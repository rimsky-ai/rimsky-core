# RunScope as a persisted per-frame execution context and its twelve invariants

Unsupported: the twelfth invariant fails on both of its claims — that one lazy-allocation primitive is the node-run allocation entry point, and that callers must not depend on its return value beyond error or no-error. Each storage dialect carries six statements that insert a node-run row, behind six distinct table methods covering queue enqueue, cascade-pending creation, non-cascade stale creation, root and child run-tree creation, and the source-node stale mark; the two dialects carry the same six, and none is privileged over the others. Two of the six return the new run's identifier, and every production caller of both consumes it: the cascade walk's receiver resolution hands its id to wait-set insertion and to the upstream force-refresh pull, and the message-delivery and debug-override paths use theirs to key the receiver's attribute bag and dispatch input bag. The two run-tree creations take a caller-supplied identifier instead, so their callers hold the id before the call rather than after it. Nothing enforces the stated discipline and no caller observes it. The other eleven invariants hold and were checked individually. The row exists with the derivable-kind shape the concept describes — no kind column, a self-referential parent pointer, a partition key, and a closure stamp — and both storage dialects carry the check constraint making the two parent pointers stand or fall together plus the partial unique index admitting one open partition per parent-run and key; a shared conformance suite of six cases exercises creation, closure, closed-scope refusal, partition uniqueness, kind derivation, and the parent-chain walk against both. Root scopes are inserted in the same transaction as the frame row that references them; fan-out partitions are created by the shared child-execution helper in a transaction of its own, opened after acquisition returns. Both depth-gating layers exist: a static sub-graph cycle rejection at template validation and a runtime ancestor-chain walk at delegate dispatch. Closure walks the tree deepest-first at settlement and at administrative termination, includes already-closed scopes so a failed peer delivery is re-offered, and dedupes per scope per peer through the lifecycle-idempotency ledger, with the frame-settlement path carrying its own terminal reason. Carry-forward selects the prior run inside one run scope only, and trace retention deletes a pruned frame's root scope alongside the frame.
