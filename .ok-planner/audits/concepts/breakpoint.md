# The breakpoint ledger, its checkpoints, its overlay layer, and its debug-override channel

Supported; all twelve invariants check out. Registration rejects each of the three illegal combinations the concept names — a signal-type filter on a pre-dispatch breakpoint, a pause mode paired with the silently-dropping overflow policy, and a notify-only mode paired with the blocking one — and applies the matcher validation described in the policy-differences section: the breakpoint side builds its executor set from every deployment-declared executor with no used-in-template restriction, where the attribute by-match validator additionally passes a used-executor set, while node types, graph names, and the closed grammar are checked identically by the one shared validator. Hit rows are created at exactly one site, in the supervisor's evaluation path; nothing in the control plane inserts one. Resume is idempotent on the hit — an already-resumed hit returns without rewriting anything — and an overlay offered on a post-terminal hit is refused as an invalid overlay before any write. The overlay is layer six by construction: the dispatcher resolves the bag, applies the stored overrides, and only then reaches the checkpoint, so the overlay never touches the instance's persisted overrides and lives only on the hit row and the in-memory bag for that dispatch; when several breakpoints pause one dispatch the merged result is fed back as both the next matcher's input and the next hit's snapshot, so sequential resumes compose. A vanished hit row — the cascade-delete case — is treated as auto-resume with no overlay, releasing the blocked runner. Pause-mode evaluation fails closed with a logged block of the dispatch; the post-terminal evaluation logs and continues. The pre-dispatch checkpoint sits on the single attribute-resolution path, gated on the node having an executor so the executor-less dispositions skip it, and it runs once before the retry loop that re-invokes the executor rather than inside it. The debug-override channel resolves the node's latest run inside the instance's running frame only, refuses a request naming a run from another frame, redirects an attribute write against a terminal in-frame run onto a freshly created operator-invalidated run whose bag is snapshotted forward, and against an in-flight run merges into the live bag and queues one invalidated run behind it. Both ledgers exist in both storage backends behind a shared conformance suite, and eighteen breakpoint scenario tests plus the runtime and control-plane unit suites exercise these behaviours by name.
