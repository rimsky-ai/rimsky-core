# The audit-log ledger: typed kinds, proto-declared payloads, retention, and the synchronous auth-audit write

Unsupported, on one clause. Everything else in the concept holds. The kind discriminator is typed at the application boundary by a proto-declared enum carrying 44 operational values plus a signal-class family parsed as type-paths; both persistence drivers store the column as free text with no check constraint, exactly as claimed. Payload construction goes through a value type whose only build-from-scratch constructor takes a generated protobuf message — the map-accepting constructor is reachable only from the two drivers' row-decode paths and from tests — so an untyped map genuinely cannot be persisted, and foreign-shaped fields (executor error data, template-author blobs) are declared as generic JSON values and passed through. Retention holds: rows age out by timestamp under the shared trace window that also bounds frames and node runs, and instance-scoped rows additionally cascade away on instance delete in both drivers. The three-index claim (by node, by instance, by kind, each newest-first) is present in both drivers' initial schema. All five auth kinds exist and all five are readable through the audit surface, which is gated on the read action and filters by key id, key name, action, request path, response status, mode, and time range. Key expiry is a passive per-request timestamp comparison that emits no revocation row; the rotation row names the new key as its actor while carrying the old and new ids separately; a permission denial carries the resolved request mode while every denial raised before permission evaluation carries none. The per-request access-attempted write is genuinely synchronous and inline — it runs after the wrapped handler returns and before the gate returns, under a two-second bounded context, and a failure is logged at error level with no retry and no buffer. What is not carried is the invariant's "one message per kind": the proto declares 50 payload messages, but at least five operational kinds share two of them — the template-resolution, template-validation, and executor-schema-unavailable kinds all construct the same message, and the commit and abandon claim-resolution kinds both construct one settled-resolution message — and on the signal-class side a single terminal-error message serves the whole open-ended family of per-error-class type-paths. The property the sentence exists to guarantee (declared shape, constructed from the generated type) is enforced; the one-to-one mapping it asserts is not.
