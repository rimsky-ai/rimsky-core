# Retired DSL surfaces leave no named remnant in the parser

Supported. Searched shipping code for every retired template and request surface the project's own migration and proto history names — the terminate-after-run flag, the hard-dep attribute flag, the frame timeout, the park reason, the max-retries-without-progress knob, the executor-side environment substitution form, the wait-set subscription scope, the asset-materialize verb, and the retired error-type actions — and found no occurrence of any of them outside test fixtures. Retired error-type action names fail through the same unknown-action path a nonsense value takes, asserted by a test that runs four retired names and one nonsense name through one table. Unknown template and message fields are rejected by strict decoding at the template-registration and message-send routes, which is the unknown-field path the decision points at. The retired callback discriminator is rejected by the generic rule that exactly one outcome key must be set, naming no old shape. The single targeted rejection message in the tree names four ordinal matcher keys, and those were never an accepted surface — the rejection vocabulary is owned by the attribute concept as a designed guard, not a remnant. The protobuf field reservations that remain are wire-number hygiene in the schema, not parser cases.
