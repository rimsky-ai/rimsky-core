# Fan-out implementation Plan

**Spec:** `.ok-planner/specs/2026-06-18-fan-out-design.md`
**Goal:** Implement fan-out end-to-end across the bundled filesystem and postgres stores — wiring `SplitScope` on both, retiring legacy substitution residue, bringing sub-claims to wire parity with regular claims, unifying messages-as-nodes substitution, and shipping seven runnable example proofs.
**Architecture:** Four implementation layers — (1) substitution-context unification + legacy retirement, (2) `SubScopeDescriptor` wire parity + sub-claim insert-path fixes, (3) bundled-store `SplitScope` implementations with substrate-specific partition_request shapes, (4) conformance coverage + concept doc updates. Acceptance is exhibited by seven examples under `examples/`, each a runnable shell + YAML template pair that drives the assembled `rimsky` stack via the HTTP control-API surface.
**Tech Stack:** Go (rimsky core, bundled stores), protobuf (claim-producer protocol), PostgreSQL + SQLite (persistence), bash + curl + jq + yq (example drivers), `examples/onboarding-template.yaml` and `examples/cross-frame-coupling-demo.sh` as reference patterns.
