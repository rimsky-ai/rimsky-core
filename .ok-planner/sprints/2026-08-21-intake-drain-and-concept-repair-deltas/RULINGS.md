# Per-concept fact changes ruled by the owner (apply while rewriting)

- lifecycle-subscriber — A subscriber reacts to a transition and never refuses one: a subscriber's error neither rolls a transition back nor fails the request that performed it (see `decision:lifecycle-fanout-after-commit`). Drop the provisioning archetypes from Purpose: rimsky orders no work against a subscriber's reaction, so the concept promises delivery and reaction only; the one shape worth naming is that a peer reacts to a transition it observes. Keep: the lifecycle-subscriber protocol is the one peer protocol notified at instance creation. Keep: a periodic poll loop delivers instance-terminated; the request that terminated the instance does not. Keep: delivery is at-least-once under an idempotency ledger (see `decision:lifecycle-subscriber-at-least-once-delivery`).
- template — Identity: a template's id is the content hash of its spec after the deployment's canonicalization; that canonicalization absorbs key order and whitespace and reads the deployment's kind-alias map, so identity is a function of the spec and the deployment that registers it (see `decision:template-identity-deployment-canonical`). Boundaries: instance params are cleartext operational data; rimsky masks nothing in them on any surface, and a secret belongs in a surface that carries the never-logged, never-returned guarantee (see `decision:secret-at-rest-posture`). No `params_redact` field exists. The registration pipeline also serves a validate-without-registering entry (see `story:template-validate-without-registering`).
- instance — Define quiescence: an instance is quiescent when no frame of it is running and no message is pending on its queue. An instance never self-terminates; the run-to-terminal verbs poll quiescence and terminate their own instances (see `decision:termination`).
- rimsky-yml — One file, read by every runtime process; per-role tuning lives under a per-role section of the same file; no per-process configuration file exists (see `decision:launch-config-injection`).
- blob-backend — A read of a spilled row whose handle names a backend other than the active one refuses with an error on every read path; no path falls back to the inline column (see `decision:blob-backend-mismatch-read-refused`).
- observability, executor — An executor's expected-attributes schema is a closed contract: it declares every key the executor reads, and registration rejects a key it does not declare (see `decision:expected-attributes-schema-closed`).
- lineage, lineage-record — A leaf-run record is written only for a run that invoked an executor; the terminal-kind family is closed at four (see `decision:lineage-records-computation-only`). Rimsky writes a data-processing promotion's claim-terminal record once the commit response lands, carrying the version (see `decision:promotion-lineage-record-after-commit`).
- host-agent-proxy, host-agent, peer-auth — The agent-to-proxy hop is TLS in every posture, the zero-config posture included, with plaintext only behind an explicit insecure switch (see `decision:host-agent-proxy-tls`).
- event-log — Every operational kind the enum declares has a writer (see `decision:event-log-kind-enum`).
- message — The envelope carries the sender kind, the sender, and the sender-subject (see `decision:message-sender-kind-discriminator`). The idempotency key is mandatory on every send surface (see `decision:idempotency-key-header-universal`).
- cascade-mode — Under `sequenced`, a receiver's rounds from one sender dispatch in arrival order: a later round never dispatches while an older round of the same sender is still queued.
- anonymous-mode — Recovery from total key loss lives outside the API and the CLI: it is an operator act on the ledger. State it in Boundaries.
- cascade-graph — The surface is read-only. The per-handler transaction discipline is implementation; it does not appear.
- control-api — Lifecycle fan-out runs after the transition commits and never decides the request's outcome (see `decision:lifecycle-fanout-after-commit`).
